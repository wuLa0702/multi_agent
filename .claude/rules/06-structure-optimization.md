## 1. 阈值与统计口径

**有效业务代码行** = 总行数 − 注释/docstring − 空行 − 单独导入行 − 类型注解 − 装饰器 − 常量定义区。

| 线 | 阈值（有效业务代码行） | 动作 |
|----|------------------------|------|
| 文件关注线 | > 750 | 标记拆分候选，人工评估 |
| **文件强制线** | > **800** | **必须拆分**（单一职责/业务能力维度，禁随机切块） |
| **函数强制线** | > **80** | **必须拆分解耦**（不再"考虑"） |
| 函数质量底线 | > 160 | 拆分失败信号：拆解后仍 >160 → 继续拆 |

**底层函数豁免**（必须拆分例外）：全局通用工具 / 基础算法（tokenizer、分页）/ 通用解析封装。
**不豁免**：业务逻辑 / Agent 编排逻辑 / 流程控制逻辑。
豁免函数必须在 docstring 声明"底层函数，按规范豁免"（供校验脚本白名单）。

## 2. 分层与职责（backend/src/）

> **具体目录清单见 `docs/架构/多agent项目-架构目录.md` §2（唯一真相源）。**
> 📌 **2026-10-14 修订**：本节从「固定目录表」改为「**层 + 禁令**」——**目录可增删，层职责不变**。
> 理由：目录是易变的实现细节，写死在规则里必然与代码脱节（旧表已出现 `mcp/`、`skills/` 消失后仍列着的脱节）。

| 层 | 放什么 | 禁止 |
|----|--------|------|
| 入口层 | `api/` | 禁直接写 SQL、禁调 LLM 细节 |
| 编排层 | `agent/`（**根只允许 `main_agent.py`**） | 禁业务实现（≥3 行业务逻辑必须外提） |
| 能力层 | 按域组织（工具 / 沙箱 / …）；**当前清单见架构文档** | 禁跨域直调、禁反向调上层 |
| 底座层 | `core/` `llm/` `schemas/` `db/` | core 禁依赖业务；db 唯一 SQL 出口；llm 唯一 LLM 出口 |

**能力层约束（2026-10-14 新增）**：能力层目录**按域组织、可增删**；新增能力域在**架构文档**登记，**不在本规则登记**——避免规则随目录变动而频繁改动。

**跨层禁令**：
1. 只能上层调下层：`api → agent → 能力目录 → db/`；core/llm/schemas 为公共底座
2. **禁跨多层跳跃**（如 api/ 直调 db/、agent/ 直调第三方 SDK）
3. **Agent 禁直接调用底层存储/第三方 SDK**——一律经 adapter/repository 中转

**Agent 只编排**：agent/ 下文件只组装节点/中间件/参数；出现 3 行以上业务实现（SQL/LLM 细节/格式解析）→ 抽到能力目录；无匹配目录 → 新建能力文件统一收纳。

**模块 README**：核心模块/Agent 能力/工具服务必须配套 `模块目录/README.md`（职责/入参出参/依赖/异常场景/示例/变更记录）。

## 3. 常量与路径

- **常量**：跨文件共用 → `core/constants.py`（"用两次就抽"）；单文件私有 → 模块头部常量；函数内禁硬编码魔法值
- **路径**：全部集中 `core/paths.py`（dev/prod 自适应）；新增数据目录必须登记；**禁裸字符串路径拼接**（`str + "/"`），统一 pathlib

## 4. 日志与异常

- **注释 ≠ 日志**：注释管开发阅读，日志管线上排查——关键节点/入参出参/异常**必须有日志**（统一中间件覆盖，函数内仅异常分支与关键状态补打）；禁 print 调试
- **异常四分类**：
  | 分类 | 处理 |
  |------|------|
  | 可重试（网络/超时/限流）| 重试后仍失败 → 降级 |
  | 不可重试（参数/状态/不存在）| 直接返回业务错误码，不重试 |
  | 业务异常 | 业务错误码 + 降级/默认兜底 |
  | 系统异常（未知内部）| 记 error 日志 + 按链路矩阵降级 |
- **禁超大范围 try-except 裸捕获**（`except Exception` 包整段业务）：捕获必须精确到异常类型、必须处理（记录/转换/降级），不吞异常、不盲抛
- 除 LLM 主链路外，**不因单点失败断流**——降级 + 默认兜底 + 日志留痕

## 5. 依赖与导入

- 禁循环 import（出现立即重构）
- 禁全局 `*` 导入（全部显式导入）
- 第三方 SDK/LLM/中间件统一单例封装（`llm/adapter.py`、`tools/registry.py`、`core/redis.py`）——业务代码禁直接 `new` 第三方实例
- 导入顺序：标准库 → 第三方 → 项目内部，每组空一行

## 6. 文案与可测试性

- **错误文案**：统一中文 + 冒号分隔（`失败原因：xxx`）；文案进 `core/errors.py` 的 `ErrorMessage`（code → 文案映射），API 层禁裸字符串错误；ErrorResponse 三字段（error/detail/code）
- **可测试性**：每个业务/工具函数必须有对应测试（`test_<模块>.py`，随写随测）；外部依赖全部可 mock（构造注入式）；LLM 全 mock（20-testing 纪律）
