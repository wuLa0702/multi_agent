# 文档目录规范（2026-08-04 确立：文档必须放对应目录，防错位）

> 教训：持久化能力开发计划（评审稿性质）曾放 `docs/方案/`，实际应归
> `docs/decisions/`——评审稿与已定方案混放，查找困难且性质混淆。

## 目录归属表

| 目录 | 放什么 | 示例 |
|------|--------|------|
| `docs/方案/` | 已定方案 / 定稿计划 | 方案-后端基础架构、后端开发计划、后端接口对接文档 |
| `docs/decisions/` | **评审稿 / 决策记录 / 待评审计划**（评审通过后再考虑归档） | 持久化能力开发计划 |
| `docs/架构/` | 架构蓝图与目录树（唯一真相源） | 多agent项目-架构目录 |
| `docs/learnings/` | 踩坑与经验沉淀 | 2026-08-04-PyCharm索引未解析引用 |
| `docs/学习/` | 学习笔记 / 调研梳理 | harness 学习 |
| `docs/评审/` | 评审材料（对外评审用） | 技术栈与前端功能-评审材料 |

## 规则

1. **新建文档先判断性质**：方案？评审稿？决策？学习？踩坑？→ 再落位，不随手放
2. 拿不准归属 → 问 co-creator，不猜
3. **移动文档用 `git mv`**（保留 git 历史），并同步更新引用它的文档
4. 文档内部格式规则仍以 `docs/文档规范.md` 为唯一载体（本规则只定目录归属）
