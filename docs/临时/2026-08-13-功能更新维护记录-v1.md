## 0. 用途与维护规则 🔴 v1

**用途**：这是项目**统一的功能更新维护点**——co-creator 指示在 `docs/临时/` 记录已更新功能，作为后续维护**面经**（`docs/学习/面试/`）和**项目结构**（`docs/架构/`）的依据。

**维护规则（后续新增功能必须填写）**：
1. **新功能落地后**，在 §1 对应功能域表格**追加一行**（倒序，最新在上）
2. 每行固定四要素：**日期（YYYY-MM-DD）+ 功能简述 + commit 短哈希 + 影响（面经点 / 项目结构）**
3. 面经/项目结构大改时，同步 §2 待维护提示 + 更新 `docs/索引.md`
4. 本记录定位 = 人类可读的"做了什么"，`功能更新日志.md` = git 变更流水（互补，不重复）
