## 3. 核心设计决策

### 3.1 Redis：连接池 + lifespan
- 用 `redis.asyncio` 客户端，**进程级单例连接池**（`get_redis()` + `close_redis()`）
- FastAPI `lifespan` 启动时连接、关闭时释放
- 短期记忆语义：`sessions:{id}` hash 存会话元数据 + `messages:{id}` list 存消息流
- 连接失败 → health 显示 `redis: disconnected`（**不崩溃**，服务照常起）——本地没 redis 也能开发

### 3.2 SQLite：schema 先行 + DAO 参数化
- `db/schema.py` 集中 SQL（符合旧项目规范「所有 SQL 写在 schema.py，DAO 只调用」📌）
- 建表：`sessions(id, title, created_at, updated_at)` + `messages(id, session_id, role, content, created_at)`
- `aiosqlite` 异步访问，`:memory:` 测试注入
- 路径用 `core/paths.get_db_path()`（dev 本地 / prod 云端自动切换 ✅ 已有）

### 3.3 健康检查 = 验收点
```json
GET /v1/health → {
  "status": "ok",
  "redis": "connected" | "disconnected",
  "sqlite": "connected",
  "env": "dev"
}
```
- 不依赖 LLM/沙箱——**只验证地基**，跟 Agent 无关的纯基建层

### 3.4 依赖
- 新增：`redis>=5.0`（已有 ✅）、`aiosqlite>=0.20`（已有 ✅）——**零新增依赖**

## 4. 启动与验证

```bash
# 1. 起 Redis（本地 docker，或直接连云端——.env.dev 的 REDIS_URL 决定）
docker compose --env-file .env.dev up -d redis

# 2. 启动后端
cd backend && uvicorn src.api.main:app --reload --port 8010

# 3. 验证
curl http://localhost:8010/v1/health
# → {"status":"ok","redis":"connected","sqlite":"connected","env":"dev"}

# 4. 测试
cd .. && pytest backend/tests -v   # 全绿
```

## 6. 风险与开放问题

| 风险 | 缓解 |
|------|------|
| 本地没 Redis 时开发受阻 | health 降级为 disconnected，服务不崩；本地可 docker 起 |
| SQLite 并发写 | 单写连接 + WAL 模式（schema 里 PRAGMA） |
| Windows 路径 | paths.py 已处理（win32 短路）✅ |

**开放问题（评审时定）**：
1. Redis 先存什么？——建议：只建连接 + 会话元数据占位，业务数据结构 v3 定
2. 消息表要不要分表（session 维度）？——建议：单表 + session_id 索引，够用再拆
3. 是否要 `/v1/sessions` CRUD 接口？——建议：要，它是前端会话列表的地基
