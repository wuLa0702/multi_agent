## 1. 对接总览

- **Base URL（dev）**：`http://127.0.0.1:8010`（前端 Vite proxy：`/v1` → 8010）
- **认证**：无（单用户本地项目，密钥在后端 .env 管理，不经前端）
- **数据格式**：JSON（UTF-8）；请求/响应字段 snake_case
- **错误统一**：`{ "error": "ErrorResponse", "detail": "...", "code": "..." }`，非 2xx 时返回

### 接口清单

| 方法 | 路径 | 说明 | 前端使用 |
|------|------|------|---------|
| GET | `/v1/health` | 健康检查 | 启动探测（降级标记） |
| POST | `/v1/chat/stream` | SSE 对话流（核心） | 聊天 |
| POST | `/v1/chat/approve` | 审批决策 | 审批弹窗 |
| GET | `/v1/providers` | 厂商→模型列表 | 模型下拉 |
| POST | `/v1/sessions` | 创建会话 | 新建会话 |
| GET | `/v1/sessions` | 会话列表 | 会话侧栏 |
| PATCH | `/v1/sessions/{id}` | 改名 | 行内改名 |
| DELETE | `/v1/sessions/{id}` | 删除会话 | 删除 |
| GET | `/v1/sessions/{id}/messages` | 历史消息分页 | 切换会话加载 |
| GET | `/v1/skills/marketplace/list` | 市场浏览（Smithery 代理） | 能力市场页 |
| POST | `/v1/skills/install` | 安装 / 升级（force） | 市场卡片 |
| GET | `/v1/skills/installed` | 已安装列表 | 已安装分类 |
| PATCH | `/v1/skills/{id}` | 启停 | 开关 |
| DELETE | `/v1/skills/{id}` | 卸载 | 卸载按钮 |
| — | `/mcp` | FastMCP 端点（外部 Agent 接入） | 前端不用 |

## 2. REST 接口明细

### 2.1 健康检查

```
GET /v1/health
```
响应：
```json
{ "status": "ok", "redis": "connected", "sqlite": "connected", "env": "dev" }
```
- `status`: `ok` / `degraded`（依赖失败不 500，前端可展示降级）

### 2.2 模型配置（二级选择数据源）

```
GET /v1/providers
```
响应：
```json
{
  "providers": [
    {
      "id": 1, "slug": "deepseek", "name": "DeepSeek", "is_active": true,
      "models": [
        { "id": 1, "provider_id": 1, "name": "deepseek-v4-flash", "is_default": true, "is_active": true }
      ]
    }
  ]
}
```
前端：厂商→模型二级联动；请求不带 model_id = 后端默认模型。

### 2.3 会话 CRUD

**创建**：`POST /v1/sessions`（无 body）
```json
{ "id": "uuid", "title": "新会话", "created_at": "...", "updated_at": "..." }
```

**列表**：`GET /v1/sessions`（updated_at 倒序）
```json
{ "status": "ok", "items": [Session...], "total": 28 }
```

**改名**：`PATCH /v1/sessions/{id}` body `{ "title": "新标题" }`（1-100 字符，400 校验）

**删除**：`DELETE /v1/sessions/{id}` → `{ "status": "ok" }`（messages 级联删除）
- 404 错误码：`SESSION_NOT_FOUND`（前端特殊处理：提示已不存在并刷新列表）

**历史消息**：`GET /v1/sessions/{id}/messages?limit=200&before_id=...`（cursor 分页）
```json
{
  "status": "ok", "items": [Message...],
  "next_before_id": 123, "has_more": false
}
```
Message：`{ "id": int, "session_id": str, "role": "user|assistant|system|tool", "content": str, "created_at": str }`

### 2.4 Skill 市场

**市场浏览**：`GET /v1/skills/marketplace/list?source=smithery&query=&page=1&page_size=20&skill_type=mcp_server|skill_md`
```json
{
  "source": "smithery",
  "items": [
    {
      "name": "Vercel Grep", "description": "...", "source": "smithery",
      "source_url": "https://smithery.ai/servers/vercel/grep", "version": "vercel/grep",
      "skill_type": "mcp_server", "use_count": 20743, "verified": true,
      "transport": "streamable_http", "url": "", "command": "", "args": [], "git_url": ""
    }
  ],
  "total": 150, "page": 1, "has_more": true
}
```
- 注意：`source_url` 是唯一标识（React key + 幂等去重）；skill_md 类 qualifiedName 可能为 null，source_url 用 gitUrl 兜底
- 服务端 5 分钟缓存

**安装 / 升级**：`POST /v1/skills/install`
```json
{
  "source": "smithery", "source_url": "https://smithery.ai/servers/vercel/grep",
  "name": "Vercel Grep", "skill_type": "mcp_server",
  "transport": "streamable_http", "url": "", "command": "", "args": [],
  "git_url": "", "force": false
}
```
- `force=false`：已安装幂等返回现有记录
- `force=true`：先卸载再重装（升级）
- mcp_server 类：后端自动建 Smithery connection 补全 url；需要 OAuth 的 server 返回 400 `INSTALL_FAILED`（detail 含授权 URL 提示）
- 安装后后端自动热刷新 Agent（下次对话生效）
- 响应：`InstalledSkill`（id/name/skill_type/source/source_url/version/install_path/is_active/created_at/updated_at）

**已安装列表**：`GET /v1/skills/installed`
```json
{ "items": [InstalledSkill...], "total": 3 }
```

**启停**：`PATCH /v1/skills/{id}` body `{ "is_active": true }` → `{ "status": "ok", "id": 3, "is_active": true }`

**卸载**：`DELETE /v1/skills/{id}` → `{ "status": "ok", "id": 3 }`

## 3. SSE 流式协议（对话核心）

### 3.1 请求

```
POST /v1/chat/stream
Content-Type: application/json
Accept: text/event-stream
```
```json
{
  "session_id": "uuid | null",   // null = 后端自动建会话（响应 start 事件返回）
  "message": "用户消息",          // 与 resume_run_id 互斥
  "resume_run_id": "uuid | null",// 审批后恢复
  "model_id": 1 | null           // null = 默认模型
}
```

### 3.2 事件类型（8 类，type 字段判别）

| type | 关键字段 | 前端行为 |
|------|---------|---------|
| `start` | run_id, session_id, resumed | 置 streaming；新 run 清面板；resume 保留挂起前节点 |
| `token` | text | 追加到 assistant 消息（id=null 未落库） |
| `tool_call` | call_id, name, arguments, status(running/success/error), result | 幂等 upsert（陈旧 running 不覆盖已完成） |
| `subagent` | name, status(start/end), summary | start 追加 running 节点；end 置 done + summary |
| `approve` | run_id, call_id, tool_name, arguments, message | 弹审批窗 + 存 pendingRunId（localStorage 可恢复） |
| `summarize` | summary, removed_count, keep_from_message_id | info notice |
| `done` | run_id, session_id, duration_ms | 置 idle + 静默重拉全量消息以库为准 |
| `error` | code, detail, retryable | error notice（retryable 提示可重试） |

### 3.3 SSE 帧格式

- 分隔符兼容 `\n\n`（LF）与 `\r\n\r\n`（CRLF）——FastAPI 实测输出 CRLF，前端解析器两者都认
- 每帧 `data: {json}`，多 data 行拼接
- 流内 error 事件后连接不关闭（继续收 done）

### 3.4 审批闭环

1. 收到 `approve` 事件 → 前端弹窗（工具名 + 参数 + message）
2. 用户操作 → `POST /v1/chat/approve` body `{ "run_id": "...", "action": "approve|reject", "note": "可选" }` → 202
3. 前端自动 `POST /v1/chat/stream` body `{ "resume_run_id": run_id }` 恢复流
4. 错误码：`RUN_NOT_FOUND` / `NOT_PENDING`（前端清理审批态，提示已失效）

## 5. 通用约定

1. **错误响应**：`{ "error": "ErrorResponse", "detail": "...", "code": "..." }`
   - 400 参数错误 / 404 不存在（SESSION_NOT_FOUND / SKILL_NOT_FOUND）/ 502 市场不可达（MARKETPLACE_UNAVAILABLE）
2. **时间格式**：ISO 8601 UTC（`2026-08-03T11:45:52.18+00:00`）
3. **前端 ApiError**：非 2xx 自动解析 ErrorResponse → 抛 `ApiError(code/status/detail)`，业务按 code 分支
4. **热刷新**：Skill 安装/卸载/启停后后端自动 `reload + rebuild_agent`，前端无需额外操作，下次对话生效
