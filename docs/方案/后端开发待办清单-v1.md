## 3. P0 明细（会话体验，最高优先）

### 3.1 会话摘要（last_message）

- **现状**：会话列表第二行只有时间；后端无最后消息字段
- **改动**：`GET /v1/sessions` 响应每个 Session 增加 `last_message: str | null`（该会话最后一条 assistant/user 消息截断 ≤50 字）
- **实现**：`db/repository.py` `list_sessions` SQL 加子查询（LEFT JOIN 取最新 message）；`schemas/session.py` 加字段
- **前端**：SessionList 第二行显示摘要（后端有值后自动渲染，前端已预留两行布局）

### 3.2 会话自动标题

- **现状**：创建即「新会话」，永不更新
- **改动**：`api/chat.py` 首条 user 消息落库后，若会话标题仍为「新会话」→ 截取消息前 20 字更新标题
- **实现**：`append_message` 后调用 `update_session_title`（或 repository 内联判断）；需保留用户手动改名（仅当标题=默认值时覆盖）

### 3.3 会话置顶（is_pinned）

- **现状**：前端 localStorage（`multi-agent.pinned-sessions`），刷新不丢但跨设备/后端不可见
- **改动**：`sessions` 表加 `is_pinned INTEGER DEFAULT 0`（schema.py + 旧库迁移）；`GET /v1/sessions` 返回该字段且**置顶优先排序**；`PATCH /v1/sessions/{id}` body 支持 `is_pinned`
- **前端**：usePinnedSessions 改为调后端（localStorage 降级兜底），置顶分组逻辑不变

## 4. P1 明细（设置页去 mock）

### 4.1 MCP 管理 API

- **现状**：设置页 MCP 管理为静态 3 行 mock（Smithery 网关/博查/沙箱）
- **改动**：新增
  - `GET /v1/mcp-servers` → mcp_servers 表全量（name/transport/url/is_active/source/version）
  - `PATCH /v1/mcp-servers/{id}` body `{is_active}` → 同步切换 + 触发 reload
  - `DELETE /v1/mcp-servers/{id}` → 删除行（含 installed_skills 关联清理）
- **实现**：`api/mcp_servers.py` + `db/skill_repository.py` 复用（`update_mcp_server_active`/`delete_mcp_server_by_id` 已有）
- **前端**：SettingsPage McpSection 改真实数据 + 空状态

### 4.2 系统配置 API

- **现状**：系统配置 3 个开关 mock（日志上报/Skill 自动更新/流式加速）
- **改动**：新增 `GET /v1/settings` + `PUT /v1/settings`（JSON 存 SQLite settings 表或文件）
- **建议**：先做「前端日志上报」真实化（`POST /v1/frontend/logs`，logger.ts 的 flush 已留占位）——这是最有价值的一项
- **前端**：SettingsPage 开关改真实读写；logger.ts flush 接后端

### 4.3 代理模式透传

- **现状**：四档模式纯前端状态（自动模式二次确认）
- **改动**：`POST /v1/chat/stream` 请求体加 `mode: "default"|"plan"|"agent"|"auto"`（可选，缺省 default）
- **实现**：ChatContext 加 mode 字段 → system_prompt 按模式附加指令（plan：先拆解任务；agent：自主多步；auto：模型自选）
- **前端**：ChatInput 的 mode 状态传入 send

## 5. P2 明细（增强功能）

### 5.1 上下文用量统计

- **现状**：输入栏「1.2k/128k」固定 mock
- **改动**：SSE `start` 事件加 `context_used`/`context_total`；或 `GET /v1/context-usage?session_id=`
- **实现**：对话历史 token 估算（chars/4）或调模型 tokenizer；汇总 + 压缩后更新

### 5.2 附件上传

- **现状**：📎 仅本地记录文件名
- **改动**：`POST /v1/chat/stream` 附件字段（base64 或 multipart 上传接口 + 文件落盘 `data/uploads/`）
- **实现**：`core/paths.py` 加 `get_uploads_dir()`；消息体携带附件引用，Agent 可读

### 5.3 Skill 分类聚合

- **现状**：「全部」分类由前端合并两类（mcp_server + skill_md 各一页）
- **改动**：`GET /v1/skills/marketplace/list` 支持 `skill_type=all`（后端合并分页）或按 Smithery categories 分类
- **实现**：marketplace.py 加 all 分支
