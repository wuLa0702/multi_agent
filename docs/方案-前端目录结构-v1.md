# 方案：前端目录结构（React 19 + shadcn/ui + Tailwind 4）

> 状态：**待评审**（v1 评审稿）
> 依据：架构文档决策 #5（React 19 + shadcn/ui + Tailwind 4，复用 wiki-ui-v2）+ E2（工具/参数/结果三栏）
> 目标：一个聊天页 + Agent 调用可视化 + 人工审批 + 会话历史，能对接后端 SSE。

## 1. 技术栈定稿

| 项 | 选型 | 理由 |
|----|------|------|
| 框架 | React 19 + Vite + TypeScript 严格模式 | 决策 #5 |
| UI | shadcn/ui + Tailwind 4 | 决策 #5，复用 wiki-ui-v2 |
| 状态管理 | **zustand**（轻量）+ TanStack Query（服务端状态） | Agent 对话流状态复杂但单向，zustand 够用；SSE 流用 Query 的流式扩展 |
| 路由 | react-router v7 | 页面少但需要 history/ 独立页 |
| SSE | 原生 EventSource（封装） | 后端走 SSE，`ai` SDK 可选（架构文档曾提 ai SDK，但 EventSource 更透明，先原生后抽象） |
| 图谱 | vis-network（复用 wiki-ui-v2） | 多 Agent 调用链可视化 |

## 3. 核心模块说明

### 3.1 SSE 事件协议（★与后端 v3 对齐，前端第一天定）
`lib/api/sse.ts` 监听事件类型（对应 .claude/rules/10-api.md）：

| 事件 | payload 要点 | 前端动作 |
|------|-------------|---------|
| `token` | `{delta}` | 追加到当前 assistant 消息 |
| `tool_call` | `{tool, args, result}` | 更新 ToolCallPanel 三栏 |
| `subagent` | `{name, status, result}` | 更新 AgentTree 节点 |
| `approve` | `{request_id, summary}` | 弹 ApproveDialog |
| `summarize` | `{event}` | 折叠历史 + 提示 |
| `done` | `{session_id}` | 结束流 + 刷新历史 |
| `error` | `{code, message}` | 错误提示 |

**重连策略**：EventSource 断线 → 3s 指数退避重连；`done` 后关闭。

### 3.2 状态设计（zustand）
```
chatStore: {
  messages: Message[],          // 对话流（含工具调用嵌入）
  toolCalls: ToolCall[],        // 当前/历史工具调用（三栏数据源）
  agentTree: AgentNode[],       // 主→子调用链
  isStreaming: boolean,
  pendingApproval: Approval | null,
  actions: { send, cancel, approve, reject }
}
```
- 单向数据流：SSE 事件 → store action → 组件订阅
- 工具调用 = 消息的"附件"而非独立消息（渲染时同气泡展开）

### 3.3 复用（wiki-ui-v2 📌）
- shadcn 组件（button/input/dialog/card…）直接拷贝
- vis-network 图谱配置复用（换数据形状）
- Tailwind 主题配置复用

## 6. 开放问题（评审时定）

1. **是否需要 HistoryPage 独立页**？——建议：仅侧栏列表 + 点击切会话，不做独立页（MVP 减负）
2. **流式渲染库**：`react-markdown` 直接流式渲染 vs 先收集后渲染？——建议：先收集后渲染（token 粒度渲染开销大），流结束一次性 render + 每 200ms 节流刷新
3. **SSE 用 EventSource 还是 ai SDK？**——建议 EventSource 原生（透明可控，ai SDK 的 useChat 虽快但抽象黑盒，学习项目要能讲清楚）
