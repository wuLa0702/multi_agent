## §1 总（30s）

> "多 Agent 工程化的地基是**断点持久化**——deepagents 图每个 super-step 落 SQLite（AsyncSqliteSaver，WAL + busy_timeout），`resume_run_id + checkpoint_id` 精确恢复，断线可续。"

## §2 分（60-90s）

**① 为什么**：多轮研究任务耗时长，一次中断全丢不可接受；HITL 审批依赖 checkpoint 存中断点。
**② 方案**：
- AsyncSqliteSaver：每 super-step 落库（lifespan 管理 async 连接，WAL + busy_timeout 防写锁）
- resume 精确恢复：`resume_run_id`（会话级）+ `checkpoint_id`（精确快照）
- 会话文件隔离：每个 session 独立 backend/工作区
**③ 权衡/追问点（async 教训）**：Sync 版本不兼容 async → AsyncSqliteSaver 修正；伪造 checkpoint 会静默新跑 → `checkpoint_exists` 校验 → RESUME_NOT_FOUND。

## §3 流程图

```
🟦 主图执行：每 super-step → AsyncSqliteSaver 落库
   ├─ 中断（HITL/异常）→ checkpoint 已存
   └─ resume：resume_run_id + checkpoint_id → 精确恢复
```

## §4 总（20s）

> "断点 = 状态一致性 + 可恢复——审批、续跑、防伪造都建立在它上面；这是工程化不是 demo。"
