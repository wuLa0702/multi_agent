## §1 总（30s）

> "无审核的研报质量不可控——我加了**审核子代理**：rubric 同源标准独立审核，产出即检、不通过打回修订最多 2 轮。实测**质量分 +1~2**，但代价是耗时放大 2-8 倍——**代价我主动讲**。"

## §2 分（60-90s）

**① 问题**：首轮评估质量分低（交付格式/章节不符），自己写自己审形同虚设。
**② 方案（review_agent）**：
- **rubric 同源**：审核标准与评估管道同一套，不另立标准
- **无工具 + 全拒绝权限**：审核者不能改，只能判断（独立评审）
- **修订回路**：委派 → 修订重审 ≤2 轮（prompt 引导循环 + recursion_limit 兜底防死循环）
**③ 权衡/追问点**：耗时 2-8×（101s→860s）——审核是质量成本，值得；为什么 2 轮封顶？防无限修订（bad case：报告交付被拒无限修订 → `publish_review_max_revisions` 配置化）。

## §3 流程图

```
主 Agent 产出报告
   ↓ 委派
review_agent（rubric 同源 · 无工具 · 全拒绝）
   ├─ 通过 → 交付
   └─ 不通过 → 打回修订（≤2 轮）→ 重审
```

## §4 总（20s）

> "审核回路证明多 Agent 的价值不在'多'，在**角色分离**——写的人不管质量，审的人不改内容；主动讲 2-8× 代价，面试官看到的是踩过坑的诚实。"
