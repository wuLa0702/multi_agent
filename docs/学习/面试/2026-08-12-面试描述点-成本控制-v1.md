## §1 总（30s）

> "成本控制是这套多 Agent 系统里我做的**生产级收尾**——多 Agent 每次委派都是独立 LLM 调用，成本比单 Agent 高 2-8 倍（实测），不控就是烧钱。我做的是全链路四件套：**token 统计 → 模型单价 → 缓存 → 分级告警**，现在 375 个测试全绿，**每一分钱可核算、可预警**。"

## §2 分（60-90s，四件套 × 各带权衡）

| 件 | 做了什么 | 可追问点 |
|----|----------|----------|
| **① Token 差量统计** | TokenUsageMiddleware 每次 LLM 调用后差量落成本流水（`token_cost_ledger`）| 差量是近似（压缩可能影响）→ P2 接 `usage_metadata` 精确化 |
| **② 模型单价可配** | `PATCH /v1/providers/models/{id}/price` + seed 预填真实官方价（元/千token）| 之前自定义模型单价=0 → **核算是假的**，评审抓出的真问题 |
| **③ LLM 缓存（主链路）** | `_configurable_model` 拦截点，相同 (messages+model) 命中绕过 LLM；辅助+主链路都挂 | 命中率可量化（评审拍板从 P2 升级实施）|
| **④ 分级告警** | 阈值 5/10/20 倍数递增，每档告警一次（修了 MAX 档去重 bug）| "避免打扰也避免失联"——不硬断，提示自主决定 |

## §3 流程图（成本横切挂载）

```
用户 → api → 主图(deepagents) → 工具 → 审核 → SSE 交付
              │
              └─ 🟥 成本横切（中间件栈，图执行完自动触发）
                   ├─ ① LLM 调用 → ③ 缓存命中? → 省一次调用
                   ├─ ② 每次调用 → 差量 token × 单价 → 成本流水
                   └─ ④ 累计超阈值(5/10/20) → cost_alerts 落库 + SSE 提示
```

## §4 总（20s 价值升华）

> "一句话——**成本不是事后统计，是横切在每次 LLM 调用上的护栏**：命中缓存就省一次调用，用了多少记流水，超阈值才告警，单价不对能改。这块和容错、安全一样，都是挂在主流程横切点上加固，不重写业务编排。"
