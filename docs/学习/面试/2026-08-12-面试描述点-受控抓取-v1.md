## §1 总（30s）

> "评估跑数时发现模型**绕过搜索在沙箱自写爬虫**（66 次 curl、循环 50 轮撞限）——提示词管不住的行为要用环境约束。我做了 **fetch_url 受控抓取工具**：搜索发现、抓取获取双工具分工，沙箱断网，**task-001 从 4 连败到成功、沙箱调用 66→1 次**。"

## §2 分（60-90s）

**① 问题**：模型为求数据绕过受控搜索自写 curl 抓取循环——数据外泄风险 + 循环失控。
**② 方案（架构解，非修模型行为）**：
- **fetch_url 工具**：服务端 httpx 抓取 + 清洗 + 截断 + 审计自动覆盖（URL 校验 http/https）
- **沙箱网络隔离**：沙箱只做计算，网络走受控工具（决策 2026-08-11）
- **搜索发现 + 抓取获取双工具分工**：搜索拿 URL 摘要，fetch_url 拿正文
**③ 权衡/追问点**：为什么不在 prompt 里禁止？——提示词约束不可靠，**环境约束才治本**；"发现架构问题比修模型行为更重要"。

## §3 流程图

```
用户请求 → 主 Agent
   ├─ internet_search（搜索发现：URL 摘要）
   └─ fetch_url（受控抓取：服务端 httpx + 清洗截断 + 审计）
沙箱（只计算，断网）
```

## §4 总（20s）

> "这是 bad case 反转的典型——评估当探针发现问题，用**架构决策**（受控工具 + 网络隔离）治本，而不是跟模型行为较劲。"
