## §1 总（30s）

> "我把后端异常做了**四分类 + 降级矩阵**：可重试的（网络/超时/限流）重试后降级，不可重试的直接业务错误码，**除 LLM 主链路外不因单点失败断流**。延迟测试真链路还抓出 4 个单测掩盖的真实 bug。"

## §2 分（60-90s）

**① 异常四分类**：
- 可重试（网络/超时/限流）→ 重试后仍失败 → 降级
- 不可重试（参数/状态/不存在）→ 业务错误码，不重试
- 业务异常 → 业务错误码 + 降级兜底
- 系统异常（未知）→ error 日志 + 按链路矩阵降级
**② 工具重试**：只读工具（search/fetch_url）瞬时失败重试 2 次退避；写操作工具不重试（幂等）
**③ 降级实例（追问点）**：会话落库失败 → 重试 1 次 → 降级内存会话（断库不打断对话）；`except Exception` 精确捕获禁裸吞。

## §3 流程图

```
🟨 容错横切
   ├─ LLM/工具调用 → timeout + retry（adapter 固化）
   ├─ 只读工具 → 重试 2 次退避 → 降级
   ├─ 落库 → 重试 1 次 → 降级内存
   └─ 全链路 → 异常四分类 → 降级矩阵
```
