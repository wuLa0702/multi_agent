## §1 总（30s）

> "我做了**运行时模型切换**：`_configurable_model` middleware 每次模型调用按 `ChatContext.model_id` 换模型，SQLite 注册表是真相源——多 provider（deepseek/ark/智谱），前端选谁下一轮就用谁。"

## §2 分（60-90s）

**① 为什么**：不同任务用不同模型（主 Agent 贵、子代理便宜）；用户可随时切换。
**② 方案**：
- `_configurable_model`：deepagents middleware，每次 LLM 调用读 ChatContext.model_id → 换模型实例
- `core/model_registry.py`：SQLite 注册表真相源（厂商/模型/单价），密钥只经 .env 变量名引用
- 会话级编译图缓存（LRU 32 + 双重检查锁）+ `rebuild_agent`（Skill 变化后失效重建）
**③ 权衡/追问点**：编译图按 thread 缓存，模型切换不能动图结构 → middleware 运行时换模型实例（不动图）；单价 API（F1）改动后 registry reload 生效。

## §3 流程图

```
🟦 用户请求 → ChatContext.model_id（会话级）
   → _configurable_model middleware → 每次 LLM 调用按 model_id 换实例
   → registry（SQLite 真相源，reload 热更新）
```

## §4 总（20s）

> "模型切换 = 注册表真相源 + middleware 运行时换实例——图结构不变、模型可换，这是 deepagents 中间件栈的典型用法。"
