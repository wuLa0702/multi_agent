## 2. 演示流程（7 步 × 讲稿） <span style="color:#fff;background-color:#e11d48;border-radius:4px;padding:1px 6px;font-size:0.8em">v1</span>

> 默认任务：task-003（MCP 协议生态调研——历史 4.0 满分样本，输出稳定）。

```bash
cd backend
python scripts/demo_interview.py
```

| 步 | 屏幕发生什么 | 讲稿（30 秒/步） |
|----|-------------|------------------|
| 1 | 任务发起（青色 ▍任务）| "这是用户的一条研究请求：调研 MCP 协议生态。系统会把它交给主 Agent——deepagents 编译图，我在上面挂了三个东西：模型运行时切换、工具审计、token 用量统计" |
| 2 | run_id 生成（绿色 ▍开始）| "每次对话有 run_id + 会话隔离的断点（SQLite checkpointer）——断线可以 resume 恢复，这是多 Agent 工程化的地基" |
| 3 | token 流开始输出 | "主 Agent 先规划：拆成搜索→抓取→撰写→审核几个阶段。注意它没有一次性输出，是边想边写" |
| 4 | 子代理事件（青色 ▍子代理）| "看这里——它委派了 search_agent 子代理搜索。子代理是独立上下文的，只回结构化结果，不会把搜索过程污染到报告上下文" |
| 5 | 工具调用（黄色 ▍工具）| "搜索发现 URL 后，用 fetch_url 受控抓取正文拿精确数据。为什么不用沙箱爬？——沙箱只做计算，网络走受控工具（有审计、有限流）。这是评估跑数时发现模型自写爬虫后做的架构决策" |
| 6 | 审核回路（子代理再次出现）| "报告写完后会委派 review_agent 审核——独立评审标准（rubric 同源）。不通过就打回修订，最多 2 轮，防死循环。看它这次过了" |
| 7 | done 指标（绿色 ▍完成）| "结束。看数据：耗时 X 秒、token Y、成本约 ¥Z、工具调了 N 次、子代理 M 次。这个成本口径是评估管道一直监控的——每次优化后重跑同任务集对比（git 版本指纹可回溯）" |

**收尾一句话**："整个系统是数据驱动的：离线评估管道 90% 完成率、引用合规 90%，审核子代理上线质量 +1~2 分。要深入讲哪块都行。"

## 3. 回放兜底方案（网络/LLM 不稳时） <span style="color:#fff;background-color:#e11d48;border-radius:4px;padding:1px 6px;font-size:0.8em">v1</span>

**触发**：现场真跑超 2 分钟无输出 / 报错 / 面试官时间紧。

```bash
python scripts/demo_interview.py --replay demo_trace/2026-08-11_task-003.sse
```

**话术**（无缝切换，不尴尬）："现场环境网络不稳，我切预跑的演示数据回放——结果是一样的，这样不浪费时间。"

**回放数据**：面试前跑一次真任务，SSE 输出存文件（§1 预跑动作）。**预跑失败则跳过回放，直接口头讲 §2 流程**（剧本本身可脱离演示独立讲）。

## 4. 演练清单（面试前） <span style="color:#fff;background-color:#e11d48;border-radius:4px;padding:1px 6px;font-size:0.8em">v1</span>
