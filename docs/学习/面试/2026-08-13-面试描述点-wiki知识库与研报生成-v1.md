## §1 总（30s）

> "我把**研报沉淀到 wiki 知识库**做成闭环：主 Agent 撰写 → `generate_report` 结构化 → `publish_report` 审核闸门 → `write_wiki` 归档到 wiki。跨项目通过 **REST/MCP 双通道**打通（前端手动走 REST，Agent 运行时走工具），复用 wiki 的图关系 + 三角定位查询。"

## §2 分（60-90s）

**① 为什么跨项目接 wiki**：不重复造存储——multi_agent 管会话/记忆（SQLite），wiki 管结构化知识（图关系 + 编译质量）；两套职责单一。
**② write_wiki 工具**：Agent 运行时把内容写入 wiki 页面（`POST /v1/pages/{path}`），失败降级不中断 run；配审计 + 路径规范（对话-xxx / 产物-类型-时间）。
**③ generate_report 工具**：主 Agent 撰写 → 结构化（标题/章节/来源引用占位）→ 交付；Word 渲染（沙箱 python-docx）为增强，当前以结构化 Markdown 交付。
**④ 双通道语义（追问点）**：**MCP = Agent 工具通道**（运行时自动查/写）；**REST = 前端手动通道**（用户点"保存到 wiki"）——两者最终都写 wiki，但入口和语义不同。

## §3 流程图

```
用户：调研 MCP 生态，结论存到知识库
  → 主 Agent 推理 1：查已有 → wiki_read（MCP 工具）
  → 主 Agent 推理 2：网络搜索 → internet_search（Searchpin）
  → 主 Agent 推理 3：撰写 → generate_report（结构化）
  → 主 Agent 推理 4：审核 → publish_report（HITL 闸门）
  → 主 Agent 推理 5：沉淀 → write_wiki（归档 wiki）
  → 回复用户「已存到 wiki: xxx」
前端手动：选中对话/产物 → 保存到 wiki → POST /v1/export/wiki → wiki 写入
```

## §4 总（20s）

> "研报闭环 = 生成 → 审核 → 沉淀：`generate_report` 管产出，`publish_report` 管质量闸门，`write_wiki` 管知识复用——下次调研直接查 wiki，不用重复搜。"
