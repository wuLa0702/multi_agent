## §1 总（30s）

> "安全我做了**四层**：注入防护、数据脱敏、文件权限、审计留痕。**安全评审抓出过真漏洞**——`validate_workspace_path` 跨会话路径穿越，修复后 `FileRef` 校验 + `security_audit` 统一审计入口，校验失败自动收口。"

## §2 分（60-90s）

**① 四层设计**：
- **注入防护**：fetch_url 协议校验（http/https + 无注入字符）；命令拼接符禁止（`; && |`）
- **数据脱敏**：工具审计截断 + 密钥模式打码；成本流水不记内容
- **文件权限**：`validate_workspace_path`（workspace/{session_id}/ 白名单）+ `FileRef` 路径校验（防越权回显）
- **审计**：`security_audit` 统一装饰器，校验失败自动收口（不散落）
**② 职责划分（追问点）**：CompositeBackend 管"能不能读写"（路径白名单/会话隔离），本设计管"返回给用户的地址合不合法"——两层互补不重复。
**③ 权衡/追问点**：校验失败降级提示不中断（除 LLM 主链路不因单点断流）；PII 全量识别不做（单用户本地，P2 后）。

## §3 流程图

```
🟨 安全横切（主流程挂载）
   ├─ 注入防护：fetch/命令参数校验 → 失败审计+降级
   ├─ 文件权限：validate_workspace_path + FileRef 校验 → 越权拦截
   └─ 审计：security_audit 装饰器 → 校验失败自动收口留痕
（CompositeBackend：实际读写白名单 / 本设计：返回地址合法性）
```

## §4 总（20s）
