## §1 总（30s）

> "子代理我做成 **YAML 声明式**：每个子代理一个 yaml（模型/权限/工具声明），loader 加载。**独立上下文**——子代理只回结构化结论，搜索过程不污染报告上下文。"

## §2 分（60-90s）

**① 为什么拆（决策故事）**：单 Agent 三个坑——prompt 膨胀、上下文污染、工具过载 → 角色分离（主 Agent 编排 + search 搜索 + review 审核）。
**② 实现**：
- YAML 声明式：`search_agent.yaml`（model 字段按任务选模型，构建期绑定）
- 独立上下文：子代理只回结构化结果（防中间结论错误迁移）
- 权限模板：`build_main/subagent_permissions`（最小工具集）
**③ 权衡/追问点**：委派 = 独立 LLM 调用（成本 2-8×）；异步子代理需 Agent Protocol server（部署不匹配，决策=不做，触发条件已记录）。

## §3 流程图

```
主 Agent（编排/撰写）
 ├─ search_agent（YAML 声明 · 独立上下文 · 便宜模型）
 └─ review_agent（rubric 同源审核 · 无工具 · 全拒绝）
```

## §4 总（20s）

> "多 Agent 的价值在角色分离，不在'多'——声明式 + 独立上下文 + 最小权限，每个都是对应一个真实坑。"
