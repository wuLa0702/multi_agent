## 项目经历

### 基于 Wiki 语义化知识存储的单 Agent 系统

  ~ 2026.05 - 2026.06

**项目背景**：传统 RAG 把文档切碎塞向量库，检索片段答非所问、相似度黑盒不可解释、知识零累积。核心思路是"把文档编译成 wiki 而非塞进向量库"，实现知识可溯源、可沉淀、越用越厚。

**核心工作**：

- **Agent 自纠错机制**：三层自纠错（熔断/校验/反思）替代裸 ReAct 循环——解决无效工具调用多、错误无法自修正的问题，无效工具调用降低约 60%
- **wiki 语义化存储**：非 RAG 路线，文档经两步 CoT 编译成互链结构化页面，查询用 SQLite+BM25+图扩展三角定位——解决 RAG 碎片化检索答非所问、相似度黑盒不可解释的问题，不依赖向量也答准
- **知识图谱**：wikilink 自动构建 4-Signal 关联度 + Louvain 社区发现，纯确定性零 LLM 成本——解决知识间语义关系隐含、无法回答"哪些内容相关"的问题，页面全部带 sources 溯源
- **编译器模式摄入管线**：两步 CoT 编译 + SHA256 增量缓存 + index-summary 注入——解决全量摄入 token 消耗大、重复文件重复处理的问题，摄入 token 节省约 80%
- **工程化落地**：双轨记忆（Attention Sink + Working Memory）、风险分级 HITL、8 个 MCP 工具双模式接入、PyInstaller 桌面打包

**成果**：18,324 行后端代码，782 个测试全绿，无效工具调用降低约 60%，摄入 token 节省约 80%。

### 多 Agent 智能研究系统 —— 深度研究类任务的多 Agent 协作框架

  ~ 2026.06 - 至今

**项目背景**：单 Agent 做深度研究时存在 Prompt 膨胀、上下文污染、工具过载三个结构性问题，且多 Agent 方案成本高 2-8 倍、缺乏可量化评估手段。在单 Agent 项目基础上演进，搭建角色分离、过程透明、成本可控的多 Agent 研究系统，首个落地场景为行业研究。

**核心工作**：

- **多 Agent 协作架构**：主 Agent 编排 + 搜索/审核子代理角色分离，YAML 声明式配置，子代理独立上下文隔离只返回结构化结论，按任务分级选模型——解决单 Agent 职责冲突、搜索结果污染写作上下文的问题，290 个测试全绿，任务完成率 90%
- **SSE 事件协议**：定义 10 类事件做前后端共享契约，将多 Agent 黑盒执行过程实时可视化——解决十几分钟任务用户干等、无法感知执行进度的问题
- **HITL 人在回路**：风险分级中断 + checkpoint 精确断点恢复，审批后从断点继续而非重跑——解决高风险操作无法人工干预、中断后状态丢失的问题
- **离线评估体系**：10 任务集 × 四类指标的可复跑评估管道，规则指标优先、LLM-judge 纯文本解析规避国产模型兼容问题——解决多 Agent 效果"靠感觉"无法量化的问题，评估作为开发探针抓出 3 个 bug
- **工程化三横切**：容错（异常四分类 + 降级矩阵，断库不打断对话）、成本（token 全链路核算 + 缓存 + 分级告警）、安全（路径校验 + 权限分层 + 审计）——延迟测试真链路抓出 4 个单测掩盖的 bug

**成果**：290 个测试全绿，任务完成率 90%，评估抓出 3 个 bug，延迟测试抓出 4 个单测掩盖的 bug，多 Agent 黑盒过程实现 10 类事件可视化。
