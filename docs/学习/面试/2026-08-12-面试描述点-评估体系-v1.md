## §1 总（30s）

> "这个系统里我最看重的是**评估体系**——多 Agent 有没有用不能靠感觉，我做了一个**可复跑、有数据、能纵向对比**的离线评估管道：10 个任务集跑四类指标，首跑完成率 90%。最关键的是——**评估当探针，抓出了 3 个生产 bug**。"

## §2 分（60-90s）

**① 问题**：生产落地必须回答"Agent 到底有没有用"；面试第一分水岭 = 可量化结果。
**② 方案（eval_harness 管道）**：
- 10 任务集（assets 入库）→ 四类 10 项指标（引用合规 A1 / 来源可达 A2 / 规则指标 C-D / 成本）
- **规则指标优先**，LLM-judge 只做主观维度且**纯文本解析**（规避国产模型 response_format 三态全挂）
- **git_commit 版本指纹** → 支持纵向对比（同一任务集不同版本）
**③ 权衡/追问点**：统计显著性弱（10 任务）→ 扩到 50+；judge 与被评估同模型有风格偏好 → 异模型盲评。

## §3 流程图

```
任务集(10) → eval_harness 管道 → 四类指标 → git 指纹存档
                                      ↓ 每批优化后复跑
                              纵向对比（同任务集不同版本）
```

## §4 总（20s）

> "评估不是验收工具，是**开发探针**——每次优化后复跑同任务集，用数据判断是否真的变好；它抓出的 3 个 bug 证明：慢的真相要靠数据，不靠直觉。"
