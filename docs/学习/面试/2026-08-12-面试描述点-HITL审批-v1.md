## §1 总（30s）

> "HITL 是我做的**高级感功能**——人在回路：需求澄清（ask_human）+ 高风险审批（publish_report）四场景一机制，`interrupt_on` 风险分级配置，审批后 **checkpoint resume 真恢复**。实测抓出 call_id 缺失 bug 并修复。"

## §2 分（60-90s）

**① 四场景一机制**：需求澄清 / 高风险审批 / 修订上限 / 恢复链路——同一套 interrupt → approve 事件 → 审批 API → resume。
**② 技术实现**：
- `interrupt_on` 风险分级（工具名白名单），默认关（配置化）
- SSE `approve` 事件（run_id/checkpoint_id/call_id）→ 前端审批卡 → `POST /v1/chat/approve`
- **resume 恢复**：AsyncSqliteSaver 每 super-step 落库，checkpoint_id 精确恢复
**③ 权衡/追问点（实证坑）**：
- `astream_events` 不产 `on_interrupt` → 用 GraphCallbackHandler 采集中断（实证）
- 伪造 checkpoint 静默新跑（状态丢失不报错）→ `checkpoint_exists` 校验 → RESUME_NOT_FOUND
- call_id 缺失 → `_find_action_index` fallback

## §3 流程图

```
🟦 主流程：用户 → api → 主图 → 工具 → 审核 → 交付
🟨 HITL 横切：interrupt_on 命中 → approve 事件 → 审批卡 → /approve → resume
   （GraphCallbackHandler 采集中断 → 落 checkpoint → 恢复精确快照）
```
