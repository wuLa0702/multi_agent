## §1 总（30s）

> "对话流式我定了**前后端共享的 SSE 事件协议**：`start/token/tool_call/subagent/approve/summarize/todos/done/error/cost_alert`，token 逐 chunk 推（打字机效果），工具/子代理事件实时透传——前端按契约渲染，**一个事件一个 Pydantic 模型**。"

## §2 分（60-90s）

**① 为什么 SSE**：多 Agent 过程长（101s→860s），要实时反馈过程；SSE 单向流够用（审批走 REST /approve）。
**② 事件协议**：
- token 逐 chunk（on_chat_model_stream）；tool_call 状态机（running/completed/error）；subagent 启停
- approve（run_id/checkpoint_id/call_id）；cost_alert（成本分级告警）；todos（任务规划）
- 事件 payload 用 Pydantic 模型序列化，前后端共享 types（契约即代码）
**③ 权衡/追问点（实测校准）**：国产模型无 content-block 协议 → v3 直接出 token 毁打字机 → 校准单次 v2 多事件分发。

## §3 流程图

```
🟦 用户 → api/chat_stream → deepagents 主图（astream_events v2）
   → 事件分发（token/tool_call/subagent/approve/cost_alert/todos）→ SSE → 前端
   → done（上下文用量/耗时）
```

## §4 总（20s）

> "SSE 不是简单的流式输出——是**多 Agent 过程的可视化协议**：每个事件对应一个前端组件（工具卡/审批卡/成本徽标），契约前后端共享。"
