# 记忆体系串讲（口述级整合版）

> 📌 **关联**：`面试话术/05-记忆体系.md`（分问题话术）、`面试/2026-08-12-面试描述点-记忆体系-v1.md`（客观素材）
> 📊 **状态**：待背
> 🔄 **最后更新**：2026-08-14

> 这一份不是逐问题的问答话术，是把整个记忆体系**串成一条主线**的口述版——
> 读一遍能复述，面试被问"你记忆系统整体怎么做的"直接讲这条线。

---

## 一句话总览（30秒口述）

"我的记忆系统是三层的：**文件记忆**管 Agent 的项目常识，**语义 Store** 管跨会话的用户画像和事实，**memory_agent** 负责后台异步把值得记的记下来、不拖慢对话。整条线串起来是——**对话开始时读记忆注入，对话跑完后台写记忆，下一条消息再读出来**。"

---

## 一、三层各管什么，数据都存哪

口述："三层分工很清晰：

- **文件记忆**：AGENTS.md 是项目指南，全量注入，告诉 Agent 这个项目的规矩；tasks/decisions 是任务和决策，按需读、不常驻。存在 `data/memory/` 文件夹。
- **语义 Store**：存的是'值得记住的事实'——用户画像（user_profile）和客观事实（facts），是 memory_agent 用 LLM 从对话里抽出来的。存在 SQLite（`data/store.db`）。
- **断点**：这里容易混——运行时快照是 **Checkpointer** 管的（`checkpoints.db`），**不是 Store**。Store 管长期记忆，Checkpointer 管执行状态/断点，别搞反。"

一句话：**文件管常识（文件夹）、Store 管回忆（SQLite）、Checkpointer 管断点（SQLite）**。

---

## 二、一条消息的完整生命周期（串起来的核心）

口述："拿一条用户消息走一遍就全串起来了：

**① 读**：用户发消息，后端先取最近记忆注入到 SystemMessage，Agent 带着记忆开始跑。
**② 跑**：Agent 正常执行，流式输出，SSE 推给前端。
**③ 写（关键）**：输出跑完，把'这次对话 + 回复'打包成一个记忆任务，丢进后台队列——注意这里**不阻塞**，done 事件马上发。
**④ 后台**：队列的 worker 慢慢消费任务，调 memory_agent 子代理——它判断这段对话有没有值得记的，有就抽成一句话事实，按类型写进 Store。
**⑤ 循环**：下一条消息又回到①，读出来的就是刚写进去的记忆——跨会话就这么串起来了。"

---

## 三、后台为什么不阻塞

口述："记忆抽取是额外一次 LLM 调用，如果同步等它，用户看到结果就慢了。所以做成**队列 + worker**：对话结束只把任务丢进队列（指纹去重——session + 用户消息 + 回复一起 hash，同一段对话不会重复入队），worker 在后台各自消费。

每个任务是一次完整的 memory_agent 抽取——**2 个 worker 就是同时最多 2 个抽取任务在跑，不是 1 个 Agent 切 3 个活**。worker 数是我调出来的常量，单用户够用就行，不是越多越好（多了是同时打更多后台 LLM 调用，纯烧 token）。"

---

## 四、检索怎么取

口述："对话开始时读记忆，读取有三条原则：**画像优先**（用户画像永远排在事实前面）、**时间衰减**（新的在前）、**窗口裁剪**（注入的记忆 token 不超过上下文的 10%，防止撑爆窗口）。

⚠️ **诚实标注**：这三个原则的函数已经写好了（`load_recent_memories_v3`），**但主链路还没切过去**——现在实际用的是简单版（只取最近 5 条）。面试讲到这要主动说'检索升级已开发、接线中'，别把没上线的说成已上线。"

---

## 五、已实现 vs 规划（诚实清单）

口述："哪些是活的、哪些是规划，我心里有数：

**已实现且在用**：三层骨架、Store 读写、memory_agent 队列后台写、AGENTS.md 注入。
**写了但没接线**：v3 检索（画像/衰减/裁剪）——函数在，主链路没调。
**规划中的**：tasks.md / tasks_archive.md（现在磁盘上只有 decisions.md，任务文件还没生成）；write_wiki 是占位。
**可串但未串**：wiki 读写服务已合并（export + read 两个服务都在），可以把 memory_agent 的写 wiki 接上去，让 wiki 当'文档记忆'的存储——但注意 wiki 是**文档存储不是向量检索**，替代不了语义 Store。"

---

## 一句话记忆

**一条线：读（注入）→ 跑 → done → 队列丢任务 → worker 后台抽 → 写 Store → 下条再读。三层：文件管常识、Store 管回忆、Checkpointer 管断点。诚实分清：v3 检索没接线、tasks.md 没生成、wiki 可串但只是文档记忆。**
