## 一、核心认知（P0：先建立正确观念）

> ⚠️ **最大的误区**：把 Agent 当 Java 八股学，背定义、背概念。
>
> **真相**：Agent 面试考的是**系统设计能力 + 项目追问链**。面试官要听的是你发现问题、解决问题的真实故事。

| 认知 | 说明 |
|------|------|
| **项目 > 八股** | 一个讲得透的好项目，比背 100 道八股有用 |
| **追问链 > 知识点覆盖** | 面试官不会问"Agent 是什么"，他会顺着你的项目一路深挖 |
| **复盘 > 刷题** | 面试后整理逐字稿，更新简历，比刷 10 道题有用 |
| **现在就开始** | 别等完全准备好再投递。先投中小厂攒经验，用面试校验水平 |
| **时间窗口** | 转行有红利期，早期门槛最低，过了 26 年可能就悬了 |

## 二、优先级行动清单（P0：现在就做）

按优先级排序，**从上往下做，做完一个再做下一个**：

| 优先级 | 行动 | 预计时间 | 说明 |
|--------|------|----------|------|
| **P0-1** | **确定简历项目，把框架补完** | 3-5 天 | 选定"多 Agent 行业研究系统"，把核心功能跑通 |
| **P0-2** | **补全项目 5 个关键模块** | 5-7 天 | 评估、成本、安全、容错、HITL（详见 §3.2） |
| **P0-3** | **整理项目追问链** | 2-3 天 | 每个技术点都准备好"为什么这么做、对比过什么方案、遇到什么坑" |
| **P0-4** | **简历埋点 + STAR 化** | 1-2 天 | 每个项目点都预设坑，准备完美答案 |
| **P0-5** | **开始投递（中小厂）** | 立即 | 别等准备好，边面边补。用面试倒逼学习 |
| **P1-6** | **每天刷八股（辅助）** | 每天 30 分钟 | 重点是理解体系，不是死记硬背 |
| **P1-7** | **每次面试后复盘** | 每次 1 小时 | 整理逐字稿，更新简历和追问链 |

## 三、项目准备（P0：核心中的核心）

### 3.1 项目选型：多 Agent 行业研究系统

**为什么选这个**：
- 覆盖面广：RAG、工具调用、Memory、多 Agent、评估，全能放进去
- 有业务价值：不是玩具项目，真实场景
- 可深可浅：基础功能好做，深挖也有东西

**项目一句话描述**：
> 拆解研究任务，同时查网页和本地知识库，多个 Agent 并行研究，最后完成事实核验和报告生成。

### 3.2 必须补全的 5 个模块

> ⚠️ 你现在的项目缺这些，面试一定会被问到。优先级从高到低：

| 优先级 | 模块 | 为什么重要 | 要做到什么程度 |
|--------|------|-----------|---------------|
| **P0** | **评估体系** | 怎么证明你的 Agent 有用？面试官必问 | 至少有：准确率、召回率、人工评估、bad case 分析 |
| **P0** | **HITL 机制** | 高级感的体现，区分初级和高级 | 需求澄清、中途确认、高风险审批、输出审核，四个场景至少做两个 |
| **P1** | **容错处理** | 工程能力的体现 | 工具调用失败重试、降级策略、超时处理、异常兜底 |
| **P1** | **成本控制** | 生产环境必考虑 | Token 用量统计、模型分级、缓存策略、预算控制 |
| **P2** | **安全机制** | 加分项，不是必问 | Prompt 注入防护、数据脱敏、权限控制、审计日志 |

### 3.3 项目追问链（面试官会怎么问）

> 🎯 **核心原则**：每个点都要能往下挖 3 层。面试官顺着你的回答一路问，答不上来就减分。

**完整追问链条（从浅到深）**：

```
第 1 层：业务层
  ├─ 这个 Agent 解决什么业务问题？
  ├─ 用户是谁？使用场景是什么？
  └─ 为什么要用 Agent 做？传统方案为什么不行？

第 2 层：架构层
  ├─ 整体架构是什么样的？画一下
  ├─ 为什么要拆成多个 Agent？一个不行吗？
  ├─ 每个 Agent 的职责是什么？输入输出是什么？
  ├─ 任务是谁拆的？模型拆还是规则拆？为什么？
  └─ 对比过哪些方案？为什么选这个？

第 3 层：实现层
  ├─ RAG 怎么做的？chunk 怎么切？召回率多少？
  ├─ 工具调用怎么实现的？失败了怎么办？
  ├─ 记忆怎么做的？短期长期怎么分？
  ├─ 多 Agent 怎么协作？同步还是异步？
  └─ 遇到过什么坑？怎么解决的？

第 4 层：效果层
  ├─ 怎么评估效果？用什么指标？
  ├─ 上线后提升了多少？有数据吗？
  ├─ 怎么证明是 Agent 带来的提升，不是其他因素？
  └─ bad case 有哪些？怎么处理的？

第 5 层：优化层
  ├─ 现在还有什么不足？
  ├─ 如果给你更多时间，你会怎么改进？
  ├─ 成本怎么控制的？
  └─ 安全问题怎么考虑的？
```

**准备方法**：把你项目里每个技术点，都按这个链条自问自答一遍。答不上来的，就是要补的。

## 四、简历优化与埋点（P1）

### 4.1 埋点策略

**什么是埋点**：在简历上预设面试官会问的"坑"，把每个坑的完美答案提前准备好。

**怎么做**：
1. 简历上每写一个技术点，都问自己："如果我是面试官，我会怎么深挖？"
2. 把深挖的问题和答案提前准备好
3. 故意在简历上留"钩子"，引导面试官问你准备好的问题

**例子**：
- 简历写"优化了 chunk 切分策略，检索准确率提升 15%"
- 提前准备：之前是什么策略？现在是什么？为什么这么改？对比了哪些方案？怎么评估的？15% 怎么算出来的？还有什么不足？

### 4.2 STAR 法则展开链

每个项目点都按 STAR 法则展开，**一环套一环，不能想当然**：

```
S（场景）
  ├─ 业务背景是什么？
  ├─ 在什么场景下做的？面向什么用户？
  └─ 遇到什么痛点？

T（任务）
  ├─ 要解决什么问题？
  └─ 目标是什么？

A（行动）—— 重点
  ├─ 现有方案有什么不足？用户反馈了什么问题？
  ├─ 为什么调研了这个方案？怎么发现这个解决思路的？
  ├─ 对比过哪些方案？各有什么优劣？
  └─ 做了什么优化？（这是核心）

R（结果）
  ├─ 上线效果怎么评估？用什么指标衡量？
  ├─ 提升了多少？（要有数据）
  └─ 方案还有什么不足？时间充裕还想做什么改进？
```

### 4.3 技术深度原则

> ❌ **面试官最反感**：队列一大堆技术名词，问到哪个都只能说个大概（深度不够）。
>
> ✅ **正确做法**：与其说十个技术点每个浅尝即止，不如深挖三个点。

**原则**：
- 不堆砌技术名词
- 讲透一个点 > 浅尝十个点
- 每个技术点准备一个"小故事"（背景→问题→方案→结果）
- 动手实践没有替代品——面试官会问非常细的实践问题（比如 learning rate 设了多少、为什么）

## 五、八股知识体系（P1：辅助理解，不是重点）

> 📌 **定位**：八股是辅助理解体系的，不是面试重点。重点还是项目。
>
> **怎么学**：按"追问链"的顺序学，而不是按知识点顺序学。每学一个点，都想"这个在我项目里怎么用？面试官会怎么问？"

**完整知识体系（10 大模块）**：

| 模块 | 内容 | 优先级 |
|------|------|--------|
| **01 岗位与项目地图** | Agent 岗位有哪些？分别考什么？ | P1 |
| **02 业务问题与 Agent 适用边界** | 什么问题适合用 Agent？什么不适合？ | P0 |
| **03 Agent Harness** | 任务拆解、执行与终止、规划能力 | P0 |
| **04 HITL 与需求澄清** | 人在回路、什么时候需要停下来问人 | P0 |
| **05 知识、记忆与检索** | RAG、短期/长期记忆、向量检索 | P0 |
| **06 Tool Calling、MCP、Skill 与 Runtime** | 工具调用、工具协议、技能体系 | P0 |
| **07 Multi-Agent 架构** | 多 Agent 协作模式、通信、调度 | P0 |
| **08 评测、观测、安全与治理** | 怎么评估效果、怎么监控、安全问题 | P1 |
| **09 工程可靠性** | 状态持久化、流式输出、沙箱、部署 | P1 |
| **10 项目表达与面试追问** | 怎么讲项目、怎么应对追问 | P0 |

**每天刷题**：https://offerforge.top/quiz/session?source=bank&category=agent&start_id=1550
- 每天 30 道，早上刷
- **重点**：不是背答案，是理解思路，然后想"这个在我项目里怎么体现"

## 九、项目场景评估与加固计划（P0：2026-08-10 调研定案）

### 9.1 场景评估结论：不换场景，加固「行业研究」载体

> 📌 2026-08-10 多源调研（面经 + 面试官标准，Sources 见下），核心证据：
> - 行业研报 Agent 是**面试经典考题**，面试官有标准预期——真实面经「多智能体深度行业调研系统」（6 Agent）被逐层深挖：各 Agent 职责、搜索来源由谁决定、审核意见为何不回到规划节点、是否保留历史版本选最优
> - 面试第一分水岭 = **评估与可量化结果**（baseline 对比），多源收敛；本项目 🔴 缺评估体系
> - 必考题「为什么用多 Agent」：拆分四前提（角色分离 / 工具差异 / 上下文冲突 / 并行收益）；研究场景天然满足「并行探索 + 上下文隔离」；必须**主动讲代价**（成本放大、延迟、调试难）
> - 个人定位拍板：**Harness/框架向 + 中厂/转型岗 + 无行业背景** → 场景只是载体，技术深度才是卖点，**不换场景**
