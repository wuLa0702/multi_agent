## 1. 总：背景、目标与范围

### 1.1 背景

v1 方案（MemoryMiddleware 启用）被批评**偏薄**——只做了"把 MemoryMiddleware
接上去"的基础设施层，记忆体系的核心设计（**类型、策略、检索**）基本没碰。
本版全面重设计：从"能记住"升级到"**记得准、找得到、用得好**"。

**一句话定位**：v1 是有记忆，v2 是会记忆——先分类（知道记什么）→ 再定规矩
（知道怎么记）→ 然后会找（知道怎么取）→ 最后治理（知道怎么管）。

### 1.2 目标

1. **类型体系（P0）**：四类记忆分层（用户画像/任务/决策知识/事实常识），
   各居其位、互不干扰
2. **写入策略（P1）**：从"靠自觉"到"有规矩"——触发条件、结构化格式、更新规则
3. **检索机制（P1）**：从"全量塞"到"按需取"——三层注入 + 语义检索演进 + 窗口控制
4. **记忆治理（P2）**：噪音控制 / 版本回滚 / 人工干预

### 1.3 范围

| 在本方案内 | 不在本方案内 |
|-----------|-------------|
| 四类记忆拆分 + 多文件布局 + 写入格式模板 | 向量数据库引入（语义检索先关键词/标签方案，向量标注演进） |
| 触发条件清单 + 更新规则（追加/冲突/去重） | 记忆自动评测/质量评分模型 |
| 三层注入（核心/相关/详情）+ 窗口控制 | 前端记忆管理面板（标注后续） |
| 治理：审计日志 + git 回滚（利用现有 git） | 记忆加密/多租户隔离（单机不需要） |
| v1 基础设施成果保留（MemoryMiddleware 启用） | — |

## 2. 分·现状盘点与 v1 批评

### 2.1 v1 三个核心缺失（批评提炼）

| 缺失 | 问题 |
|------|------|
| **无记忆类型分类** | 所有记忆塞一个 AGENTS.md：用户偏好/任务/决策/事实/摘要混在一起——越写越乱，agent 找东西慢，互相干扰 |
| **无写入策略** | 只有一句 system prompt 指引（"值得记住的就写"）——何时写？什么格式？怎么更新？怎么遗忘？全靠模型自觉：要么啥都不记，要么啥都记 |
| **无检索机制** | 全量注入（AGENTS.md 全文 + Store 取最近 N 条）——记忆多了就爆：无相关性检索、无类型过滤、无时间衰减 |

### 2.2 其他问题（v1 遗留）

| 问题 | 说明 |
|------|------|
| 单文件瓶颈 | AGENTS.md 越来越大，8KB 阈值只是提醒，无自动处理 |
| 双层分工模糊 | 文件记忆和 Store 都存"事实"，边界不清，容易重复存 |
| 无质量控制 | 写错/写多/写偏无审核机制 |
| 无版本历史 | 记忆文件改坏无法回滚 |
| 无优先级 | 重要记忆与琐碎记忆平权 |

### 2.3 v1 保留成果（本版基础）

| 成果 | 状态 |
|------|------|
| Store 语义记忆底座（AsyncSqliteStore + memory_store.py LLM 抽取） | ✅ 已启用 |
| MemoryMiddleware 机制确认（多 sources 注入，虚拟路径语义） | ✅ 已核实 |
| /memories/ 路由权限与审计 | ✅ 已就绪 |

## 3. 分·设计一：记忆类型体系（P0——先分类，再谈其他）

### 3.1 四类记忆分层

| 类型 | 存在哪 | 谁写 | 内容示例 | 生命周期 |
|------|--------|------|---------|---------|
| **用户画像** | Store（结构化） | LLM 抽取 | 偏好、习惯、身份、常用语 | 长期 |
| **任务记忆** | 文件记忆（tasks.md） | agent 主动写 | 待办、进行中、已完成 | 中短期 |
| **决策/知识** | 文件记忆（decisions.md） | agent 主动写 | 项目约定、技术选型、踩坑教训 | 长期 |
| **事实/常识** | Store（结构化） | LLM 抽取 | 客观事实、名词解释 | 长期 |

**分层原则**：
- **Store 存结构化短事实**（适合检索、适合 LLM 抽取）：用户画像 + 事实常识
- **文件记忆存长文上下文**（适合 agent 读写、适合人类阅读）：任务 + 决策知识
- 各司其职，不打架——**消除 v1 双层分工模糊**（v1 两层都存"事实"）

### 3.2 文件记忆布局（多文件，替代单 AGENTS.md）

```
data/memory/（/memories/ 路由，全局共享）
├── tasks.md           # 任务记忆（中短期，agent 主动维护）
├── decisions.md       # 决策/知识（长期，agent 主动维护）
└── AGENTS.md          # 兜底通用（渐进披露的官方语义保留，不承载分类内容）
```

- MemoryMiddleware 多 sources 注入：`memory=["/memories/AGENTS.md",
  "/memories/tasks.md", "/memories/decisions.md"]`（多 sources 拼接注入，
  官方支持——memory.py:38 "Multiple sources are concatenated in order"）
- **user_profile/facts 不进文件**——Store 结构化（§3.1 分工）

## 4. 分·设计二：写入策略（P1——从"靠自觉"到"有规矩"）

### 4.1 写入触发条件（不是每轮都写，满足任一才写）

1. 用户明确说"记住"、"以后都这样"
2. 出现新的用户偏好/习惯
3. 做出重要决策/约定
4. 发现重要事实/规律
5. 任务状态变化（新增/完成/取消）

### 4.2 写入格式（结构化模板，非自由文本）

```markdown
# 用户画像（Store，LLM 抽取——键值对）
- 语言偏好：中文
- 回复风格：简洁直接
- 技术栈：Python/React

# 任务记忆（tasks.md，agent 主动写）
- [ ] 完成沙箱池化开发（优先级：高）
- [x] CompositeBackend v3 改造

# 决策记录（decisions.md，agent 主动写）
## 2026-08-05 沙箱选型
- 决策：选 OpenSandbox 自建
- 原因：可控性强、成本低
- 风险：需要自己维护
```

### 4.3 更新规则

| 规则 | 行为 |
|------|------|
| **追加优先** | 新信息追加，不随便删旧的 |
| **冲突处理** | 新信息覆盖旧信息，旧信息移到"历史"区（保留可追溯） |
| **去重** | 相同/相似信息合并，不重复写 |

### 4.4 遗忘策略（P2 细化）

- 任务完成 → 移入"已完成"区（不删，可查）
- 决策过时 → 新决策覆盖 + 旧决策标注"已废弃（被 XX 取代）"
- 定期整理：压缩归档（§6.1）

## 5. 分·设计三：检索机制（P1——从"全量塞"到"按需取"）

### 5.1 三层注入策略

| 层 | 注入时机 | 内容 | 方式 |
|----|---------|------|------|
| **核心层** | 每次会话开头 | 用户画像 + 重要决策 | 全量注入（量少：Store 画像 + decisions 关键节） |
| **相关层** | 对话过程中 | 与当前话题相关的记忆 | 检索注入（按类型/标签/关键词过滤，按需取） |
| **详情层** | agent 主动读 | 完整记忆文件 | agent 自己调文件工具读（read_file /memories/tasks.md） |

### 5.2 检索方式升级

| 层 | v1（现状） | v2 目标 | 实现 |
|----|-----------|---------|------|
| Store | 取最近 N 条 | 语义相似度检索 | P1 先关键词/标签过滤；**向量检索标注演进**（需引入向量能力，见风险项） |
| 文件 | 全量注入 | 按类型/标签过滤 + 关键词匹配 | MemoryMiddleware 多 sources 拆分后按需注入 |

**时间衰减**：越新权重越高，越旧越低（P1 检索排序参数；P2 正式化）

### 5.3 上下文窗口控制

- 记忆注入总量上限：**≤ 上下文 10%**（阈值配置化）
- 超限裁剪优先级：**用户画像 > 当前任务 > 相关事实 > 旧决策**

## 6. 分·设计四：记忆治理（P2——质量控制）

### 6.1 噪音控制

- 写入前校验：不符合格式的不写（LLM 抽取侧校验 + 文件格式模板校验）
- 定期整理：每周/每月自动压缩归档旧记忆（脚本 + 审计）
- 重要性评分：每条记忆 1-5 分，低分优先裁剪（P2）

### 6.2 版本与回滚

- 记忆文件变更走 git（项目本就 git 管理）——`data/memory/` 需解除 gitignore 或
  独立版本目录（⚠️ 现状 data/ 整体 gitignore，记忆文件入库需评估，见风险项）
- 每次写入留审计日志（谁、什么时候、改了什么——复用 audit logger）
- 写错可回滚（git checkout 或审计回溯）

### 6.3 人工干预

- "记忆管理"面板（前端）：查看/编辑/删除记忆（标注后续）
- 重要记忆人工确认后生效（可选：interrupt 审批——权限模板预留）

### 7.1 实施路线

| 阶段 | 内容 | 工作量 | 依赖 |
|------|------|--------|------|

### 7.2 风险自检清单

- [ ] **记忆文件入库（最高）**：data/memory/ 当前被 data/ 整体 gitignore——治理
      的"git 回滚"依赖它入库；需评估：记忆入库 vs 运行时数据不入库的原则冲突
      （方案：记忆独立版本目录或仅 decisions.md 入库——评审决策点）
- [ ] **语义检索依赖**：向量检索需引入向量能力（sqlite-vec/外部向量库）——
      P1 先用关键词/标签过滤替代（诚实标注：非真语义，是结构化近似）
- [ ] **Store 类型化**：memory_store.py 现为单 namespace("memory","global")——
      类型化需按类型分 namespace（user_profile/facts）或加 type 字段（实施细化）
- [ ] **多 sources 注入的 token 成本**：三个记忆文件全量注入违反 §5.1 分层——
      MemoryMiddleware 只支持全量 sources 注入；分层注入需自建中间件（P1 关键
      设计决策：官方 MemoryMiddleware 注入全量 vs 自建分层中间件，二选一）
- [ ] **写入质量**：触发条件清单 + 格式模板约束模型行为，仍非强制——
      审计兜底 + P2 校验；学习 demo 初期接受噪音
- [ ] **先红后绿**：P0 测试先行；提交前 pytest 全绿

### 8.3 Store 类型化写入（P1：memory_store.py 按类型分 namespace）

```python
"""（memory_store.py 增量：v2 类型体系——用户画像/事实常识分 namespace）"""

# v1 单 namespace 扩展为类型化（P1）：
MEMORY_NAMESPACES = {
    "user_profile": ("memory", "user_profile"),   # 用户画像（长期）
    "facts": ("memory", "facts"),                 # 事实/常识（长期）
}
# 兼容保留：("memory", "global") 旧数据迁移（实施时一次性搬移）

async def save_typed_memory(store, memory_type: str, fact: str) -> None:
    """类型化写入（LLM 抽取分类后落对应 namespace）。

    Args:
        store: AsyncSqliteStore 实例
        memory_type: user_profile / facts（§3.1 分工）
        fact: 抽取的一句话事实

    Raises:
        ValueError: 未知类型
    """
    namespace = MEMORY_NAMESPACES.get(memory_type)
    if namespace is None:
        raise ValueError(f"未知记忆类型：{memory_type}，可选 {list(MEMORY_NAMESPACES)}")
    if store is None:
        return
    await store.aput(namespace, str(time.time()), {"fact": fact, "ts": time.time()})
```
