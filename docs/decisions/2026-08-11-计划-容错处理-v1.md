## 1. 背景与目标 <span style="color:#fff;background-color:#e11d48;border-radius:4px;padding:1px 6px;font-size:0.8em">v1</span>

**Why（双动机）**：
1. **面试**（备战指南 §3.2）：容错处理（P1）——"工程能力的体现"，追问点：工具调用失败重试、降级策略、超时处理、异常兜底。当前项目容错**散落不系统**，面试答"怎么容错"缺完整故事
2. **工程**：生产环境工具调用失败是常态（网络/限流/超时），无系统化重试+降级 = 对话中断率高、故障难定位

**目标**：把结构优化规范 v2 §7 的**异常四分类 + chat 链路降级矩阵**从设计稿落地为代码——统一异常体系、工具失败重试、链路逐节点降级、超时统一。

**边界（不做）**：不做熔断器（circuit breaker，单机单用户不需要）；不做分布式重试队列（单进程够用）。

## 3. 设计 <span style="color:#fff;background-color:#e11d48;border-radius:4px;padding:1px 6px;font-size:0.8em">v1</span>

### 3.1 异常四分类扩展（core/errors.py）

| 分类 | 基类 | 定义 | 处理 |
|------|------|------|------|
| 可重试 | `RetryableError`（已有）| 网络超时/抖动/限流 | 重试 N 次 → 仍失败降级 |
| 不可重试 | `NonRetryableError`（已有）| 参数错/权限拒绝/校验失败 | 直接返回错误码 |
| 业务 | `BusinessError`（新增）| 业务规则不满足 | 业务错误码 + 降级返回/默认兜底 |
| 系统 | `SystemError`（新增）| 未知内部错误 | 记 error 日志 + 按链路矩阵降级 |

**与既有兼容**：`RetryableError`/`NonRetryableError` 不动，新增两个子类，基类加 `category` 字段（retryable/non-retryable/business/system）便于矩阵匹配。

### 3.2 工具调用失败重试（agent/middlewares/tool_retry.py 或 core/retry.py）

- **装饰器 `@retry_tool(retries=2, delay=0.5, only=(RetryableError, TimeoutError))`**：
  - 工具实现抛 `RetryableError`/超时 → 重试最多 2 次（退避 0.5s/1s）
  - 非可重试异常/业务异常 → 不重试直接降级
  - 重试耗尽 → 降级返回（错误字符串，不中断 run，与现状一致）
- **接入**：关键工具（internet_search / fetch_url / run_skill_script）包一层；或注册表统一包装（TOOL_REGISTRY 装配时加）

### 3.3 chat 链路降级矩阵落地（结构优化规范 v2 §7.2 逐节点核对）

| 链路节点 | 失败形态 | 降级策略 | 断流？ | 落地动作 |
|----------|----------|----------|--------|----------|
| 会话/消息落库 | SQLite 错（可重试）| 重试 1 次 → 降级内存会话（标注未持久化）| 否 | chat.py 精确捕获 RetryableError |
| 记忆注入/读取 | Store 不可用 | 静默降级（跳过记忆）| 否 | 已有，核对 |
| 记忆写入 | Store 不可用 | 记 error + 队列重试（P2）| 否 | 已有旁路 |
| LLM 调用 | 超时/不可用 | 重试耗尽 → SSE error（retryable=true）| 是（协议设计）| 已有 |
| 工具调用 | 工具异常 | **本计划 §3.2 重试 → 错误结果回传** | 否 | 新增重试 |
| 子代理 | 子图异常 | 错误摘要回传主 agent | 否 | 核对 |
| 沙箱执行 | 沙箱不可用 | 返回工具错误 + AUTH/ENV 提示 | 否 | 已有降级 |
| 审核/审批 | checkpointer 异常 | 拒绝审批请求（400），状态保持 | 否 | 已有 |

**核对目标**：全链路无裸 `except Exception`（结构优化规范 §7.1 禁令），每节点精确捕获 + 降级。

### 3.4 超时统一

- 工具级：fetch_url 已有 10s；internet_search / run_skill_script 补统一超时（settings 可配 `tool_timeout_seconds`）
- 沙箱命令级：adapter.run_command 已有 timeout 参数（None = 不强制）——默认给 60s

### 4.2 追问链预演（§3.3 五层自答）

| 追问 | 预演答案 |
|------|----------|
| **为什么做容错？** | 生产工具调用失败是常态（网络/限流/超时）——无系统化重试+降级 = 对话中断率高；面试工程能力体现 |
| **为什么异常四分类？** | 可重试（瞬时故障→重试）/不可重试（参数错→直接返回）/业务（规则不满足→降级兜底）/系统（未知→记日志不暴露）——降级策略精准匹配异常类型，避免"一刀切重试"浪费成本 或 "一刀切失败"丢失可恢复请求 |
| **工具失败为什么重试？** | 瞬时故障（限流 429/超时）本可成功——重试 2 次退避，成功率提升；重试预算（次数+退避）防雪崩 |
| **为什么不中断对话？** | 降级矩阵原则：除 LLM 主链路外全部"失败降级不断流"——工具失败回传错误让 Agent 自行处理，用户感知降级而非崩溃 |
| **裸捕获为什么禁？** | `except Exception` 包整段 = 掩盖真实故障（调试黑洞）——精确捕获 + 记录 + 降级三件套 |
| **怎么量化？** | 评估跑数统计：工具失败率 / 重试成功率 / 降级触发次数（trace 已采集工具调用，加异常计数）|

### 4.3 可量化结果（落地后预期产出）

- 工具失败率：评估跑数前后对比（重试后成功率 ↑）
- 重试命中次数：logs 统计（trace 加 `tool_retry` 事件）
- 降级矩阵核对清单：全链路无裸捕获（AST 扫描）

### 5.1 `backend/src/core/errors.py` 四分类扩展（增量）

```python
class AppError(Exception):
    """应用异常基类（统一携带 message + code + category）。"""

    def __init__(self, message: str, code: str = "APP_ERROR", *, category: str = "system") -> None:
        super().__init__(message)
        self.message = message
        self.code = code
        self.category = category  # retryable / non-retryable / business / system


class RetryableError(AppError):
    """可重试异常：网络超时、连接抖动、临时故障。"""

    def __init__(self, message: str, code: str = "RETRYABLE") -> None:
        super().__init__(message, code, category="retryable")


class NonRetryableError(AppError):
    """不可重试异常：参数错误、权限拒绝、业务校验失败。"""

    def __init__(self, message: str, code: str = "BAD_REQUEST") -> None:
        super().__init__(message, code, category="non-retryable")


class BusinessError(AppError):
    """业务异常：业务规则不满足 → 降级返回/默认兜底数据。"""

    def __init__(self, message: str, code: str = "BUSINESS") -> None:
        super().__init__(message, code, category="business")


class SystemError(AppError):
    """系统异常：未知内部错误 → 记 error 日志，按链路矩阵降级（不暴露细节）。"""

    def __init__(self, message: str, code: str = "INTERNAL") -> None:
        super().__init__(message, code, category="system")


class ConfigError(NonRetryableError):
    """配置缺失或非法。"""

    def __init__(self, message: str) -> None:
        super().__init__(message, code="CONFIG_ERROR")
```

> ⚠️ 兼容：现有代码 `retryable` 布尔属性保留（`@property` 映射 category == "retryable"），旧调用不破。

### 5.2 `backend/src/core/retry.py` 工具重试装饰器

```python
"""工具调用重试（P1 容错：瞬时故障重试，重试耗尽降级返回）。

原则（结构优化规范 v2 §7.1）：
- 只重试可重试异常（RetryableError / TimeoutError）——预算有限防雪崩
- 业务/不可重试/系统异常不重试，直接降级
- 重试耗尽 → 返回错误提示字符串（与工具降级现状一致，不中断 run）
"""

import asyncio
import logging
from collections.abc import Callable
from functools import wraps

logger = logging.getLogger(__name__)

DEFAULT_RETRIES = 2
DEFAULT_DELAYS = (0.5, 1.0)  # 退避：0.5s / 1s


def retry_tool(
    retries: int = DEFAULT_RETRIES,
    delays: tuple[float, ...] = DEFAULT_DELAYS,
) -> Callable:
    """工具函数重试装饰器。

    Args:
        retries: 最大重试次数
        delays: 每次重试的退避秒数

    Returns:
        包装后的工具函数（重试耗尽仍失败 → 降级错误字符串）
    """

    def decorator(func: Callable) -> Callable:
        @wraps(func)
        def wrapper(*args, **kwargs):
            last_exc: Exception | None = None
            for attempt in range(retries + 1):
                try:
                    return func(*args, **kwargs)
                except (RetryableError, TimeoutError) as exc:
                    last_exc = exc
                    if attempt < retries:
                        delay = delays[min(attempt, len(delays) - 1)]
                        logger.info("工具 %s 重试 %d/%d（%s）", func.__name__, attempt + 1, retries, type(exc).__name__)
                        time.sleep(delay)
            # 重试耗尽 → 降级（记录 + 返回错误提示）
            logger.error("工具 %s 重试耗尽：%s", func.__name__, last_exc)
            return f"工具调用失败（{type(last_exc).__name__}）：{last_exc}。请稍后重试。"

        return wrapper

    return decorator
```
