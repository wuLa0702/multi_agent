## 4. 前端功能规划 <span style="color:#fff;background-color:#e11d48;border-radius:4px;padding:1px 6px;font-size:0.8em">v1</span>

### 4.1 对话界面（含补充功能 1：一键到底按钮）

**现状**：ChatMessages.tsx 滚动容器（scrollRef），消息追加后滚动到底部；OverviewRuler 展示进度概览；**无脱离底部检测**。

**补充功能 1——一键回到最新（详设）**：

| 项 | 设计 |
|----|------|
| 触发条件 | 滚动容器 `scrollHeight - (scrollTop + clientHeight) > 500`（**脱离底部 500px**）时显示按钮；回到 500px 内隐藏 |
| 按钮形态 | 右下角悬浮圆钮（ChatInput 上方，z 层低于弹窗）：`↓ 回到最新`，带未读消息数角标（可选） |
| 点击行为 | `scrollTo({ top: scrollHeight, behavior: "smooth" })`，滚回后隐藏 |
| 自动跟随策略 | 用户滚动脱离底部 → **暂停流式自动跟随**（新消息不抢滚动）；点击回底 → 恢复自动跟随 |
| 与 OverviewRuler 关系 | 位置分离（Ruler 在滚动条侧，按钮在右下角），互不干扰 |
| 实现位置 | 新组件 `components/chat/ScrollToBottom.tsx`（监听 scroll 事件 + 500px 阈值计算） |
| 依赖 | 无后端依赖，纯前端 |

**其他对话界面规划**：
- **代理模式透传**：AgentModeSelector 当前纯本地 → ChatInput 的 mode 状态传入 `POST /v1/chat/stream`（`mode: "default"|"plan"|"agent"|"auto"`，后端接口已支持）
- **附件上传真实化**：📎 接 `POST /v1/uploads`（后端已实现），消息气泡展示附件（§4.5 mock 表项去 mock）
- 工具调用四栏保持现状（已覆盖 tool_call/subagent 事件）

### 4.2 高风险审批 UI（补充功能 2：人工审批 · 详设）

**后端现状（代码实证，`agent/hitl/hitl.py`）**：
- `hitl_enabled` 门控（默认关，SettingsPage 开关）
- **风险分级 interrupt_on**：
  - 高危（`run_code_in_sandbox` 任意代码执行）→ `approve + edit + reject` 三决策
  - 中危（命令/文件上传下载/技能脚本）→ `approve + reject` 两决策
  - 只读/无副作用工具 → 不审批
- 事件契约：SSE `approve` 事件（`run_id/call_id/tool_name/arguments/message`）；`POST /v1/chat/approve` → 202 → 前端重连 `resume_run_id`
- ⚠️ 恢复链路（checkpoint resume）待 P0-V2 验证——**UI 按契约先实现，联调时校准**

**前端审批 UI 设计**：

| 项 | 设计 |
|----|------|
| 触发 | 收到 SSE `approve` 事件 → 渲染审批卡片（非阻塞全屏弹窗，对话流挂起） |
| 卡片内容 | 工具名 + **风险等级徽标**（高危=红 / 中危=橙，按工具名映射）+ arguments 结构化展示 + message（为何需要批准） |
| 决策按钮 | 按后端 `allowed_decisions` 动态渲染：`approve`（批准）/ `edit`（编辑参数后批准，仅高危）/ `reject`（拒绝，可附理由 note） |
| 提交 | `POST /v1/chat/approve {run_id, action, note?}` → 收到 202 → 自动重连 `POST /v1/chat/stream {session_id, resume_run_id}` |
| 恢复 | 新流首事件 `start {resumed: true}` → 重置审批状态、清空增量缓冲、继续渲染 |
| 断线恢复 | `pendingRunId` 存 localStorage（页面刷新后提示"有待审批操作"，恢复弹窗） |
| 错误处理 | `RUN_NOT_FOUND`/`NOT_PENDING` → 清理审批态提示"审批已失效"；`RESUME_NOT_FOUND` → 提示"断点已失效可重新开始" |
| 实现位置 | 新组件 `components/chat/ApprovalCard.tsx` + ChatPage 状态管理（pendingApprove 状态机：idle → pending → submitted → resumed） |
| 设置联动 | SettingsPage 增加 HITL 开关（`hitl_enabled`，默认关） |

**审批状态机**：
```
idle ──approve 事件──▶ pending ──POST approve──▶ submitted（202）
                        │                          │
                        └──reject/超时──▶ closed   └──重连 start(resumed)──▶ idle（继续渲染）
```
