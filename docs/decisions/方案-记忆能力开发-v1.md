## 1. 总：背景、目标与范围

### 1.1 背景

用户直觉"项目没有启用记忆"——**核实结论（2026-08-05）：一半对**：

| 记忆层 | 状态 |
|--------|------|
| **Store 语义记忆**（SQLite 全局事实，LLM 抽取式） | ✅ **已启用**——memory_store.py + chat.py 注入/后台写入 |
| **官方文件记忆**（MemoryMiddleware + `/memories/` 路由） | ❌ **未启用**——`/memories/` 路由空置，`data/memory/` 无人读写 |

持久化计划 B.1（文件记忆）为待办；且 B.1 的改造点写法存在**虚拟路径隐患**
（`memory=[str(get_memory_dir())]` 磁盘路径会被 backend virtual_mode 拒绝——与
skills 同款教训：sources 必须用虚拟路径 `/memories/...`）。

### 1.2 目标

1. **文件记忆启用**：MemoryMiddleware 挂载（`/memories/AGENTS.md` 渐进记忆），
   跨会话回忆闭环（B.1 验收场景落地）
2. **双层记忆体系整合**：文件记忆（agent 主动维护的上下文文件）与 Store 语义
   记忆（程序化抽取的全局事实）分工清晰，不互相打架
3. **B.1 虚拟路径隐患修正**：memory sources 用虚拟路径（backend 协议语义）
4. 记忆写入机制设计：agent 自主写 + 指引 + 噪音控制 + 审计

### 1.3 范围

| 在本方案内 | 不在本方案内 |
|-----------|-------------|
| MemoryMiddleware 启用 + AGENTS.md 渐进记忆 | 记忆自动评测/质量体系 |
| 双层记忆分工与整合 | 记忆版本管理/冲突合并 |
| 记忆写入指引 + 噪音控制 | 记忆加密（单机场景，暂不需要） |
| 记忆权限与审计确认（/memories/ 已可写+审计） | 按会话隔离记忆（当前全局共享设计） |

## 3. 分·设计

### 3.1 双层记忆体系（分工）

```
文件记忆（MemoryMiddleware，对话级上下文）      Store 语义记忆（程序化抽取，全局事实）
┌──────────────────────────────┐            ┌──────────────────────────────┐
│ /memories/AGENTS.md          │            │ store.db                     │
│ 渐进记忆：agent 主动维护      │            │ namespace=("memory","global")│
│ 写入：agent 用 write_file    │            │ 写入：LLM 抽取（memory_store）│
│ 注入：每次会话开头全量        │            │ 注入：chat.py 取最近 N 条     │
│ 语义：对话上下文/项目约定     │            │ 语义：用户事实/偏好/决策     │
└──────────────────────────────┘            └──────────────────────────────┘
        谁写：agent（模型驱动）                     谁写：程序（LLM 抽取式）
        内容：上下文/约定/待办                     内容：一句话事实
        特征：长文、可编辑、人工可读                特征：短句、结构化、检索
```

**分工原则**：
- 文件记忆 = **agent 工作记忆的持久化**（它认为重要的上下文，主动维护）
- Store = **程序筛选的长期事实**（LLM 判断"值得记住"的全局事实）
- 两者互补：文件记忆管"上下文连续性"，Store 管"事实沉淀"

### 3.2 MemoryMiddleware 启用（B.1 落地 + 虚拟路径修正）

```python
# main_agent.py _build_agent：create_deep_agent 增加
memory=["/memories/AGENTS.md"],   # ⚠️ B.1 修正：虚拟路径（backend 协议语义），
                                  # 非磁盘路径（磁盘路径会被 virtual_mode 拒绝）
```

- 注入机制：每次会话开头，MemoryMiddleware 读 AGENTS.md 全文注入 system prompt
- 全局共享：AGENTS.md 单文件跨会话共享（官方渐进记忆语义）——多会话回忆同一份上下文

### 3.3 记忆写入机制（agent 自主写 + 指引）

MemoryMiddleware 无原生写——写入靠 agent 用文件工具：

```
agent 对话中 → 判断"值得记住"（关键事实/用户偏好/项目约定）
  → write_file("/memories/AGENTS.md", 全文更新)    # /memories/ 路由可写（MEMORY_POLICY）
  → 权限层：写审计（policy_backend 审计行）         # 已就绪
  → 下次会话：MemoryMiddleware 注入更新后的全文
```

**system prompt 记忆指引**（DEFAULT_SYSTEM_PROMPT 追加，教 agent 何时写）：

```
## 记忆维护
当对话中出现值得长期记住的信息（用户偏好、关键决策、项目约定）时，
用 write_file 更新 /memories/AGENTS.md（保留原有内容，追加新条目）。
仅写事实性内容，不写对话过程。无新信息时不要改动记忆文件。
```

### 3.4 噪音控制

| 控制点 | 方案 |
|--------|------|
| 写入时机 | system prompt 指引（§3.3）——"仅事实性内容，不写对话过程" |
| 审计 | `/memories/` 写操作全量审计（policy_backend 层，已就绪）——噪音可追溯 |
| 高危子目录 | `/memories/private|secrets/**` interrupt 审批开关预留（权限模板 INTERRUPT_PERMISSIONS_ENABLED）——敏感记忆人工把关 |
| 上限 | AGENTS.md 超长（>阈值，如 8KB）→ system prompt 指引"精简/归档"（后续可加自动摘要） |

### 3.5 权限与隔离

- `/memories/` 全局共享读写 + 写审计（现状已具备，无改动）
- 隔离矩阵（v3 设计文档 §4.1）不变：记忆全局共享是设计决策
- 文件记忆与 Store 都全局共享——跨会话回忆闭环的物理基础

## 6. 总·优先级与风险自检

### 6.1 优先级

| 优先级 | 项 | 内容 | 依赖 |
|--------|----|------|------|
| **P0** | MemoryMiddleware 启用 | main_agent `memory=["/memories/AGENTS.md"]` + 开关 | 无（backend 路由已就绪） |
| **P0** | system prompt 记忆指引 | DEFAULT_SYSTEM_PROMPT 追加（何时写/写什么） | 无 |
| **P1** | 回忆闭环测试 | B.1 验收场景（会话 A 写 → 会话 B 回忆） | P0 |
| **P1** | 噪音控制深化 | AGENTS.md 超长阈值 + 精简指引 | P0 |
| **P2** | 敏感记忆审批激活 | interrupt 权限开关 + approve 链路（依赖前端） | 审批链路 |

### 6.2 风险自检清单

- [ ] **虚拟路径（最高）**：memory sources 必须 `/memories/` 虚拟路径——磁盘路径
      被 virtual_mode 拒绝（B.1 原写法隐患）；验收用例断言无磁盘路径
- [ ] **MemoryMiddleware 空文件容错**：AGENTS.md 不存在 → 空注入不报错
      （实施第一步实测，不猜）
- [ ] **写入噪音**：agent 自主写记忆有模型驱动风险——指引 + 审计 + 后续阈值；
      初期接受噪音（学习 demo 定位）
- [ ] **双层不打架**：文件记忆（上下文）与 Store（事实）分工清晰；
      同一信息两处都写可接受（不同粒度）
- [ ] **审计完整**：/memories/ 写操作审计已就绪（policy_backend），无改动
- [ ] **先红后绿**：P0 测试先行；提交前 pytest 全绿
