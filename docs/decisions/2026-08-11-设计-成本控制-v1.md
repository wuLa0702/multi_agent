### 2.2 追问链预演（指南 §3.3 五层链 × 三问自答）

**Q1：成本怎么核算？**

- 为什么：多 Agent 并行 + 多轮 ReAct 的 token 消耗是真实成本，面试必问"怎么证明成本可控"。
- 对比过什么方案：① 只算 context_used（现状，当前占用非累计——语义不符"成本"）② 只统计 token 不折算（无单价，无法回答"花了多少钱"）③ **真实单价核算**（✅ 选定）：models 表加 input/output_price（元/千 token），中间件按 token×单价落 `token_cost_ledger` 流水——每会话成本可审计、可汇总。
- 坑与量化：token 数是"估算"（chars/4 近似）非模型真实 usage——成本也是近似值（面试主动说明"近似估算，生产可换真实 tokenizer/usage 字段"）。量化：会话成本 = Σ(input_tokens×input_price + output_tokens×output_price)/1000。

**Q2：预算怎么控？为什么不硬限制？**

- 为什么：生产环境要有成本护栏，但不能绑架用户——强制拒绝/降级会破坏对话体验。
- 对比过什么方案：① 硬限制（超预算拒绝请求/自动切便宜模型）→ 简单但粗暴，用户失去自主权 ② **软告警**（✅ 选定）：记录 + 超阈值告警落库 + 前端提示——观测优先，用户看到告警自主决定。面试可讲"成本是观测问题不是管控问题"。
- 坑与量化：告警要**落库**（用户拍板）而非只前端飘过——`cost_alerts` 表留痕可回溯。量化：超阈值触发告警落库 + 前端 notices 提示（§8 用例 8-10）。

**Q3：缓存怎么省 token？**

- 为什么：重复/相似查询重复调 LLM 是纯浪费——缓存命中即省一次完整调用。
- 对比过什么方案：① 完整缓存（LRU + 语义相似检索）→ 复杂 ② **轻量结果缓存**（✅ 选定 P0）：`llm/cache.py` 相同 (prompt, model) 命中返回，TTL + settings 开关——实现轻、命中率可量化；完整版 P2 接语义检索。
- 坑与量化：缓存键要含 model（不同模型不共享）；缓存失效/超内存要兜底（命中失败直接调 LLM）。量化：缓存命中率 = 命中数/总调用数（§8 用例 11-12）。

### 2.3 可量化结果（落地后预期产出）

| 指标 | 预期值 | 测量方式 |
|------|--------|----------|
| 成本流水可审计 | 每会话成本可查（token×单价，精确到模型）| §8 用例 1-3（流水落库 + summary API）|
| 单价核算准确 | 会话成本 = Σ(input×in_price + output×out_price)/1000 | §8 用例 2（构造单价断言）|
| 预算软告警 | 超阈值 → cost_alerts 落库 + 前端 notices | §8 用例 8-10 |
| 缓存命中率 | >0（重复查询命中）且可量化 | §8 用例 11-12（构造重复 prompt）|
| 面试叙事资产 | 1 个"成本可控"故事（§2.1 埋点）| 追问链文档回填（§4.6 流程）|

## 4. 分·机制设计：四要素 × 软告警

### 4.1 成本核算（真实单价 × token 流水）

```
每次图执行（TokenUsageMiddleware.aafter_agent 已有钩子）
  → 计算本轮消耗 token（输入+输出；现有 context_used 是全量占用，需补"本轮增量"）
  → 查 models 表单价（model_id → input_price/output_price，元/千 token）
  → cost = (input_tokens×input_price + output_tokens×output_price) / 1000
  → 落 token_cost_ledger 流水（session_id, model_id, input_tokens, output_tokens,
     input_cost, output_cost, total_cost, created_at）
```

- **token 口径**：现有 `context_used` 是"当前上下文占用"（含历史），成本核算需要**本轮增量**——深化：`aafter_agent` 里 `state["messages"]` 是执行后全量，需对比执行前（中间件维护 per-run 起点）或改用 langchain 的 usage_metadata（真实 token，若模型返回）。P0 用"全量差量近似"（本轮 = 执行后 − 执行前），文档标注可换 usage_metadata。
- **脱敏**：流水只记 token/成本，不记 prompt 内容（成本是"钱"不是"内容"）。

### 4.2 模型分级档位（单价即档位）

- models 表加 `input_price/output_price` → 单价本身即成本档位（cheap/standard/premium 由单价区间推导）
- 现有 `_configurable_model` 已支持按 model_id 选模型——P1 只落地单价，**自动选档 P2**（如搜索子代理用便宜模型、报告用贵模型——依赖单价排序）

### 4.3 缓存策略（轻量结果缓存）

```
llm/cache.py：get_cache(key) / set_cache(key, value, ttl)
  key = hash(prompt + model_name)   # 不同模型不共享
  → 命中：省一次完整 LLM 调用；未命中：调 LLM 后写入
  → settings.llm_cache_enabled 开关 + TTL（默认如 3600s）
  → 缓存不可用（异常）→ 直接调 LLM（降级不阻断）
```

- 挂载点：`LLMAdapter.chat`（辅助任务）优先；deepagents 主链路 P2 再接（中间件层）
- 面试点：命中率可量化，重复查询省 token

### 4.4 预算软告警（只记录 + 落库，不做硬限制）

```
每次成本核算后：
  → 累计会话成本（token_cost_ledger 按 session 聚合）> settings.session_cost_warn_threshold
  → 落 cost_alerts 表（session_id, threshold, total_cost, message, created_at，去重防重复）
  → SSE/前端 notices 提示"会话成本已达 ¥X，超阈值 Y"
```

- **只记录 + 告警**（用户拍板）：不拒绝请求、不自动降级——观测优先，用户自主
- **告警落库**（用户明确要求）：`cost_alerts` 表留痕，可回溯"何时超阈值"
- 去重：同一阈值只告警一次（`cost_alerts` 查最近一条是否同阈值，避免每次核算都弹）

## 5. 分·设计决策（D1-D7）

### 5.1 D1：成本核算落 `token_cost_ledger` 表（新） 🔴 v1

- 新表：`(id, session_id, model_id, input_tokens, output_tokens, input_cost, output_cost, total_cost, created_at)`——每次图执行一条流水，可审计可汇总
- 复用 TokenUsageMiddleware 钩子（不新挂中间件）；token 用"执行后 − 执行前"差量近似

### 5.2 D2：models 表加单价字段（迁移） 🔴 v1

- `input_price REAL DEFAULT 0`（元/千 token 输入）+ `output_price REAL DEFAULT 0`（元/千 token 输出）
- 复用 `_migrate_columns` 模式（schema.py 幂等加列）；seed 时给默认模型填单价

### 5.3 D3：缓存策略用轻量结果缓存（新 llm/cache.py） 🔴 v1

- `llm/cache.py`：内存 dict + TTL（进程级，单用户够）；key=hash(prompt+model_name)
- settings 加 `llm_cache_enabled`（默认 False，面试演示开）+ `llm_cache_ttl`
- 挂 `LLMAdapter.chat`；deepagents 主链路 P2

### 5.4 D4：预算软告警落 `cost_alerts` 表（新） 🔴 v1

- 新表：`(id, session_id, threshold, total_cost, message, created_at)`
- settings 加 `session_cost_warn_threshold`（元，默认如 5.0）
- 触发：成本核算后累计 > 阈值 → 落库 + SSE 提示；同阈值去重

### 5.5 D5：成本查询 API 🟠 v1

- `GET /v1/cost/summary?session_id=` → `{session_id, total_cost, input_tokens, output_tokens, alert_count}`（聚合 ledger）
- `GET /v1/cost/alerts?session_id=` → 告警列表（可选）
- 响应模型进 `schemas/cost.py`

### 5.6 D6：告警经 SSE 提示前端 🟠 v1

- 成本核算后若触发告警 → SSE 事件 `cost_alert`（新事件类型，或复用 notices 机制）
- 前端 chatStore 处理 `cost_alert` → pushNotice（复用既有 notices）
- P0 后端落库 + SSE 事件；前端 UI 展示 P2（或复用 ContextUsage 组件扩展）

### 5.7 D7：不做清单 ⚪ v1

- ❌ 自动降级/换便宜模型（P2：软告警不触发硬动作）
- ❌ 按任务类型自动选档（P2：有单价后按档位排序）
- ❌ 完整缓存（LRU/语义相似检索，P2）
- ❌ 全局预算/多会话聚合（P2）
- ❌ 前端成本面板 UI（P2：先 API 后 UI）

## 6. 分·权衡与风险

| 风险/权衡 | 等级 | 缓解 |
|-----------|------|------|
| token 估算非真实 usage（chars/4 近似）| 中 | 文档标注近似；P2 接 langchain usage_metadata（若国产模型返回）|
| 成本流水膨胀（每次图执行一条）| 低 | 表按 session 可聚合；TTL 清理 P2（流水保留审计）|
| 缓存命中/内存泄漏 | 低 | 轻量内存 dict + TTL；命中失败直接调 LLM 兜底 |
| 告警频繁打扰 | 低 | 同阈值去重（cost_alerts 查最近一条）；阈值可配置 |
| 预算阈值配置缺失 | 低 | settings 默认值（5.0 元）+ .env.dev 可调 |
| 与既有 context_used 语义混淆 | 低 | 明确区分：context_used=当前占用（前端进度条），ledger=累计成本（审计）|

### 7.1 `backend/src/db/schema.py` 增量（单价列迁移 + 2 新表）

```python
# schema.py 增量（设计 §5.1/§5.2/§5.4）：

# models 表加单价列（新库 CREATE 已含；旧库走 _migrate_columns）
#    input_price REAL DEFAULT 0,   -- 元/千 token 输入
#    output_price REAL DEFAULT 0,  -- 元/千 token 输出

# 新表：成本流水（设计 §5.1，D1）
_COST_LEDGER_SQL = """
CREATE TABLE IF NOT EXISTS token_cost_ledger (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id    TEXT NOT NULL,
    model_id      INTEGER NOT NULL,
    input_tokens  INTEGER NOT NULL DEFAULT 0,
    output_tokens INTEGER NOT NULL DEFAULT 0,
    input_cost    REAL NOT NULL DEFAULT 0,
    output_cost   REAL NOT NULL DEFAULT 0,
    total_cost    REAL NOT NULL DEFAULT 0,
    created_at    TEXT NOT NULL,
    FOREIGN KEY (session_id) REFERENCES sessions(id) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS idx_cost_ledger_session ON token_cost_ledger(session_id);
```

```python
    total = round(input_cost + output_cost, 6)

async def _check_cost_alert(session_id: str, total_cost: float) -> bool:
    """累计成本超阈值 → 落 cost_alerts + 返回是否触发（设计 §4.4/§5.4）。

    Args:
        session_id: 会话 ID
        total_cost: 本次核算后累计成本（元）

    Returns:
        True=触发告警（调用方发 SSE 提示）；False=未触发
    """
    threshold = settings.session_cost_warn_threshold
    if threshold <= 0 or total_cost <= threshold:
        return False
    from src.core import db as core_db

    conn = await core_db.get_connection()
    try:
        # 去重：同阈值最近已告警 → 不再重复
        cur = await conn.execute(
            "SELECT threshold FROM cost_alerts WHERE session_id = ? "
            "ORDER BY created_at DESC LIMIT 1",
            (session_id,),
        )

        if last and abs(float(last["threshold"]) - threshold) < 1e-9:
            return False
        await conn.execute(
            """INSERT INTO cost_alerts (session_id, threshold, total_cost, message, created_at)
               VALUES (?, ?, ?, ?, ?)""",
            (session_id, threshold, total_cost,
             f"会话成本已达 ¥{total_cost:.2f}，超阈值 ¥{threshold:.2f}", _now_utc_str()),
        )
        await conn.commit()
    finally:
        await conn.close()
```

### 7.3 `backend/src/llm/cache.py`（轻量结果缓存，全量）

```python
"""LLM 结果缓存（设计 §4.3/§5.3）：轻量内存 dict + TTL。

- key = sha1(prompt + model_name)——不同模型不共享缓存
- settings.llm_cache_enabled 开关；llm_cache_ttl 过期
- 缓存不可用/异常 → 直接调 LLM（降级不阻断，容错纪律）
- P2 升级：LRU 上限 + 语义相似检索（记忆 Store 对接）
"""

from __future__ import annotations

import hashlib
import time
import threading

_cache: dict[str, tuple[float, str]] = {}
_lock = threading.Lock()
_MAX_ENTRIES = 1024  # 容量上限（防泄漏，超限逐出最旧）


def _key(prompt: str, model_name: str) -> str:
    """缓存键：prompt + model 哈希（不同模型不共享）。"""
    return hashlib.sha1(f"{model_name}:{prompt}".encode()).hexdigest()


def get_cached(prompt: str, model_name: str, ttl: int) -> str | None:
    """查缓存（未命中/过期返回 None）。

    Args:
        prompt: 输入 prompt
        model_name: 模型名（缓存键维度）
        ttl: 有效期（秒）

    Returns:
        缓存结果；None=未命中/过期
    """
    key = _key(prompt, model_name)
    with _lock:
        entry = _cache.get(key)
        if entry is None:
            return None
        ts, value = entry
        if time.monotonic() - ts > ttl:
            _cache.pop(key, None)
            return None
        return value


def set_cached(prompt: str, model_name: str, value: str) -> None:
    """写入缓存（容量上限逐出最旧）。

    Args:
        prompt: 输入 prompt
        model_name: 模型名
        value: 模型回复
    """
    key = _key(prompt, model_name)
    with _lock:
        if len(_cache) >= _MAX_ENTRIES:
            oldest = min(_cache, key=lambda k: _cache[k][0])
            _cache.pop(oldest, None)
        _cache[key] = (time.monotonic(), value)
```

### 7.4 `backend/src/api/cost.py`（成本查询路由，全量）

```python
"""成本查询（设计 §5.5）：会话成本汇总 + 告警列表。

- 写入方：TokenUsageMiddleware 成本核算落 token_cost_ledger / cost_alerts
- 本接口只读：前端成本展示（P2 UI）或调试/审计
"""

from __future__ import annotations

from fastapi import APIRouter, HTTPException, Query

from src.core import db as core_db

router = APIRouter(prefix="/v1/cost", tags=["cost"])


@router.get("/summary")
async def get_cost_summary(session_id: str = Query(..., description="会话 ID")):
    """会话成本汇总（聚合 token_cost_ledger）。

    Returns:
        {"session_id", "total_cost", "input_tokens", "output_tokens", "alert_count"}
    """
    conn = await core_db.get_connection()
    try:
        cur = await conn.execute(
            """SELECT COALESCE(SUM(input_tokens),0) AS it, COALESCE(SUM(output_tokens),0) AS ot,
                      COALESCE(SUM(total_cost),0) AS tc FROM token_cost_ledger
               WHERE session_id = ?""",
            (session_id,),
        )
        row = await cur.fetchone()
        cur2 = await conn.execute(
            "SELECT COUNT(*) AS n FROM cost_alerts WHERE session_id = ?", (session_id,)
        )
        alert = await cur2.fetchone()
    finally:
        await conn.close()

    if row is None:
        raise HTTPException(status_code=404, detail={
            "error": "ErrorResponse", "detail": "会话无成本记录", "code": "COST_NOT_FOUND",
        })
    return {
        "session_id": session_id,
        "total_cost": round(row["tc"], 4),
        "input_tokens": row["it"],
        "output_tokens": row["ot"],
        "alert_count": alert["n"] if alert else 0,
    }
```
