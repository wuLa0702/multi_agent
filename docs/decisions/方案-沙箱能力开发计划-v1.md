## 1. 总：背景、目标与范围

### 1.1 背景

项目沙箱层（OpenSandbox 阿里开源，SDK 0.1.15）当前是**初始薄壳**：`src/sandbox/adapter.py`
一个适配器 5 个方法 + `run_code_in_sandbox` 一个工具函数，每次调用"创建沙箱 → 写代码 →
执行 → 销毁"，30 秒就绪等待 + 首次拉镜像的开销每次全付。SDK 0.1.15 已提供
`renew / pause / resume / connect / create_snapshot / 持久 bash 会话 / 后台任务 / egress 策略`
等能力，项目**零使用**。

deepagents 官方模型（docs/langchain.com/oss/python/deepagents/sandboxes）：
**沙盒 = backend**——SandboxBackendProtocol 在文件操作之上增加 `execute` 工具
（任意 shell 命令），agent 获得"全部文件工具 + execute + 隔离边界"；沙盒生命周期
由调用方用 provider SDK 管理（try/finally delete_sandbox）。官方 provider：
LangSmith / Daytona / E2B / Runloop / Vercel；本地参考实现 `LocalShellBackend`
（FilesystemBackend + SandboxBackendProtocol）与 `BaseSandbox`（大输出 offload 到文件）。

**定位决策**（2026-08-05）：OpenSandbox 自建部署（本地 docker / 云端自管），
**对标官方"外部管理生命周期"模式**——沙箱由本项目后端管理，不是官方托管 provider。

### 1.2 目标

1. **会话级沙箱复用**（P0）：每会话（thread_id）一个沙箱实例，TTL 续期 + 空闲回收——
   消除"每次工具调用 create+destroy + 30s ready"的重复开销
2. **执行能力分层**（P1）：一次性 run_code 保留；增强多文件脚本、命令超时、
   持久 bash 会话、后台任务（SDK 已支持，接线即用）
3. **文件同步边界**（P1）：backend 持久文件（workspace）↔ 沙箱临时文件的
   上传/取回约定，明确"持久在 backend、执行在沙箱"的双层模型
4. **安全与审计闭环**（P0/P1）：容器隔离边界确认、密钥不注入、生命周期审计
   （工具调用审计已由 ToolAuditMiddleware 覆盖）、egress 策略可选收紧、资源限额
5. **官方抽象演进预留**（P2）：`OpenSandboxBackend(SandboxBackendProtocol)`
   让 deepagents 原生 execute 工具可用——标注代价与取舍，不急于落地

### 1.3 范围

| 在本计划内 | 不在本计划内 |
|-----------|-------------|
| 会话级沙箱池 + TTL 续期 + 空闲回收 | 多机/多进程沙箱池共享（redis pool_store，SDK 有但单机不需要） |
| 执行增强（多文件/超时/会话/后台） | 沙箱快照模板工程化（P2 预留 create_snapshot 接线） |
| workspace ↔ 沙箱文件同步约定 | OpenSandboxBackend 实现（P2，本计划只给设计） |
| 生命周期审计 + 密钥纪律 + 资源限额 | 沙箱内 git/代码仓库场景（后续按需） |
| 兼容：现有 run_code_in_sandbox 签名不变 | Docker-in-Docker / 构建流水线 |

## 3. 分·设计

### 3.1 会话级沙箱生命周期管理（P0，核心）

**定位**：项目后端扮演官方文档中"provider SDK"的角色——管理沙箱创建、复用、续期、回收。

**会话级沙箱池**（`src/sandbox/pool.py` 新建，手写核心逻辑）：

```
SandboxPool（进程内单例，thread_id 维度）
  ├─ get_sandbox(thread_id) → SandboxSync   # 懒创建：无则 create（TTL=sandbox_timeout）
  │                                        # 有则 renew() 续期 + 返回（同实例连续 run 保留状态）
  ├─ release(thread_id)                    # 归还（无需操作，池不销毁；仅记录）
  ├─ destroy(thread_id)                    # 主动销毁（会话删除 / 显式清理）
  └─ sweep()                               # 空闲回收：超过空闲阈值的沙箱 destroy
      （守护任务或调用时惰性检查，二选一，见 §4 兼容）
```

**关键决策**：

| 项 | 方案 | 依据 |
|----|------|------|
| 池维度 | thread_id（会话级）——主 agent + 子代理共用该会话沙箱 | 与 backend 会话隔离同维度；多会话沙箱天然隔离 |
| 复用语义 | 同一 thread 的连续工具调用**共享沙箱**（文件/环境保留） | SDK 同实例语义；消除重复 create+ready |
| TTL 续期 | 每次取用时 `renew(sandbox_timeout)`——沙箱在活跃会话中永不过期 | SDK `renew` 接口（sync/sandbox.py:284） |
| 空闲回收 | `sweep()`：`sandbox_idle_ttl`（如 15min）无访问 → destroy | 防资源泄漏；服务端 TTL 只是兜底 |
| 创建失败 | 降级为错误字符串返回（现有工具语义），不中断 run | 与 run_code_in_sandbox 现状一致 |
| 并发 | 单机单用户，锁内懒创建（threading.Lock，同 _agents 模式） | 无跨进程需求（redis pool_store 留演进） |
| 内存模式 | `MEMORY_WORKSPACE=True` 时沙箱池仍可用（沙箱与 backend 独立） | 沙箱是执行层，与存储模式正交 |

**生命周期审计**（P1，与 CompositeBackend 审计同通道）：
`layer=sandbox` 审计行——create/destroy/renew/sweep 各事件带 thread_id/sandbox_id/原因。

### 3.2 执行能力分层（P1）

| 层 | API（adapter 扩展） | 场景 | 备注 |
|----|--------------------|------|------|
| 一次性 | `run_code(code, filename)`（现状，签名不变） | 快速验证脚本 | 内部改为"池化沙箱 + 续期"，不再每次 create/destroy |
| 多文件 | `run_script(files: dict[str,str], entry: str)` | 多文件项目（写多个再跑） | `files.write_files(entries)`（SDK :134） |
| 命令 | `run_command(cmd, *, timeout, envs)`（增强） | shell 操作、pip install | `RunCommandOpts.timeout/envs`（models/execd.py:273） |
| 持久会话 | `run_in_session(session_id, cmd)` | 同一 bash 会话连续命令（cd 状态保留） | SDK create_session/run_in_session（:47 附近） |
| 后台 | `run_background(cmd) → id` + `poll(id)` | 长任务（pip install、测试套件） | `background=True` + `get_background_command_logs` |
| 输出上限 | 单次输出截断阈值（如 8KB），超限提示落文件取回 | 防上下文爆炸 | 对标官方 offload 语义的轻量版 |

注册进 registry（§3.3 文件同步配套）；`run_code_in_sandbox` 语义不变（兼容 demo）。

### 3.3 文件同步边界（P1）

**双层模型（明确边界）**：

```
backend（持久层，CompositeBackend 会话隔离）        sandbox（执行层，容器内临时）
  workspace/{thread_id}/  ←──────────────→   /workspace/（沙箱内工作目录约定）
  /memories/ /skills/ /exports/（只读/共享）     ↑ 上传：backend 读 → sandbox 写
                                               ↓ 取回：sandbox 读 → backend 写
```

- **方向语义**：上传 = 把 workspace 文件（或 agent 代码）送入沙箱执行；
  取回 = 把沙箱运行产物（报表/结果文件）落回 exports/ 或 workspace
- **约定**：沙箱内统一 `/workspace/` 目录（create 后初始化）；虚拟路径不混用——
  sandbox 工具的路径参数**独立命名空间**（如 `sandbox:/workspace/x.py`），
  不与 backend 虚拟路径（`/workspace/`）混淆（防路径越权误判）
- **实现**：adapter 增 `upload_file(sandbox, local_virtual_path, content)` /
  `download_file(sandbox, sandbox_path)`；工具层映射 backend 路径 → 沙箱路径
- **审计**：上传/取回走 ToolAuditMiddleware（敏感工具名单加 upload/download）

### 3.4 安全与审计（P0/P1）

| 项 | 方案 | 依据 |
|----|------|------|
| 隔离边界确认 | 沙箱 = 容器级隔离（docker runtime，compose 已配 docker.sock）；沙箱内 FS/网络与宿主机隔离是**设计意图**，不是漏洞 | 官方文档"secure boundary"定位 |
| 密钥纪律 | create 的 `env` 与命令级 `envs` **白名单注入**（显式字段，绝不读 .env 全量）；工具参数与审计日志禁密钥字段 | 00-security.md 硬约束 |
| 资源限额 | create 时 `resource={"cpu","memory"}`（SDK 默认 1cpu/2Gi，可下调适配 2核4g 单机） | sync/sandbox.py:554 |
| 生命周期审计 | `layer=sandbox` 审计行（create/destroy/renew/sweep + thread_id/sandbox_id） | 复用 audit logger（JSONL，CompositeBackend 基建） |
| 工具调用审计 | 已覆盖（ToolAuditMiddleware：run_code_in_sandbox 记 code_len）——新增工具同步加入 | 深化方案 §3.4 |
| egress 收紧（可选） | `patch_egress_rules` 默认放行、按需白名单（SDK :320-348）；搜索类工具需要出网 → 默认不收紧 | P2 按需 |
| 运维观测 | `get_metrics / get_diagnostic_logs` 接入日志（P2） | 排查用 |

### 3.5 配置与官方演进

**config.py 新增字段**（全默认值，不破坏现状）：

```python
# ── 沙箱（2026-08-05 能力计划）──
sandbox_image: str = "python:3.11"      # 池化默认镜像（现有 DEFAULT_IMAGE 迁移）
sandbox_timeout: int = 1800             # TTL 秒（现 DEFAULT_TIMEOUT=30min 迁移）
sandbox_pool_enabled: bool = True       # 会话级池化总开关（False = 现 run_code 一次性语义）
sandbox_idle_ttl: int = 900             # 空闲回收阈值（15min）
sandbox_pool_max: int = 4               # 并发沙箱上限（超限排队/复用最闲，单机资源约束）
sandbox_output_limit: int = 8192        # 单次命令输出截断字节
```

**官方演进预留（P2，本计划只给设计不做）**：`OpenSandboxBackend(SandboxBackendProtocol)`
——把池化沙箱包装成 deepagents backend，让原生 `execute` 工具与文件工具直操作沙箱内 FS。
**代价标注**：① execute 无权限检查（官方限制，filesystem.py:1436 核实）→ 需
PolicyBackend 包装兜底；② 文件虚拟路径语义变化（沙箱 FS 即 backend）→ 与 §3.3
双层模型互斥，二选一演进；③ 沙箱快照 `create_snapshot` 可做"依赖预装模板"（pip 装好
pandas 等快照化，起沙箱秒级）——P2 时与池化结合。**当前阶段 §3.3 双层模型更贴合
"存储持久 + 执行隔离"的项目现状，不急于切官方模型。**

## 6. 总：优先级与风险自检

### 6.1 优先级

| 优先级 | 项 | 内容 | 依赖 |
|--------|----|------|------|
| **P0** | 会话级沙箱池 | pool.py + adapter 改造（run_code 走池）+ config 字段 + 开关 + 审计 | 无（独立模块） |
| **P0** | 生命周期审计 | layer=sandbox 审计行（create/destroy/renew/sweep） | audit logger 已就绪（CompositeBackend 深化） |
| **P1** | 执行增强 | run_script / run_command 增强（timeout/envs）/ 输出上限 | P0 池 |
| **P1** | 文件同步 | upload/download 工具 + registry 注册 + ToolAudit 名单扩充 | P0 池 |
| **P1** | 会话删除联动 | DELETE /v1/sessions → pool.destroy(thread_id) | sessions.py 联动点已存在 |
| **P2** | 快照模板 | create_snapshot 依赖预装（pip 库快照化，起沙箱提速） | 池化稳定后 |
| **P2** | 官方演进 | OpenSandboxBackend(SandboxBackendProtocol) 设计落地 | 双层模型验证后决策 |

### 6.2 风险自检清单

- [ ] **池化语义变化**：run_code 从"一次性"变"复用"——同一沙箱残留上次文件/环境
      → 工具级执行前清工作目录（约定 /workspace 每次执行前重置或版本化子目录）
- [ ] **续期失败**：renew 异常 → 按沙箱已过期处理（销毁重建），不静默复用死沙箱
- [ ] **并发上限**：sandbox_pool_max 用尽 → 明确策略（复用最闲 / 排队 / 错误提示），不无限创建
- [ ] **密钥纪律**：env/envs 白名单显式注入；审计日志禁密钥字段（00-security 硬约束）
- [ ] **与 backend 虚拟路径混淆**：sandbox 路径独立命名空间（sandbox:/ 前缀），防越权误判
- [ ] **官方演进取舍**：P2 OpenSandboxBackend 与 §3.3 双层模型互斥——切换需评审，
      不默认可行（execute 无权限检查是官方限制，必须 PolicyBackend 兜底后才可评估）
- [ ] **测试不连 docker**：全 mock SDK（延续 test_adapter 模式）；真实联调用
      scripts/dev.sh + 手工冒烟
- [ ] **先红后绿**：每个 P 级先用例后实现；提交前 pytest 全绿；改代码开 worktree

### 6.3 后续

1. P0 落地后浏览器实测：多轮对话连续写代码 → 沙箱复用耗时对比（30s → 秒级）
2. 沙箱内依赖预装：pip 缓存层 / 快照模板（P2）
3. OpenSandboxBackend 官方演进评审点：权限兜底方案 + 文件语义切换
