## 1. 总：背景、目标与范围

### 1.1 背景

项目沙箱层（OpenSandbox 阿里开源，SDK 0.1.15）当前是**初始薄壳**：`src/sandbox/adapter.py`
一个适配器 5 个方法 + `run_code_in_sandbox` 一个工具函数，每次调用"创建沙箱 → 写代码 →
执行 → 销毁"，30 秒就绪等待 + 首次拉镜像的开销每次全付。SDK 0.1.15 已提供
`renew / pause / resume / connect / create_snapshot / 持久 bash 会话 / 后台任务 / egress 策略`
等能力，项目**零使用**。

deepagents 官方模型（docs/langchain.com/oss/python/deepagents/sandboxes）：
**沙盒 = backend**——SandboxBackendProtocol 在文件操作之上增加 `execute` 工具
（任意 shell 命令），agent 获得"全部文件工具 + execute + 隔离边界"；沙盒生命周期
由调用方用 provider SDK 管理（try/finally delete_sandbox）。官方 provider：
LangSmith / Daytona / E2B / Runloop / Vercel；本地参考实现 `LocalShellBackend`
（FilesystemBackend + SandboxBackendProtocol）与 `BaseSandbox`（大输出 offload 到文件）。

**定位决策**（2026-08-05）：OpenSandbox 自建部署（本地 docker / 云端自管），
**对标官方"外部管理生命周期"模式**——沙箱由本项目后端管理，不是官方托管 provider。

### 1.2 目标

1. **会话级沙箱复用**（P0）：每会话（thread_id）一个沙箱实例，TTL 续期 + 空闲回收——
   消除"每次工具调用 create+destroy + 30s ready"的重复开销
2. **执行能力分层**（P1）：一次性 run_code 保留；增强多文件脚本、命令超时、
   持久 bash 会话、后台任务（SDK 已支持，接线即用）
3. **文件同步边界**（P1）：backend 持久文件（workspace）↔ 沙箱临时文件的
   上传/取回约定，明确"持久在 backend、执行在沙箱"的双层模型
4. **安全与审计闭环**（P0/P1）：容器隔离边界确认、密钥不注入、生命周期审计
   （工具调用审计已由 ToolAuditMiddleware 覆盖）、egress 策略可选收紧、资源限额
5. **官方抽象演进预留**（P2）：`OpenSandboxBackend(SandboxBackendProtocol)`
   让 deepagents 原生 execute 工具可用——标注代价与取舍，不急于落地

### 1.3 范围

| 在本计划内 | 不在本计划内 |
|-----------|-------------|
| 会话级沙箱池 + TTL 续期 + 空闲回收 | 多机/多进程沙箱池共享（redis pool_store，SDK 有但单机不需要） |
| 执行增强（多文件/超时/会话/后台） | 沙箱快照模板工程化（P2 预留 create_snapshot 接线） |
| workspace ↔ 沙箱文件同步约定 | OpenSandboxBackend 实现（P2，本计划只给设计） |
| 生命周期审计 + 密钥纪律 + 资源限额 | 沙箱内 git/代码仓库场景（后续按需） |
| 兼容：现有 run_code_in_sandbox 签名不变 | Docker-in-Docker / 构建流水线 |

### 2.4 环境检测与资源预算（2026-08-05 实测）

**实测数据**（本机）：

| 资源 | 本地系统 | **Docker 引擎（沙箱容器实际运行处）** | 云端目标 |
|------|---------|----------------------------------|---------|
| CPU | 6 物理 / 12 逻辑 | **12 vCPU**（Docker Desktop 分配） | 2 核 |
| 内存 | 31.7 GB | **15.5 GiB** | **4 GB** |

**关键结论**：沙箱容器跑在 docker 引擎里（docker runtime 建容器），
**资源预算以 docker 引擎为准**（15.5GiB/12C），不是本地物理内存；
云端 4G 是硬约束。

**资源消耗模型**（回答"频繁创建 vs 续期"）：

```
总消耗 ≈ 并存沙箱数 × 单沙箱限额 + 服务端开销（opensandbox server + redis）
```

- **一次性模式（现状）**：create/destroy 本身开销小（容器启动秒级、镜像本地缓存后
  无拉取），但创建瞬间存在**新旧沙箱短时并存**（旧未销毁+新创建）→ CPU 尖峰；
  管理面请求（create/ready 轮询）频繁
- **续期模式（本计划）**：沙箱长期存活 → 资源被**持续钉住**，无创建尖峰但
  **占用是线性累积的**——这正是必须配「池上限 + 单沙箱限额」的原因：
  续期不增资源，但会让资源永不释放，**无限会话 = 无限占资源**

**单沙箱限额（配置化，不写死）**：
- SDK `create(resource=...)` 默认 **1 CPU / 2Gi**（sync/sandbox.py:554）——⚠️ **云端 4G
  下 2 个沙箱就吃满**，必须显式配置更小限额（§3.5 sandbox_cpu / sandbox_memory）
- 推荐（按场景，见 §3.1 决策表）：本地 1 CPU / 1Gi；云端 0.5 CPU / 512Mi

**预算分配建议**：

| 场景 | 引擎资源 | 单沙箱限额 | 池上限建议 | 余量 |
|------|---------|-----------|-----------|------|
| 本地开发 | 15.5GiB / 12C | 1 CPU / 1Gi | **6** | 余 ~9GiB（server/redis/前端/系统余量） |
| 云端 | 4GB / 2C | 0.5 CPU / 512Mi | **4** | 余 ~2GB（server+redis 预留） |

> 本地"基本不打游戏但会开发"（用户原话）：6 个沙箱足够覆盖
> 同时 4-5 个对话 + 1 个空闲余量；12 vCPU 完全扛得住。
> 云端 4 个 = 4 个并发对话上限，超限走 §3.1 超限策略（友好降级）。

## 3. 分·设计

### 3.1 会话级沙箱生命周期管理（P0，核心）

**定位**：项目后端扮演官方文档中"provider SDK"的角色——管理沙箱创建、复用、续期、回收。

**会话级沙箱池**（`src/sandbox/pool.py` 新建，手写核心逻辑）：

```
SandboxPool（进程内单例，thread_id 维度）
  ├─ get_sandbox(thread_id) → SandboxSync   # 懒创建：无则 create（TTL=sandbox_timeout）
  │                                        # 有则 renew() 续期 + 返回（同实例连续 run 保留状态）
  ├─ release(thread_id)                    # 归还（无需操作，池不销毁；仅记录）
  ├─ destroy(thread_id)                    # 主动销毁（会话删除 / 显式清理）
  └─ sweep()                               # 空闲回收：超过空闲阈值的沙箱 destroy
      （守护任务或调用时惰性检查，二选一，见 §4 兼容）
```

**关键决策**：

| 项 | 方案 | 依据 |
|----|------|------|
| 池维度 | thread_id（会话级）——主 agent + 子代理共用该会话沙箱 | 与 backend 会话隔离同维度；多会话沙箱天然隔离 |
| 复用语义 | 同一 thread 的连续工具调用**共享沙箱**（文件/环境保留） | SDK 同实例语义；消除重复 create+ready |
| TTL 续期 | 每次取用时 `renew(sandbox_timeout)`——沙箱在活跃会话中永不过期 | SDK `renew` 接口（sync/sandbox.py:284） |
| 空闲回收 | `sweep()`：`sandbox_idle_ttl`（如 15min）无访问 → destroy | 防资源泄漏；服务端 TTL 只是兜底 |
| 创建失败 | 降级为错误字符串返回（现有工具语义），不中断 run | 与 run_code_in_sandbox 现状一致 |
| 并发 | 单机单用户，锁内懒创建（threading.Lock，同 _agents 模式） | 无跨进程需求（redis pool_store 留演进） |
| 内存模式 | `MEMORY_WORKSPACE=True` 时沙箱池仍可用（沙箱与 backend 独立） | 沙箱是执行层，与存储模式正交 |
| **工具取 thread_id** | 工具函数声明 `config: RunnableConfig` 参数——框架自动注入执行 config，从 `config["configurable"]["thread_id"]` 取会话 ID（stream_agent_tokens 已封装传入） | langchain 工具 config 注入机制；工具函数本身无 runtime 上下文（§7.4 代码） |
| **隔离模型澄清** | 是**会话级**（thread_id 维度）隔离，不是线程——一个对话一个沙箱；多对话 = 多沙箱并存 = 资源线性增长 | 与 backend 会话隔离同语义；并发对话数直接映射沙箱数 |
| **资源消耗模型** | 总消耗 ≈ 并存沙箱数 × 单沙箱限额 + server/redis 开销；续期钉住资源，无限会话 = 无限占用 | §2.4 实测：本地 docker 引擎 15.5GiB/12C；云端 4G 硬约束 |
| **单沙箱资源限额** | `create(resource={"cpu": sandbox_cpu, "memory": sandbox_memory})`——**配置化**（§3.5），本地 1C/1Gi、云端 0.5C/512Mi | SDK 默认 2Gi 太大（云端 2 沙箱吃满）；容器级限额防资源耗尽 |
| **池上限与超限策略** | `sandbox_pool_max` 全局并发沙箱上限（本地 6 / 云端 4）；**超限 → 工具返回"沙箱资源已满，请稍后重试或换个方式"**（不排队——排队会让 agent 卡死；错误字符串不中断 run，agent 可改方案） | 多对话并发是云服务扛不住的核心风险，必须显式封顶 |

**生命周期审计**（P1，与 CompositeBackend 审计同通道）：
`layer=sandbox` 审计行——create/destroy/renew/sweep 各事件带 thread_id/sandbox_id/原因。

### 3.3 文件同步边界（P1）

**双层模型（明确边界）**：

```
backend（持久层，CompositeBackend 会话隔离）        sandbox（执行层，容器内临时）
  workspace/{thread_id}/  ←──────────────→   /workspace/（沙箱内工作目录约定）
  /memories/ /skills/ /exports/（只读/共享）     ↑ 上传：backend 读 → sandbox 写
                                               ↓ 取回：sandbox 读 → backend 写
```

- **方向语义**：上传 = 把 workspace 文件（或 agent 代码）送入沙箱执行；
  取回 = 把沙箱运行产物（报表/结果文件）落回 exports/ 或 workspace
- **约定**：沙箱内统一 `/workspace/` 目录（create 后初始化）；虚拟路径不混用——
  sandbox 工具的路径参数**独立命名空间**（如 `sandbox:/workspace/x.py`），
  不与 backend 虚拟路径（`/workspace/`）混淆（防路径越权误判）
- **实现**：adapter 增 `upload_file(sandbox, local_virtual_path, content)` /

- [ ] **池化语义变化**：run_code 从"一次性"变"复用"——同一沙箱残留上次文件/环境

- [ ] **与 backend 虚拟路径混淆**：sandbox 路径独立命名空间（sandbox:/ 前缀），防越权误判

### 7.2 `src/sandbox/pool.py`（新建，核心手写逻辑）

```python
"""会话级沙箱池（方案 §3.1 / §7.2）：thread_id 维度复用 + TTL 续期 + 空闲回收。"""

from __future__ import annotations

import json
import logging
import threading
import time
from dataclasses import dataclass
from datetime import datetime, timedelta

from opensandbox.sync.sandbox import SandboxSync

from src.core.config import settings
from src.sandbox.adapter import OpenSandboxAdapter

logger = logging.getLogger(__name__)
audit_logger = logging.getLogger("audit")


class SandboxFullError(RuntimeError):
    """沙箱池达到并发上限（sandbox_pool_max）——工具层捕获转友好错误提示。"""


@dataclass
class _Entry:
    """池条目：沙箱实例 + 最近取用时间（空闲回收判据）。"""

    sandbox: SandboxSync
    last_used: float


class SandboxPool:
    """进程内会话级沙箱池（thread_id 维度，线程安全）。

    与 backend 会话隔离同维度：每会话一个沙箱，连续工具调用共享
    （同实例连续 run() 保留文件与环境）；取用即 renew 续期（活跃会话
    永不过期）；空闲超阈值 sweep 销毁（防资源泄漏，服务端 TTL 仅兜底）。

    Attributes:
        _adapter: OpenSandboxAdapter（create/destroy 委托）
        _entries: thread_id → _Entry
        _lock: 懒创建/回收锁（同 main_agent._agents 双重检查模式）
    """

    def __init__(self, adapter: OpenSandboxAdapter | None = None) -> None:
        self._adapter = adapter or OpenSandboxAdapter()
        self._entries: dict[str, _Entry] = {}
        self._lock = threading.Lock()

    def get_sandbox(self, thread_id: str) -> SandboxSync:
        """取会话沙箱：命中续期复用；未命中懒创建（锁内双检 + 惰性 sweep）。

        Args:
            thread_id: 会话 ID（== session_id）

        Returns:
            就绪的 SandboxSync 实例

        Raises:
            SandboxException: 创建失败（由工具层降级为错误字符串，不中断 run）
        """
        if not settings.sandbox_pool_enabled:
            return self._adapter.create_sandbox()  # 兼容：旧一次性语义
        with self._lock:
            self._sweep_locked()
            entry = self._entries.get(thread_id)
            if entry is not None:
                self._renew(entry, thread_id)
                return entry.sandbox
            if len(self._entries) >= settings.sandbox_pool_max:
                # 池上限（本地 6 / 云端 4，配置化）：不排队不无限创建——
                # 直接拒绝，工具层转"沙箱资源已满"友好错误，agent 可换方案
                self._audit("full", thread_id, "")
                raise SandboxFullError(
                    f"沙箱资源已满（上限 {settings.sandbox_pool_max} 个并发会话），"
                    "请稍后重试，或换一种不需要沙箱的方式。"
                )
            sandbox = self._adapter.create_sandbox()
            self._entries[thread_id] = _Entry(sandbox, time.time())
            self._audit("create", thread_id, self._sandbox_id(sandbox))
            return sandbox

    def destroy(self, thread_id: str) -> None:
        """主动销毁会话沙箱（会话删除 / 显式清理；幂等，不存在静默通过）。"""
        with self._lock:
            entry = self._entries.pop(thread_id, None)
        if entry is not None:
            self._safe_destroy(entry, thread_id, "session-delete")

    def sweep(self) -> int:
        """空闲回收：超过 sandbox_idle_ttl 未取用的沙箱销毁，返回销毁数。"""
        with self._lock:
            return self._sweep_locked()

    # ── 内部：回收 / 续期 / 审计 ──

    def _sweep_locked(self) -> int:
        cutoff = time.time() - settings.sandbox_idle_ttl
        removed = 0
        for tid, entry in list(self._entries.items()):
            if entry.last_used < cutoff:
                self._entries.pop(tid, None)
                self._safe_destroy(entry, tid, "idle-sweep")
                removed += 1
        return removed

    def _renew(self, entry: _Entry, thread_id: str) -> None:
        """续期 + 刷新最近使用；renew 失败按过期销毁重建（不静默复用死沙箱）。"""
        try:
            entry.sandbox.renew(timedelta(seconds=settings.sandbox_timeout))
            entry.last_used = time.time()
            self._audit("renew", thread_id, self._sandbox_id(entry.sandbox))
        except Exception:  # noqa: BLE001 —— 续期失败 = 沙箱可能已过期，销毁让下次重建
            logger.warning("沙箱续期失败（销毁重建）：thread=%s", thread_id)
            self._entries.pop(thread_id, None)
            self._safe_destroy(entry, thread_id, "renew-failed")

    def _safe_destroy(self, entry: _Entry, thread_id: str, reason: str) -> None:
        try:
            self._adapter.destroy(entry.sandbox)
        except Exception:  # noqa: BLE001 —— 销毁失败不阻塞调用方
            logger.warning("沙箱销毁失败：thread=%s reason=%s", thread_id, reason)
        self._audit("destroy", thread_id, self._sandbox_id(entry.sandbox))

    def _audit(self, event: str, thread_id: str, sandbox_id: str) -> None:
        """生命周期审计（与 policy_backend 同构的扁平 JSON 行，layer=sandbox）。"""
        record = {
            "ts": datetime.now().astimezone().isoformat(timespec="seconds"),
            "thread_id": thread_id,
            "layer": "sandbox",
            "event": event,
            "sandbox_id": sandbox_id,
        }
        audit_logger.info(json.dumps(record, ensure_ascii=False))

    @staticmethod
    def _sandbox_id(sandbox: SandboxSync) -> str:
        return str(getattr(sandbox, "id", ""))  # 防御：实例属性随 SDK 版本
```

### 7.3 `src/sandbox/adapter.py` 增量（多文件 / 命令增强 / 文件同步 / 资源限额）

```python
"""（adapter.py 新增 import 与方法；原 5 方法与常量不变）"""

from opensandbox.models.execd import RunCommandOpts

    def create_sandbox(
        self,
        image: str = DEFAULT_IMAGE,
        *,
        timeout: timedelta = DEFAULT_TIMEOUT,
        resource: dict[str, str] | None = None,
    ) -> SandboxSync:
        """创建沙箱（增强：单沙箱资源限额配置化）。

        原签名 create_sandbox(image, timeout) 完全兼容——resource 为新增可选参数。
        限额来自 settings（sandbox_cpu / sandbox_memory，§3.5），
        显式传参优先；None → SDK 默认（⚠️ 1cpu/2Gi，云端必须显式配置）。
        """
        if resource is None and settings.sandbox_cpu and settings.sandbox_memory:
            resource = {"cpu": settings.sandbox_cpu, "memory": settings.sandbox_memory}
        return SandboxSync.create(
            image,
            timeout=timeout,
            resource=resource,
            connection_config=self._connection_config(),
        )

    def run_script(self, sandbox: SandboxSync, files: dict[str, str], entry: str) -> str:
        """多文件执行（§3.2）：逐文件写入 → 运行入口文件。

        Args:
            sandbox: 池化后的沙箱实例
            files: {沙箱内路径: 内容}（如 {"main.py": "...", "utils.py": "..."}）
            entry: 入口文件（如 "main.py"）

        Returns:
            run_command 的 stdout 文本
        """
        for path, content in files.items():
            self.write_file(sandbox, path, content)
        return self.run_command(sandbox, f"python {entry}")

    def run_command(
        self,
        sandbox: SandboxSync,
        command: str,
        *,
        timeout: timedelta | None = None,
        envs: dict[str, str] | None = None,
    ) -> str:
        """命令执行（§3.2 增强）：命令级超时/环境变量经 RunCommandOpts 透传。

        原签名 run_command(sandbox, command) 完全兼容——timeout/envs 为新增
        可选参数（默认 None = 服务端不强制超时，同现状）。
        """
        opts = None
        if timeout is not None or envs is not None:
            opts = RunCommandOpts(timeout=timeout, envs=envs)
        execution = sandbox.commands.run(command, opts=opts)
        stdout = "\n".join(m.text for m in execution.logs.stdout if m.text)
        if execution.exit_code not in (None, 0):
            stderr = "\n".join(m.text for m in execution.logs.stderr if m.text)
            return f"{stdout}\n[exit={execution.exit_code}]\n{stderr}".strip()
        return stdout

    def upload_file(self, sandbox: SandboxSync, sandbox_path: str, content: str) -> None:
        """上传（§3.3）：backend 读到的内容 → 沙箱内路径（sandbox:/workspace/ 约定）。"""
        sandbox.files.write_file(sandbox_path, content)

    def download_file(self, sandbox: SandboxSync, sandbox_path: str) -> str:
        """取回（§3.3）：沙箱内文件 → 文本内容（落回 exports/ 或 workspace）。"""
        return sandbox.files.read_file(sandbox_path)
```

```python
"""（sandbox_tool.py 增量：池化版工具；run_code_in_sandbox 签名与降级语义不变）"""

from langchain_core.runnables import RunnableConfig

from src.sandbox.pool import SandboxFullError, SandboxPool

# 会话级沙箱池（进程内单例，惰性：import 不连沙箱）
sandbox_pool = SandboxPool()

# 危险命令前缀黑名单（§3.4 命令约束）：防 agent 误操作/恶意指令
_BLOCKED_COMMAND_PREFIXES = (
    "rm -rf /", "mkfs", "shutdown", "reboot", "halt",
    "dd if=/dev/zero", "chmod -R 777 /", ":(){ :|:& };:",
)


def _validate_command(command: str) -> str | None:
    """命令校验（§3.4）：危险前缀拒绝，返回错误提示；None = 通过。

    Args:
        command: 待执行 shell 命令

    Returns:
        拒绝原因（字符串）或 None（放行）
    """
    stripped = command.strip()
    for prefix in ("sudo ", "env "):
        if stripped.startswith(prefix):
            stripped = stripped[len(prefix):].lstrip()
    for bad in _BLOCKED_COMMAND_PREFIXES:
        if stripped.startswith(bad):
            return f"命令被沙箱安全策略拒绝（危险操作：{bad}…），请换一种方式。"
    return None


def _thread_id_from(config: RunnableConfig | None) -> str:
    """工具执行 config → 会话 ID。

    langchain 工具函数声明 RunnableConfig 参数即由框架自动注入执行 config，
    thread_id 由 stream_agent_tokens 封装传入（config["configurable"]）；
    config 缺失（单元测试/无会话场景）回落 "default" 池。
    """
    if config:
        return str(config.get("configurable", {}).get("thread_id") or "default")
    return "default"


def run_code_in_sandbox(
    code: str, filename: str = "script.py", config: RunnableConfig | None = None
) -> str:
    """在会话级沙箱中执行代码（池化版：复用 + 续期；签名与降级语义不变）。"""
    if not settings.sandbox_url:
        return "沙箱不可用：SANDBOX_URL 未配置（.env.dev），请直接基于已有知识回答。"
    try:
        sandbox = sandbox_pool.get_sandbox(_thread_id_from(config))
        return sandbox_adapter.run_script(sandbox, {filename: code}, filename)
    except SandboxFullError as e:   # 池上限：友好提示，agent 可换方案
        return str(e)
    except Exception as e:  # noqa: BLE001 —— 工具失败降级为错误信息，不冒泡中断 run
        return (
            f"沙箱执行失败（{type(e).__name__}）：{e}。"
            "请勿重试沙箱，直接基于已有知识回答。"
        )


def run_command_in_sandbox(
    command: str, *, timeout: int = 60, config: RunnableConfig | None = None
) -> str:
    """在会话级沙箱中执行 shell 命令（P1：pip install / 文件操作等）。

    Args:
        command: shell 命令（如 "pip install pandas"）
        timeout: 命令超时秒数（默认 60，防长命令挂起）
    """
    if not settings.sandbox_url:
        return "沙箱不可用：SANDBOX_URL 未配置（.env.dev），请直接基于已有知识回答。"
    blocked = _validate_command(command)   # §3.4 命令约束：危险前缀先拒
    if blocked:
        return blocked
    try:
        sandbox = sandbox_pool.get_sandbox(_thread_id_from(config))
        return sandbox_adapter.run_command(
            sandbox, command, timeout=timedelta(seconds=timeout)
        )
    except SandboxFullError as e:          # 池上限：友好提示，agent 可换方案
        return str(e)
    except Exception as e:  # noqa: BLE001
        return f"沙箱命令执行失败（{type(e).__name__}）：{e}。请勿重试沙箱。"
```
