## 2. 安全机制评审核对（10 条） 🔴 v1

### 2.1 重大问题（2 条，必须修）

**大 1. `validate_workspace_path` 没用 session_id，跨会话穿越没防住 🔴**

- **评审确认**：函数体完全没用 `session_id`（只查空/协议/绝对/`..`），`FileRef` 还传 `"*"`——`other_session/secret.txt` 返回 True（越权）
- **建议（推荐前者）**：函数内部拼 `workspace/{session_id}/` 前缀，`resolve()` 检查最终路径在该目录下；或明确职责"只做格式校验，会话隔离由 CompositeBackend 保证"——**推荐完整校验**，调用方不关心
- 示例（评审给）：`base = Path("workspace")/session_id; full = (base/path).resolve(); return str(full).startswith(str(base.resolve()))`

**大 2. 与 CompositeBackend 权限体系关系未说清 🔴**

- **评审确认**：CompositeBackend 已管虚拟路径（`/memories/` `/skills/static/` `/workspace/{thread_id}` + PolicyBackend 拦截 + FilesystemPermission），设计未提——落地会冲突/重复建设
- **建议职责划分**：
  - **CompositeBackend**：管 agent **实际读写文件**的权限（路径白名单、deny/interrupt、会话隔离）
  - **本设计（安全机制）**：管 agent **返回给用户的文件地址格式校验**（防越权路径回显）+ 工具输入注入校验
  - 一句话：**CompositeBackend 管"能不能读写"，本设计管"返回给用户的地址合不合法"**

### 2.2 中等问题（3 条，建议修）

| # | 评审点 | 问题确认 | 建议 |
|---|--------|----------|------|
| 3 | FileRef 相对路径基准不明确 | ⚠️ `path` 相对 workspace/ 还是 workspace/{session_id}/？前端怎么拼 URL 未定义 | 明确"path 相对 workspace/{session_id}/"，或完整虚拟路径由后端解析——选一写清 |
| 4 | write_file 工具是否存在 | ⚠️ **不存在**（探索确认：tools/ 只有 sandbox upload/download）| 明确用现有 upload/download 写入；若需 write_file 则定义工具 + 权限配置——不凭空出现 |
| 5 | security_blocked 调用时机不明确 | ⚠️ 实现是工具内散落调用 | 推荐**统一校验入口**（permissions 校验函数）或 `@security_audit` 装饰器，不散落 |
