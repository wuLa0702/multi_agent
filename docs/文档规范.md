# 文档规范（docs 通用规则）

> 本文件是 docs/ 下**所有文档的格式规则唯一载体**——后续要改规则只改这里。
> 适用范围：`docs/` 目录下所有 Markdown 文档（含 `learnings/` 子目录）。
> 不适用：`docs/图片和附件/`（图片/OCR 原始附件，不参与格式约束）、仓库根目录的 CLAUDE.md / AGENTS.md / README.md（工程约定文件，保持各自格式）。

---

## 1. 文件名规则

1. **docs 下所有文档一律中文名称**（方便一目了然）：
   - ✅ `docs/方案-后端基础架构-v1.md`
   - ❌ `docs/backend-plan-v1.md`
2. 附件（图片/OCR）保留原名，不做中文约束（改名会破坏文档引用）。
3. 版本后缀（`-v1` / `-v2`）是文件名的一部分，保留。

## 2. 文档头模板（每个文档最顶部，标题之下）

所有文档必须包含以下四要素，顺序固定：

```markdown
# 文档标题

> 📋 **规范**：遵循 `docs/文档规范.md`
> 📌 **更新时间**：2026-08-02
> 🔄 **最近三次改动**：
> | 版本 | 日期 | 改动 |
> |------|------|------|
> | v3 | 2026-08-02 | 本次改动摘要 |
> | v2 | 2026-08-02 | 上次改动摘要 |
> | v1 | 2026-08-02 | 更早改动摘要 |

## 目录

- §1 …
- §2 …

---

正文开始
```

**要素说明**：
| 要素 | 要求 |
|------|------|
| 📋 规范 | 固定引用 `docs/文档规范.md`，不重复抄规则 |
| 📌 更新时间 | 每次改动都更新为当天日期 |
| 🔄 最近三次改动 | 只保留最近 **3 条**；更早的记录移到文档内「版本表」或删除（从第 4 次改动起，旧记录按需归档到正文版本表） |
| 目录 | 文档内小节导航（标题+链接），章节多时用表格 |

## 3. 版本记录规则

- 文档内建议保留完整「版本表」（v1 → vN 全部历史），放在正文开头（目录之后）。
- 版本号与文件名 `-vN` 保持一致；文档头只显示最近三次，完整历史在版本表。
- 每次修改：①文档头更新时间更新 ②最近三次改动表更新 ③版本表追加 ④文件名版本号升级（大改）或保持不变（小修）。

## 4. 内容规则

1. 优先级/状态标注统一符号：✅ 已完成 / ⏳ 待做 / ⚠️ 存疑待核实 / 🔧 已修正 / 📊 经验估算 / 📌 经验来源
2. 中文为主，术语可保留英文原文（如 SSE / Redis）。
3. 更新维护时：**先改文档头**，再改正文，最后更新版本表。

## 5. 每次更新维护的固定动作（Checklist）

- [ ] 更新时间 → 今天
- [ ] 最近三次改动表 → 插入本次，挤掉最旧一条
- [ ] 版本表 → 追加本次记录
- [ ] 文件名版本号 → 大改升级（-vN），小修不动
- [ ] 目录 → 章节有增删时同步
