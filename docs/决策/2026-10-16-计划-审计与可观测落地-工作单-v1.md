## 1. 怎么用这份工作单（崩溃恢复机制） 🔴 v1

**核心纪律（三条，缺一不可）**：

```
① 一个子任务 = 一个提交（可独立回滚）
② 每完成一个：更新 §4 的「进度表」→ 再提交 → 才动下一个
③ 进度表里写清：状态（✅/🔄/⬜）+ 提交号 + 一句话结果
```

**为什么这样设计**：会话崩溃（上下文丢失 / 进程被杀 / 换人接手）时，
唯一可靠的"进度真相源"是 **git 提交 + 本工作单的进度表**——不是聊天记录。

**判定标准**：任意时刻崩掉后，一个新会话只要读：
1. 本工作单 §4 进度表（最后 ✅ 的是哪个）
2. `git log --oneline`（提交是否与进度表一致）

→ **就能从下一个 ⬜ 继续，不丢任何已完成的工作。**

> ⚠️ 若发现**进度表与 git log 不一致** → 以 **git log 为准**（代码是真相，表可能忘了更新），
> 并把表补正后再继续。

## 4. 逐批次详细步骤与验收 🔴 v1

> ⚠️ **本节的表是"详细步骤/验收"表，不含进度**——**进度一律只记在 §3 总表**
> （否则两处进度必然漂移，崩溃恢复时不知道看哪个）。

### 批次 1｜事件模型 + emit 收口

> **目标**：所有审计写入必经 `core/audit.py::emit()`；字段统一；**不接 Redis/PG**。
> ⚠️ 本批次**不是"零行为变更"**——审计行 schema 会变（措辞见设计稿 §9）。

#### T1.1 `core/audit.py`（地基）

**产出**：
```python
_TRACE_ID: ContextVar[str]      # 供批次 2 的中间件设置
_SEQ: ContextVar[itertools.count | None]   # 可变对象（防重复，见设计稿 §3.1）
_CORE_FIELDS = frozenset({"ts","trace_id","seq","layer","event","status","session_id"})

def emit(layer: str, event: str, *, status: str | None = None, **fields) -> None
def bind_trace(trace_id: str) -> None      # 供批次 2 调用
def current_trace_id() -> str              # 取当前值（可能为空占位）
```

**验收**：
- [ ] `emit()` 产出的行含全部核心字段（`trace_id` 本批次为**空串占位**，刻意）
- [ ] `fields` 含核心字段保留名 → **抛 `ValueError`**（防覆盖）
- [ ] 任何异常都**不冒泡**（审计是旁路）
- [ ] 单测：正常 / 保留名冲突 / 底账写失败降级

#### T1.2–T1.6 逐写入点改造

**每处的固定动作**（4 步，逐处提交）：
1. 原 `audit_logger.info(json.dumps(record, ...))` → `emit(layer=..., event=..., status=..., **fields)`
2. `ts` 精度 → **毫秒**（`timespec="milliseconds"`）
3. `thread_id` → `session_id`（**同一字段改名**，见设计稿 §3.1 依据）
4. 原 `decision`/`event`/`phase` → **`event` 点分**（命名见设计稿 §3.3）

## 5. 红线（不许做什么） 🔴 v1

| 红线 | 原因 |
|---|---|
| ❌ 审计不得参与决策（拦截/放行） | 审计是旁路；参与决策会让"账本"变"开关"，故障面翻倍 |
| ❌ 不得在 `core/audit.py` **之外**直调 `audit_logger.info` | 方言会重新长出来（T1.8 会自动抓） |
| ❌ 不得记录内容正文（LLM prompt/response、文件内容、记忆 fact） | 设计稿 §3.5 边界；T1.6 已有一处历史遗留 |
| ❌ 不得擅自合并回 develop / push 远程 | 需 co-creator 明确指令 |
| ❌ 不得为省事跳过"每子任务一提交" | 崩溃后无法定位进度（本工作单的全部意义） |
| ❌ 不引入新可观测组件（Langfuse 等） | 三方选型结论：已用满（决策记录 §4.3） |
