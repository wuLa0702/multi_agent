## 1. 背景与目标 🔴 v1

基于 2026-08-11 架构拍板（v2.6），本计划覆盖后端第一阶段基础架构搭建：

**核心目标**：
- 启动流程（config → DB → 注册表 → 启动）
- 数据库初始化（SQLite + seed 数据）
- LLM 适配层（统一出口 + model_registry）

**设计决策来源**：
- `docs/架构/多agent项目-架构目录.md` v2.6
- `docs/决策/设计-模型注册与统一出口-v1.md`（已拍板）

**关键设计决策**：
1. **层级违规修正**：model_registry 从 `core/` 移到 `agent/services/`（公共框架层不应反向依赖数据层）
2. **API Key 存储**：业务配置（模型/Key/厂商）全部进 DB，.env 只留进程级基础设施

## 2. 后端目录结构（v2.6 拍板） 🔴 v1

```
backend/
├── src/
│   ├── main.py              # FastAPI 入口
│   ├── core/                # 公共框架层
│   │   ├── config.py        # 进程配置（读 .env，不碰 DB）
│   │   ├── paths.py         # 路径自适应（dev/prod）
│   │   ├── logging.py       # 日志配置
│   │   └── errors.py        # 错误码 + 文案
│   ├── db/                  # 数据层（唯一 SQL 出口）
│   │   ├── engine.py        # SQLite 连接 + WAL
│   │   ├── schema.py        # 表结构定义
│   │   └── seed.py          # 默认数据插入
│   ├── agent/               # Agent 编排层
│   │   ├── main_agent.py    # 唯一入口
│   │   └── services/        # 业务服务
│   │       ├── model_registry.py   # 注册表（从 core/ 移来）
│   │       └── llm/                # LLM 适配层
│   │           ├── adapter.py      # 统一调用出口
│   │           └── retry.py        # 重试装饰器
│   └── schemas/             # 请求/响应模型
└── tests/
```

**层级依赖**：`api → agent → 能力层 → db/`；`core/llm/schemas` 为公共底座

## 3. 实施步骤 🔴 v1

### 3.1 db/engine.py + schema.py + seed.py

**文件**：`backend/src/db/`

**职责**：
- engine.py：SQLite 连接管理（WAL 模式 + 连接池）
- schema.py：providers / models / chats / messages 表定义
- seed.py：首次启动插入默认厂商 + 模型

**依赖**：无外部依赖（最底层）

**测试**：`tests/test_db/`
- 连接成功 / 表创建 / seed 数据插入 / 重复插入幂等

---

### 3.2 core/config.py

**文件**：`backend/src/core/config.py`

**职责**：
- 读 .env（APP_ENV + 进程配置：端口/数据目录/CORS）
- **不读业务配置**（模型/Key/厂商 → DB 唯一真相源）
- Settings 单例 + FastAPI Depends 注入

**依赖**：`core/paths.py`（已有）

**测试**：`tests/test_core/`
- 读取环境变量 / 默认值 / APP_ENV 切换

---

### 3.3 agent/services/model_registry.py

**文件**：`backend/src/agent/services/model_registry.py`

**职责**：
- 从 DB 加载 providers + models → 内存注册表
- `get_model(slug)` 返回 ChatOpenAI 实例
- 启动时 load()、新增/修改后 reload()
- **从 core/model_registry.py 迁移**（解决层级违规）

**依赖**：
- `db/engine.py`（读数据）
- `core/config.py`（读回落值）

**迁移步骤**：
1. 创建新文件 `agent/services/model_registry.py`
2. 复制 `core/model_registry.py` 内容
3. 更新导入路径（`db.model_repository` → `db.engine`）
4. 更新所有引用方（`llm/adapter.py`）
5. 删除旧文件 `core/model_registry.py`
6. 测试全绿

**测试**：`tests/test_agent/`
- 加载注册表 / get_model 返回正确实例 / 未知 slug 抛异常 / reload 生效

---

### 3.4 db/model_repository.py → 合并入 engine.py + seed.py

**文件**：`backend/src/db/`

**职责**：
- model_repository.py 的 CRUD 逻辑合并到 engine.py（查询）和 seed.py（初始化）
- 保持单一职责：engine 管连接，seed 管数据

**依赖**：无新增依赖

---

### 3.5 llm/adapter.py + retry.py

**文件**：`backend/src/agent/services/llm/`

**职责**：
- adapter.py：`chat(model_id, messages)` 统一出口
  - 从 registry 获取模型 → 调用 → 返回响应
  - timeout + max_retries（从 .env 读）
- retry.py：重试装饰器（指数退避）

**依赖**：`agent/services/model_registry.py`

**测试**：`tests/test_llm/`
- 正常调用 / 超时重试 / 模型不存在 / 并发调用

---

### 3.6 启动流程串联

**入口**：`backend/src/main.py`

```python
# 启动流程
1. core/config.py → 读 .env（进程配置）
2. db/engine.py → 连接 SQLite + 创建表
3. db/seed.py → 首次启动插入默认数据
4. agent/services/model_registry.py → load() 从 DB 加载注册表
5. uvicorn 启动
```

**FastAPI lifespan**：
```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    # startup
    await init_db()        # 步骤 2+3
    registry.load()        # 步骤 4
    yield
    # shutdown
    await close_db()
```

**测试**：`tests/test_main/`
- 启动成功 / 注册表加载 / 端口绑定

### 6.2 追问链预演

**Q1：为什么 model_registry 要从 core/ 移到 agent/services/？**
- 层级依赖规则：core 是公共底座，不应反向依赖 db（数据层）
- model_registry 本质是业务能力（模型选择是 Agent 编排的一部分）
- 移到 agent/services/ 后，依赖方向变为 agent → db，符合单向依赖

**Q2：API Key 存 DB 和存 .env 有什么区别？**
- .env：新增厂商需改文件 + 重启服务，运维成本高
- DB：前端操作即可，不碰 .env，不重启
- 安全等级：SQLite 文件和 .env 文件在磁盘上是同一安全等级（本地文件）

**Q3：启动流程的依赖顺序是什么？**
- config（读 .env）→ DB（连接 + 建表）→ seed（默认数据）→ registry（加载注册表）→ uvicorn
- 严格顺序，每步依赖前一步的输出

### 6.3 可量化结果

- **启动时间**：registry 加载 < 100ms（内存注册表）
- **新增厂商**：前端操作即可，零重启
- **测试覆盖**：核心模块 100% 覆盖（db/config/registry/llm/main）
