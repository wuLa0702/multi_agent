## §1 目标与定位

**目标**：两个记忆体系收尾改动——① 把已开发未接线的 **v3 检索**（画像优先 + 时间衰减 + 窗口裁剪）接入主链路；② 把 memory_agent 的 **write_wiki** 从占位落地为真正写 wiki 知识库。

**定位**：
- 改动一是**修复实证 bug**（不是单纯接新功能）——当前"写了没读到"，见 §2.1
- 改动二对齐 `2026-08-12-设计-wiki作为multi-agent数据存储后端-v1.md` **§5 P3**（记忆抽取 → 沉淀 wiki，记忆→知识闭环）
- **明确不做**：tasks.md / tasks_archive.md（项目级全局任务文件记忆，demo 阶段不需要，单列待办）

**一句话**：让记忆体系真正闭环——**读**（v3 检索把画像/事实注入上下文）**→ 存**（memory_agent 抽到 Store）**→ 沉淀**（值得沉淀的结论写 wiki 知识库）。

## §2 现状盘点（两个关键事实）

### 2.1 🔴 实证 bug：记忆"写了没读到"

| 环节 | 现在实际用的 | 写的 namespace | 读的 namespace |
|------|------------|---------------|--------------|
| **写**（memory_agent→`write_store`）| `save_typed_memory`（`store.py:166`）| `("memory","user_profile")` / `("memory","facts")` | — |
| **写**（降级→`_save_memory_in_background`）| `extract_memory_typed`→`save_typed_memory`（`chat.py:513`）| 同上（类型化）| — |
| **读**（注入，`chat.py:267`）| `load_recent_memories` **v1**（`store.py:98`）| — | **只读** `("memory","global")` |

**结论**：writer 写类型化 namespace（user_profile/facts），reader 只读 legacy global——**两个 namespace 不匹配 → 记忆写了但注入读不到**。`save_conversation_memory`（写 global 的 v1 函数）现在**只有测试在用**（`tests/test_agent/test_memory_store.py`），生产写路径已全部类型化。

### 2.2 v3 检索已实现未接线

- `load_recent_memories_v3`（`store.py:198`）**已实现**：读 user_profile + facts + legacy(global) 三 namespace，排序（画像优先→同优先级时间衰减）、窗口裁剪（token 估算 ≤10%×128k），已有测试 `tests/test_agent/test_memory_v3.py`
- **零调用点**（grep 确认）——定义存在，主链路没用

### 2.3 write_wiki 占位 + wiki 写通道已就绪

- `write_wiki`（`agent.py:138`）是 **P2 占位**，返回"未接入"
- `export_to_wiki`（`wiki_export_service.py:23`）**已实现**（REST POST wiki `/v1/pages/{path}`），`POST /v1/export/wiki` 路由已上线（`api/export.py`），`settings.wiki_base_url` 已有（`config.py:151`）
- memory_agent 工具集已含 `write_wiki`（`agent.py:28`）——只差实现

## §4 改动二：落地 write_wiki 🟡 中改动

**write_wiki 从占位接 `export_to_wiki`**（REST 写通道），失败降级返回提示，不阻断 memory_agent 任务（wiki 是旁路能力）。

**触发（prompt 引导，对齐 §4.6「默认只查不写 + 提示词引导」）**：MEMORY_AGENT_PROMPT 加一条沉淀规则——**仅"值得沉淀的知识性结论"（研报/结论/方法）用 write_wiki 写 wiki**；普通记忆只写 Store，不每条写 wiki（防 spam）。

**页面命名**：`结论-{主题}`（对齐 wiki 设计 §4.5 产物规范 `产物-{类型}-{时间}` 风格），待 §9 决策。

**安全边界**：
- 不引入 HITL（memory_agent 是后台并列执行体，无人可交互）
- 缓解：内容限长（≤500 字）＋ 失败降级返回（不抛错）＋ 路径由提示词约束（`结论-` 前缀）
- 如需更严（白名单/审计），后续单独立项

## §5 面试要点（依 `学习/面试/2026-08-10-学习-Agent面试备战指南-v1.md`）

**覆盖面试点（指南 §3.2 五大模块）**：

| 面试点 | 本功能对应技术故事 |
|--------|------------------|
| **容错** | 记忆是旁路能力——v3 检索失败静默降级（`store.py:226` try/except）、wiki 不可达降级返回提示；**不因单点失败断流** |
| **安全机制** | write_wiki 写外部知识库的降级 + 路径约定（`结论-` 前缀）+ 内容限长 |
| **成本控制** | v3 窗口裁剪（注入 token ≤10%）；memory_agent 独立小模型决策（`memory_agent_model`）|

**追问链预演（指南 §3.3 五层追问，自答三层）**：

- **为什么这么做**：实证发现 writer 写 user_profile/facts、reader 只读 global，两个 namespace 不匹配 → 记忆写了但注入读不到。v3 是正确 reader（三 namespace 合并 + 排序 + 裁剪）
- **对比过什么方案**：v1 简单版（只读 global，limit 5）vs v3（类型化 + 画像优先 + 时间衰减 + 窗口裁剪）——v3 与当前 writer 对齐，是必要的修复不是可选项
- **遇到什么坑、怎么量化**：namespace 不匹配是实证 bug（非设计选择），靠 grep 生产写路径 vs 读路径发现；落地后可量化 = **注入命中 user_profile/facts**（v3 排序首位为画像）

## §6 风险与自省

| 风险 | 等级 | 缓解 |
|------|------|------|
| write_wiki 写外部知识库被误用 | 🟡 低 | 仅"结论沉淀"触发 + 内容限长 + 失败降级；更严白名单后续立项 |
| v3 接线破坏现有注入 | 🟡 低 | 默认参数与 v1 一致（limit 5）；测试同步 mock |
| wiki 不可达拖慢 memory_agent | 🟡 低 | write_wiki 内 try/except `WikiExportError` 降级返回；REST 带 timeout |
| 测试 import 遗漏 | 🟢 极低 | 实施前 grep `load_recent_memories` 全量确认 mock 点 |

**自省**：
1. **为什么改动一不是"可选项"**：v1 读 global 但生产写入已无 global——不接 v3，记忆注入实际是空转（读了几乎没东西），这是 bug 不是增强
2. **为什么 write_wiki 走 REST 不走 MCP**：与 wiki 设计 §3 双通道澄清一致——memory_agent 是后端进程内的工具，直接调 `export_to_wiki`（REST 封装）最简；不引入 MCP 依赖
3. **为什么不做 HITL**：后台并列执行体无交互入口；写 wiki 是旁路低危，降级已兜底
4. **为什么暂缓 tasks.md**：demo 阶段无全局任务记忆诉求；其依赖"谁来写任务文件"未定，改动大，单独排队

## §7 完整核心代码

### 7.1 改动一：chat.py v3 接线（改后完整段）

```python
    # 2.6 长期记忆注入（v3 检索）：画像优先 + 时间衰减 + 窗口裁剪（失败静默降级）
    from src.agent.main_agent import get_store
    from src.agent.memory.store import load_recent_memories_v3

    memories = await load_recent_memories_v3(get_store())
    if memories:
        memory_text = "以下是你的长期记忆（供参考，可能与本对话无关）：\n" + "\n".join(memories)
        lc_messages = [SystemMessage(content=memory_text), *lc_messages]
    return lc_messages
```

### 7.2 改动二：write_wiki 落地（agent.py 改后全量）

```python
async def write_wiki(page: str, content: str) -> str:
    """写 Wiki（文档记忆，沉淀知识性结论）——接 wiki_export_service REST 写通道。

    memory_agent 判断"值得沉淀的知识性结论"时调用（prompt 引导）；wiki
    不可达/失败 → 降级返回提示，不阻断任务（wiki 是旁路能力）。

    Args:
        page: wiki 页面路径（如 结论-{主题}）
        content: 页面正文（Markdown，≤500 字）

    Returns:
        写入结果描述（成功含 wiki 路径；失败提示降级）

    Raises:
        无——WikiExportError 一律降级返回（不冒泡到队列）
    """
    from src.agent.services.wiki_export_service import WikiExportError, export_to_wiki

    try:
        result = await export_to_wiki(page, content[:500], title=page)
        return f"已写入 wiki：{result.get('path') or page}"
    except WikiExportError as exc:
        return f"wiki 写入失败（降级跳过）：{exc}"
```

### 7.3 prompt 沉淀引导（prompts.py MEMORY_AGENT_PROMPT 增补）

```text
5.5 沉淀：若结论是值得沉淀的知识（研报/结论/方法，非普通记忆），用
    write_wiki 写入知识库，页面路径用「结论-{主题}」，正文 ≤500 字；
    普通用户画像/事实只写 Store，不写 wiki。
```
