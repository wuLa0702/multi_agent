## 3. 分·设计一：记忆类型体系（P0——先分类，再谈其他）

### 3.1 四类记忆分层

| 类型 | 存在哪 | 谁写 | 内容示例 | 生命周期 |
|------|--------|------|---------|---------|
| **用户画像** | Store（结构化） | LLM 抽取 | 偏好、习惯、身份、常用语 | 长期 |
| **任务记忆** | 文件记忆（tasks.md） | agent 主动写 | 待办、进行中、已完成 | 中短期 |
| **决策/知识** | 文件记忆（decisions.md） | agent 主动写 | 项目约定、技术选型、踩坑教训 | 长期 |
| **事实/常识** | Store（结构化） | LLM 抽取 | 客观事实、名词解释 | 长期 |

**分层原则**：Store 存结构化短事实（适合检索/抽取）；文件存长文上下文
（适合读写/人读）——各司其职，不打架。

### 3.2 文件记忆布局（v3：AGENTS.md 定位明确）

```
data/memory/（/memories/ 路由，全局共享）
├── AGENTS.md            # 系统级渐进披露（技能激活提示、全局规则）
│                        #   ——【v3 决策】不放用户记忆，四类记忆严格走分类
├── tasks.md             # 任务记忆（中短期，agent 主动维护）
├── decisions.md         # 决策/知识（长期，agent 主动维护）
└── tasks_archive.md     # 任务归档（v3 新增：不注入，agent 按需读）
```

**注入入口**（v3 决策，问题 1）：`memory=["/memories/AGENTS.md"]`——
**单文件全量注入**（官方 MemoryMiddleware 原生支持，零自建）。tasks/decisions
为分类承载文件，agent 用文件工具按需读（详情层语义天然存在）。

## 4. 分·设计二：写入策略（P1——从"靠自觉"到"有规矩"）

### 4.1 写入触发条件（不是每轮都写，满足任一才写）

1. 用户明确说"记住"、"以后都这样"
2. 出现新的用户偏好/习惯
3. 做出重要决策/约定
4. 发现重要事实/规律
5. 任务状态变化（新增/完成/取消）

### 4.2 写入格式（结构化模板，非自由文本）

```markdown
# 用户画像（Store，LLM 抽取——键值对）
- 语言偏好：中文
- 回复风格：简洁直接
- 技术栈：Python/React

# 任务记忆（tasks.md，agent 主动写）
- [ ] 完成沙箱池化开发（优先级：高）
- [x] CompositeBackend v3 改造

# 决策记录（decisions.md，agent 主动写）
## 2026-08-05 沙箱选型
- 决策：选 OpenSandbox 自建
- 原因：可控性强、成本低
- 风险：需要自己维护
```

### 4.3 更新规则

| 规则 | 行为 |
|------|------|
| **追加优先** | 新信息追加，不随便删旧的 |
| **冲突处理** | 新信息覆盖旧信息，旧信息移到"历史"区（保留可追溯） |
| **去重** | 相同/相似信息合并，不重复写 |

### 4.4 任务生命周期（v3 决策，问题 4）

| 状态 | 处理 |
|------|------|
| 进行中 | tasks.md（注入侧不注入——agent 按需读） |
| 完成 | tasks.md 勾选 ✅，**保留最近 20 条** |
| 超过 20 条 | 更早的已完成任务**归档到 tasks_archive.md**（不注入，agent 按需读） |

## 5. 分·设计三：注入与检索（P0/P1 官方全量，分层 P2）

### 5.1 注入策略（v3 决策，问题 1——架构级）

| 阶段 | 注入方式 | 依据 |
|------|---------|------|
| **P0/P1** | **官方 MemoryMiddleware 全量注入**：`memory=["/memories/AGENTS.md"]` 单文件 | 初期记忆量小（几十 KB），全量 token 成本可接受；先跑通"能分类、能写入、能回忆"闭环；自建分层中间件风险高，等记忆真膨胀再做 |
| **P2** | 分层注入（核心全量 + 相关检索 + 详情主动读）——届时自建中间件或官方能力跟进 | 记忆膨胀后 |

**AGENTS.md 内容约定**（问题 3 决策）：系统级渐进披露内容（技能激活提示、
全局规则、跨类关键索引）——**不放用户记忆**；用户记忆严格走四类分类
（tasks/decisions 文件 + Store）。

### 5.2 检索方式升级（P1）

| 层 | 现状 | P1 目标 | P2 |
|----|------|---------|----|
| Store | 取最近 N 条 | 关键词/标签过滤 + 时间衰减 | 向量语义检索 |
| 文件 | 全量注入（AGENTS.md） | agent 按需读 tasks/decisions/archive | 分层注入 |

### 5.3 上下文窗口控制（P1）

- AGENTS.md 注入超阈值（≤ 上下文 10%，配置化）→ system prompt 指引精简
- 裁剪提示优先级：用户画像 > 当前任务 > 相关事实 > 旧决策

## 6. 分·设计四：记忆治理（P2——质量控制）

### 6.1 噪音控制

- 写入前校验：不符合格式的不写（LLM 抽取侧校验 + 文件格式模板校验）
- 定期整理：压缩归档旧记忆（脚本 + 审计）
- 重要性评分：每条记忆 1-5 分，低分优先裁剪（P2）

### 6.2 版本与回滚

- 记忆文件变更走 git（评估：data/memory/ 入库 vs data/ gitignore 冲突——
  **评审决策点**，见 §7.2 风险）
- 每次写入留审计日志（谁、什么时候、改了什么——复用 audit logger）

### 6.3 人工干预

- "记忆管理"面板（前端）：查看/编辑/删除记忆（标注后续）
- 重要记忆人工确认后生效（可选：interrupt 审批——权限模板预留）

### 8.3 Store 类型化抽取链路（P1：LLM 输出类型——问题 2 决策）

```python
"""（memory_store.py 增量：v3 类型化链路——LLM 抽取时同时输出类型）"""

MEMORY_NAMESPACES = {
    "user_profile": ("memory", "user_profile"),   # 用户画像（长期）
    "facts": ("memory", "facts"),                 # 事实/常识（长期）
}
_TYPE_WHITELIST = {"user_profile", "facts"}


async def extract_memory_typed(
    user_message: str, assistant_text: str, *, turn_count: int = 0
) -> dict | None:
    """LLM 抽取 + 类型分类（v3：一次调用输出 {type, fact}）。

    性能控制（v3.1 决策）：对话太短（turn_count < 2）或明显无记忆价值 →
    跳过抽取（省 token）——每轮都调 LLM 抽取成本不可忽略。

    Args:
        user_message: 用户消息
        assistant_text: 助手回复
        turn_count: 本对话轮次（<2 → 跳过，短对话无记忆沉淀）

    Returns:
        {"type": "user_profile"|"facts", "fact": "一句话事实"}；
        无记忆价值/对话过短 → None；类型未知 → facts 兜底 + 审计
    """
    if turn_count < 2:
        return None   # 短对话跳过（v3.1：省 token）
    raw = await LLMAdapter().chat(...)   # prompt 要求输出 JSON {type, fact}
    ...  # 解析 + 类型白名单校验（未知类型 → "facts" 兜底 + 审计日志）
    return {"type": validated_type, "fact": fact}


async def save_typed_memory(store, memory_type: str, fact: str) -> None:
    """类型化写入（对应 namespace）。

    Args:
        store: AsyncSqliteStore 实例
        memory_type: user_profile / facts（§3.1 分工）
        fact: 抽取的一句话事实

    Raises:
        ValueError: 未知类型（白名单外）
    """
    namespace = MEMORY_NAMESPACES.get(memory_type)
    if namespace is None:
        raise ValueError(f"未知记忆类型：{memory_type}，可选 {sorted(_TYPE_WHITELIST)}")
    if store is None:
        return
    await store.aput(namespace, str(time.time()), {"fact": fact, "ts": time.time()})
```
