## 0. 结论（缺口清单先读） 🔴 v1

**一句话**：前端已覆盖对话/历史/模型选择/技能/审批/上下文用量，但**后端 2026-08-10~12 新增能力多数未接前端**——尤其是**成本体系（模型单价 / 成本展示 / 成本告警）完全没有前端**，这是"成本可核算"闭环的最后一段。另有 MCP 管理、设置中心、UX 小缺口。

**缺口 6 项（按优先级）**：

| # | 缺口 | 对应后端 | 优先级 |
|---|------|----------|--------|
| F1 | **模型单价编辑 UI**（设置页/模型管理输入 input_price/output_price）| `PATCH /v1/providers/models/{id}/price` | **P0** |
| F2 | **成本展示**（会话成本汇总 / 告警列表，前端展示面板）| `GET /v1/cost/summary` `/v1/cost/alerts` | **P0** |
| F3 | **成本告警 SSE 事件处理**（cost_alert 事件 → Toast/通知）| SSE `cost_alert`（分级告警 5/10/20）| **P1** |
| F4 | **MCP 管理 UI**（连接列表 / 启停 / 删除）| `GET/PATCH/DELETE /v1/mcp-servers` | **P1** |
| F5 | **设置中心对齐**（/v1/settings 读写打通 + 热更新提示）| `GET/PUT /v1/settings`、`POST /v1/frontend/logs` | **P2** |
| F6 | **文件引用渲染**（FileRef 安全路径展示，防越权回显）| 安全机制 `schemas/file.py`（FileRef）| **P2** |

## 3. 逐项详设要点 🔴 v1

### F1 模型单价编辑（P0）
- 位置：SettingsPage 或模型管理区（ModelSelector 旁）
- 交互：模型列表 → 每模型 input_price/output_price 输入框（元/千 token）→ 保存调 `PATCH /v1/providers/models/{id}/price`
- 后端已支持 reload 生效（registry 重载），前端保存后提示"已生效"

### F2 成本展示（P0）
- 位置：会话详情 / ChatPage 侧栏，或 SettingsPage
- 数据：`GET /v1/cost/summary?session_id=` → total_cost/input/output_tokens/alert_count；`/alerts` → 告警列表
- 展示：会话卡片或对话框角落显示 ¥成本 + 告警徽标

### F3 成本告警 SSE 处理（P1）
- `chatStore` 的 SSE 分发加 `cost_alert` 分支 → Toast/notice（"成本已超 ¥X"）
- mock.ts 补 cost_alert 样例（对齐分级告警）

### F4 MCP 管理 UI（P1）
- SkillsPage 加"MCP 连接"Tab：列表（来源/启停状态）→ 启停调 `PATCH /v1/mcp-servers/{id}`、删除调 `DELETE`
- 复用 InstalledSkillRow 模式

### F5 设置中心对齐（P2）
- SettingsPage 接 `GET/PUT /v1/settings`（业务开关）
- `POST /v1/frontend/logs` 接入前端 logger（占位已留）
- 后端热更新未做（P2 待办）→ 前端保存后提示"需重启后端生效"（诚实提示）

### F6 文件引用渲染（P2）
- 渲染 FileRef（name/path）时按安全契约展示，越权路径后端已拦截（FileRef validator）
- 前端不做额外路径拼接，展示后端返回的相对路径

## 4. 优先级与实施顺序 🔴 v1

| 顺序 | 项 | 依赖 | 预估 |
|------|-----|------|------|
| 1 | **F1 模型单价**（P0）| 后端已就绪 | 半天 |
| 2 | **F2 成本展示**（P0）| F1 后成本可真算 | 半天 |
| 3 | **F3 成本告警**（P1）| 与 F2 同批 | 0.5 天 |
| 4 | **F4 MCP 管理**（P1）| 无 | 半天 |
| 5 | **F5 设置中心**（P2）| 后端热更新待做 | 1 天 |
| 6 | **F6 文件引用**（P2）| 无 | 0.5 天 |

> 📌 **建议**：P0 两项（F1/F2）是"成本可核算"闭环的最后一环——后端已完成全链路（单价→流水→告警），前端补上即可在面试/演示中讲"成本从设置到展示全链路"。F3 与 F2 同批。P2 三项可后置。
