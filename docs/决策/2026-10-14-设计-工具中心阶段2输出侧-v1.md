## 1. 现状与痛点 🔴 v1

**11 个工具全部返回裸 `str`**，且**成功 / 降级 / 失败三种语义混在同一根字符串里**，下游无法程序化区分：

| 工具 | 成功返回 | 降级/失败返回（同样是一根字符串） |
|---|---|---|
| `internet_search` | 拼好的结果文本 | `搜索失败（X）：…请勿重试搜索` |
| `fetch_url` | 网页正文 | `链接格式非法（…）：{url}` / `抓取失败：HTTP 404（{url}）` / `抓取失败（X）：{url}` |
| `run_code_in_sandbox` | stdout（截断） | `沙箱不可用：SANDBOX_URL 未配置…` / `沙箱执行失败（X）：…` |
| `run_command_in_sandbox` | stdout | 同上 + 危险命令拒绝文本 |
| `upload_workspace_file` | `已上传至沙箱 workspace/…` | 路径非法 / 上传失败 |
| `download_sandbox_file` | 文件内容 | 路径非法 / 下载失败 |
| `run_skill_script` | 脚本输出 | `沙箱不可用…` / `技能脚本路径不合法…` / `脚本执行失败（X）…` |
| `write_wiki` | `已写入 wiki: {path}` | `写入失败：内容为空` / `写入 wiki 失败：{exc}` |
| `generate_report` | 拼好的 markdown | `生成失败：内容为空` |
| `publish_report` | `报告已通过审核并交付` | （HITL 闸门） |
| `ask_human` | （HITL interrupt） | — |

**三个真痛点**：
1. **下游分不清成败**——审计/事件/编排拿到一根字符串，只能靠 `"失败" in text` 猜
2. **错误语义不可枚举**——`超时` / `404` / `限流` / `未配置` 混在自由文本里，无法据此决定"重试还是降级"（阶段 4 需要）
3. **输出被截断/降级时无标记**——`_truncate_output` 只是加了一句话，程序不知道"这是不完整结果"

## 2. 目标契约：`ToolResult` 三态 🔴 v1

新增 `backend/src/tools/result.py`：

```python
from dataclasses import dataclass
from typing import Any, Literal

ToolStatus = Literal["ok", "degraded", "error"]


@dataclass(frozen=True)
class ToolResult:
    """工具统一输出信封（成功 / 降级 / 失败三态）。

    Attributes:
        status: ok=正常完成；degraded=部分可用（截断/兜底/降级路径）；error=失败
        message: 人类可读中文（统一文案，供渲染给 LLM）
        data: 结构化内容（成功/降级时），供审计、事件、编排消费
        error_code: 归一错误码（见 §3）；status=ok 时为空串
        retryable: 是否可重试——供编排层（阶段 4）决定重试/降级
        tool: 工具名（审计与事件定位用）
    """

    status: ToolStatus
    message: str
    data: dict[str, Any] | None = None
    error_code: str = ""
    retryable: bool = False
    tool: str = ""
```

**三态语义**（关键在 `degraded`——现在完全缺失）：

| status | 含义 | 例子 |
|---|---|---|
| `ok` | 正常完成 | 搜索返回结果、沙箱执行成功 |
| **`degraded`** | **部分可用**：拿到结果但不完整/走了兜底 | 输出被截断、搜索失败但给了降级提示、沙箱输出超限 |
| `error` | 失败，没有可用结果 | 参数非法、沙箱不可用、HTTP 4xx |

## 3. 错误码归一 🔴 v1

错误码进 `core/errors.py`（项目规定的错误文案唯一载体），**字符串枚举**：

| code | 含义 | 典型来源 |
|---|---|---|
| `not_configured` | 依赖未配置 | `SANDBOX_URL 未配置` |
| `invalid_arg` | 参数非法 | 链接格式非法、路径越权 |
| `denied` | 无权限 | HTTP 401 / 权限拒绝 |
| `unpaid` | 欠费/未授权 | HTTP 402 |
| `not_found` | 资源不存在 | HTTP 404 |
| `rate_limited` | 限流 | HTTP 429 |
| `timeout` | 超时 | 网络/沙箱超时 |
| `upstream_error` | 上游故障 | HTTP 5xx |
| `internal` | 未知内部错误 | 其余异常 |

`retryable` 与 code 的对应（对齐 06 §4 异常四分类）：`timeout` / `rate_limited` / `upstream_error` → **True**；`invalid_arg` / `not_configured` / `denied` / `unpaid` / `not_found` → **False**。

## 4. LLM 看文本、程序看结构（双通道） 🔴 v1

**核心设计**：`ToolResult` 同时供给两个消费者，**各有各的通道**——

| 消费者 | 通道 | 内容 |
|---|---|---|
| **LLM** | `ToolMessage.content` | `render(result)` 渲染的**中文文本**（保持现有风格，不塞 JSON，避免 token 膨胀与模型困惑） |
| **程序**（审计 / SSE / 编排） | `ToolMessage.artifact` | `result.data` + `status` + `error_code`（结构化） |

**实现方式（推荐）**：工具改用具 `response_format="content_and_artifact"` 的 `@tool` 装饰器，返回 `(render(r), r.data)`。这是 **LangChain 原生机制**（`StructuredTool` 支持），不是自造。

```python
# tools/impl/fetch.py（示意）
@tool("fetch_url", response_format="content_and_artifact")
def fetch_url(url: str, max_chars: int = 8000) -> tuple[str, dict]:
    ...
    return render(r), (r.data or {})
```

`render()` 放在 `tools/result.py`：

```python
def render(r: ToolResult) -> str:
    """ToolResult → LLM 可读文本（统一文案，对齐 06 §6「中文 + 冒号分隔」）。"""
    if r.status == "ok":
        return r.message
    if r.status == "degraded":
        return f"（部分结果）{r.message}"
    return f"失败原因：{r.message}"
```

## 5. 落地方案（2.1–2.4） 🔴 v1

| 步 | 内容 | 行为变化 |
|---|---|---|
| **2.1** | 落**契约**：`tools/result.py`（`ToolResult` + `render`）+ `core/errors.py` 补错误码 | **零**（没人用） |

## 6. 边界（不做什么） 🔴 v1

| 不做 | 原因 |
|---|---|
| **"修复"内容**（补字段 / 改错字 / 翻译） | 工具输出是**程序产出**；协议字段应"校验失败即报错"。修复只适用**内容里的 LLM 产物**（落 `llm/` 层，非工具中心） |
| **单位归一** | 当前**无真实场景**（11 个工具都不含带单位字段）——等第一个真实场景再落 |
| **中间件统一包返回值** | HITL 工具返回 `interrupt`、子代理返回结构特殊，中间件改写风险大；改为**工具自身 `return` 处渲染**（显式、可控） |
| **对 LLM 暴露 JSON** | LLM 视图保持中文文本；结构化走 `artifact` 旁路 |

## 7. 验证与测试 🔴 v1

- `test_tools/test_result.py`：`render` 三态输出；`ToolResult` 构造与默认值
- 每工具改造后**补一个三态用例**（正常 / 降级（截断）/ 错误）
- 回归：全量 `pytest` 绿；`lint_tools.py` 无违规
- **人工核对**：渲染文本与改造前文案的 diff（逐条确认，不静默改）
