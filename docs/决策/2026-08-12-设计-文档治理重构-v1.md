## 2. 核心概念 🔴 v2

### 2.1 架构 vs 方案（分类主轴）

| | `架构/` | `方案/` |
|---|---------|---------|
| 回答 | 系统现在长什么样（**是什么**）| 当时决定怎么做（**怎么做**）|
| 时态 | **现在时**——每次功能落地都要更新 | **过去时**——拍板即定格 |
| 试金石 | "现在还要不要改？" 要 → 架构 | "已定稿不再改？" 是 → 方案 |
| 生命周期 | 活着，持续维护 | 拍板 → 执行 → 使命完成 → 归档 |

### 2.2 架构/ 三层参考（v2 明确解耦）

| 层 | 文档 | 回答 | 权威内容 | 更新时机 |
|----|------|------|----------|----------|
| **结构** | 架构目录 | 系统**结构**长什么样 | 目录树 / 决策记录 / 基建 / 部署 | 结构/决策变化 |
| **契约** | 后端接口 | 系统**对外**怎么对接 | API 路由 / 请求响应模型 / SSE 协议 / CORS | 接口变化 |
| **功能** | 后端功能全景 | 系统**功能**有什么 | 16 域功能清单 / 核心函数 / 测试 / 时间线 | 功能/测试变化 |

**重合点与去重**：① 功能全景 §3 目录结构 ↔ 架构目录 §2 目录树 **重复** → **功能全景删 §3，改引用架构目录**；② 架构目录 §6 决策 ↔ 功能全景 §5 时间线 部分重叠（决策 vs 记录，性质不同可并存）。
**结论**：三层解耦合理（各回答一个问题），去重后干净互补。

### 2.3 决策/ vs 归档/（v2 明确）

> co-creator 疑问："我理解都是执行了开发，属于过程性文档？" —— 对了一半。

| | `决策/`（←decisions）| `归档/`（←archive）|
|---|-------------------|------------------|
| 位置 | **活着的决策层** | **退出决策链** |
| 放什么 | 评审稿（评审中）、决策记录（做/不做）、已实施但仍承载"为什么"的设计 | 被覆盖的旧版、被推翻的决策、执行完使命的蓝图 |
| 回答 | **为什么**系统这么设计 | 只为历史留存 |
| 判据 | "还要被读来理解为什么吗？" 需要 → 决策/ | 只是旧的 → 归档/ |

**例**：`设计-成本控制-v1` 已实施但承载决策价值 → 决策/；`方案-前端目录结构` 已执行、真相在架构目录 → 归档/。

### 2.4 命名规则（v2 新增，入文档治理规则）

- **动态维护的顶层/参考/规则文档**（架构目录 / 后端接口 / 后端功能全景 / 索引 / 功能更新日志 / 规则/ 全部）→ **`主题.md`，无日期前缀、无 -vN**（版本靠文档头 📝 记录）
- **过程性文档**（决策/ 评审稿、方案/ 已定稿、学习/、踩坑/、归档/）→ **`YYYY-MM-DD-类型-主题-vN.md`**（保留）
- 例外沿用：`踩坑/` 用 `YYYY-MM-DD-主题.md`；`索引` 类 `索引.md` / `索引-踩坑.md`

## 附录 B：面试描述点-成本控制 v1（demo，按附录 A 规则生成）

### §1 总（30s）
> "成本控制是这套多 Agent 系统里我做的**生产级收尾**——多 Agent 每次委派都是独立 LLM 调用，成本比单 Agent 高 2-8 倍（实测），不控就是烧钱。我做的是全链路四件套：**token 统计 → 模型单价 → 缓存 → 分级告警**，现在 375 个测试全绿，**每一分钱可核算、可预警**。"

### §2 分（60-90s，四件套 × 各带权衡）

| 件 | 做了什么 | 可追问点 |
|----|----------|----------|
| **① Token 差量统计** | TokenUsageMiddleware 每次 LLM 调用后差量落成本流水（`token_cost_ledger`）| 差量是近似（压缩可能影响）→ P2 接 `usage_metadata` 精确化 |
| **② 模型单价可配** | `PATCH /v1/providers/models/{id}/price` + seed 预填真实官方价（元/千token）| 之前自定义模型单价=0 → **核算是假的**，评审抓出的真问题 |
| **③ LLM 缓存（主链路）** | `_configurable_model` 拦截点，相同 (messages+model) 命中绕过 LLM；辅助+主链路都挂 | 命中率可量化（评审拍板从 P2 升级实施）|
| **④ 分级告警** | 阈值 5/10/20 倍数递增，每档告警一次（修了 MAX 档去重 bug）| "避免打扰也避免失联"——不硬断，提示自主决定 |

### §3 流程图（成本横切挂载）

```
用户 → api → 主图(deepagents) → 工具 → 审核 → SSE 交付
              │
              └─ 🟥 成本横切（中间件栈，图执行完自动触发）
                   ├─ ① LLM 调用 → ③ 缓存命中? → 省一次调用
                   ├─ ② 每次调用 → 差量 token × 单价 → 成本流水
                   └─ ④ 累计超阈值(5/10/20) → cost_alerts 落库 + SSE 提示
```

### §4 总（20s）
> "一句话——**成本不是事后统计，是横切在每次 LLM 调用上的护栏**：命中缓存就省一次调用，用了多少记流水，超阈值才告警，单价不对能改。这块和容错、安全一样，都是挂在主流程横切点上加固，不重写业务编排。"
