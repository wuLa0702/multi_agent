## 2. 方案一：右侧信息栏（任务/成本/用量收纳，可折叠） 🔴 v1

**目标**：主界面清爽——顶部只留 ChatHeader + 消息流 + 输入；过程信息收右侧栏。

**布局改造**（`ChatPage.tsx`）：
```
┌──────────────────────────────────────────┐
│ ChatHeader（标题/操作）                    │
│ ┌────────────────────┬─────────────────┐ │
│ │ 消息流（主）         │ 右侧信息栏       │ │
│ │                    │  ▸ 任务进度      │ │
│ │                    │  ▸ 成本/告警     │ │
│ │                    │  ▸ 上下文用量    │ │
│ │                    │  ▸ Agent 面板    │ │
│ └────────────────────┴─────────────────┘ │
│ ChatInput（输入）                          │
└──────────────────────────────────────────┘
```

**改造点**：
- **右栏组件** `components/layout/InfoPanel.tsx`：可伸缩（宽 280px ↔ 折叠窄条 40px）、每项可折叠（折叠头 + 展开体）
- **收纳**：`TodoPanel` / `CostPanel` / `ContextUsage` 从顶部移入右栏，各占一个折叠区块
- **AgentPanel**（已存在可开关）对齐进右栏，统一管理
- **默认**：右栏可折叠到窄条（清爽），点开展开；宽度/折叠状态存 localStorage

**落点**：`components/layout/InfoPanel.tsx`（新建）+ `pages/ChatPage.tsx`（布局重排）+ `components/todo/TodoPanel.tsx`、`components/chat/{CostPanel,ContextUsage}.tsx`（样式适配右栏窄宽）

## 3. 方案二：流式 loading 转圈 + 简单任务直连 🔴 v1

### 3.1 loading 转圈（1b）
- **发送按钮**：`streamStatus` 为 connecting/streaming 时，发送按钮变 spinner（`animate-spin`）+ 禁用，旁边显示"思考中…"；点击可停止（已有 cancel）
- **消息气泡**：收到首 token 前，用户消息气泡尾部加三点跳动动画（"…"）
- **审批等待**：awaiting_approval 时，审批卡显示"待你审批"徽标（已有，补动画）
- 落点：`components/chat/ChatInput.tsx`（按钮 spinner）+ `components/chat/MessageBubble.tsx`（等待动画）

### 3.2 简单任务直连（1c）—— mock 数据完善
> ⚠️ 澄清：**当前是测试数据**（`MOCK_ENABLED=true`）——mock 流一律触发子代理+沙箱，所以"解释 langgraph 原理"也走复杂回路。真后端（false）会按模型实际规划。

**mock 完善目标**：mock 流按**问题复杂度**分流：
- **简单问题**（问概念/解释）：直接 `token → done`，不触发子代理/沙箱/审批
- **复杂任务**（调研/生成报告/执行代码）：才走 子代理 → 工具 → 审批 回路
- 分流依据：mock 里关键词/长度启发式（如含"解释/是什么/工作原理"→ 简单；含"调研/报告/写/执行"→ 复杂），或前端在 mock 模式随机/固定分流（演示友好）

**落点**：`lib/api/mock.ts`（`streamChatMock` 加简单分支）+ 前端演示数据补充

## 4. 方案三：上下文上限可调（滑杆/输入 + 后端联动） 🔴 v1

**目标**：`context_total` 不再硬编码 128k，支持设置（输入框 + 滑杆），后端/前端一致。

**前端**（`components/chat/ContextUsage.tsx`）：
- 组件内加"设置上限"入口：**滑杆（range 64k~1M，步进 64k）** + **数字输入框**（支持 1M+，为将来更大模型预留）
- 选择结果写 `localStorage`（`multi-agent.contextLimit`），并同步 `chatStore.contextTotal`
- 读后端 `done` 事件的 `context_total` 优先；未给则用本设置

**后端**（联动）：
- `core/config.py` 加 `context_limit`（默认 128k）；DB `settings` 表可写（前端设置中心 PUT /v1/settings）
- `token_usage.py` 中间件用该值计算百分比/告警窗口（`>0.8*limit`）
- SSE `done` 事件 `context_total` = 当前配置值（非硬编码）

**落点**：`lib/stores/chatStore.ts`（contextTotal 初始读 localStorage）、`components/chat/ContextUsage.tsx`（滑杆/输入 UI）、`backend/src/core/config.py` + `agent/middlewares/token_usage.py` + `schemas/events.py`（context_total 来源）

## 5. 方案四：卡片样式统一 + mock 切换说明 🔴 v1

### 5.1 卡片统一（4a）
- 定义统一卡片规范：圆角 `rounded-lg`、边框 `border-border`、内边距 `px-3 py-2`、标题 `text-xs font-medium text-muted-foreground`
- 各信息卡（Todo/Cost/ContextUsage/Approval）改为复用统一 `InfoCard` 基座组件
- 落点：`components/ui/card.tsx` 扩展或新建 `components/shared/InfoCard.tsx`，各卡接入

### 5.2 mock 切换说明（4b）
- 明确：`mock.ts:44 MOCK_ENABLED=true` = 测试数据模式；改 `false` = 连真后端
- 建议优化：把开关做成**设置页项**（`mock_enabled` 存 DB settings / localStorage），运行时切换无需改代码
- 文档补充：`docs/规则/文档治理规则.md` 或前端 README 注明 mock/真实模式差异
