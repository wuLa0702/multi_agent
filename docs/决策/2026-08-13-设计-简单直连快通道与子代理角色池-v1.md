## 1. 方案一：简单直连快通道（规则快通道 + LM 兜底） 🔴 v1

### 1.1 机制

请求进来 → **intent 分类**（确定性规则，零 LLM 成本）→ 分流：

```
用户请求 → classify_intent(request)
  ├─ 简单（概念问答/短问）→ 快通道：主 agent 不挂搜索/子代理工具 → 单轮直接答
  └─ 复杂/模糊 → 完整链路（挂搜索/子代理/publish_report）
```

### 1.2 `classify_intent()` 规则（关键词 + 长度启发式）

| 信号 | 判简单 | 判复杂 |
|------|--------|--------|
| 关键词 | `解释/是什么/区别/为什么/定义/简述/介绍` + 无研究意图 | `调研/分析/报告/生成/评估/对比 X 和 Y 优劣/写论文/整理资料` |
| 长度 | 短问题（<30 字）| 长/多句 |
| 结论 | 命中简单信号 → 快通道 | 命中复杂信号 → 完整链路；都无 → 完整链路（**LM 兜底**，宁复杂不错过）|

> 兜底原则：**不确定就走完整链路**（规则只拦截"确定简单"的），避免误伤复杂问题。

### 1.3 快通道实现

- 快通道 = 主 agent **不挂搜索/子代理工具**（`internet_search`/`fetch_url`/subagents 不注入），只保留基本工具（sandbox 计算可选）
- 模型没有搜索工具 → 只能基于知识直接答 → **天然不会过度拆解**
- 同时 `prompts.py` 加引导："简单问题直接回答，不要拆解搜索/委派子代理"

### 1.4 落点

| 文件 | 改动 |
|------|------|
| `agent/intent.py`（新建）| `classify_intent(request) -> "simple"\|"complex"`（关键词+长度，底层豁免）|
| `api/chat.py` | 分流：simple → 快通道参数（不挂搜索工具）|
| `agent/main_agent.py` | 按 intent 决定挂载工具集（simple 少挂）|
| `agent/prompts/prompts.py` | 加"简单直接答"引导 |

### 1.5 面试价值
"意图路由 + 快慢通道"——可控、省成本、可解释；面试讲"系统级判断 vs 模型自主"的取舍。

## 2. 方案二：子代理静态角色池扩展 🔴 v1

### 2.1 现状确认
- 子代理**服务启动时**从 `subagents/*.yaml` 加载注册（`loader.py`），**固定 2 个**（search_agent 搜索 / review_agent 审核）
- **非动态**：模型只能在已注册角色里选

### 2.2 扩展方案（静态池）
- 按需**多写 YAML 角色**，扩大静态池：
  - `search_agent`（已有）：搜索委派
  - `review_agent`（已有）：质量审核
  - `data_agent`（新增）：数据/表格整理（沙箱计算 + 数据）
  - `code_agent`（新增，可选）：代码生成/验证（沙箱执行）
- 每个 YAML：name/description/system_prompt/tools/model/permissions——模型据 description 自主选用
- **仍静态**（启动注册），但池子大 → 面试讲"声明式角色分离 + 演进预留"

### 2.3 真动态（演进预留，不入本期）
- 动态数量（任务决定 N 个并行）→ **手写 LangGraph Send API（Map-Reduce fan-out）**，02-hands-on-training 学习主线
- deepagents async subagents：之前评估=不做（需 Agent Protocol server）

### 2.4 落点
| 文件 | 改动 |
|------|------|
| `agent/subagents/data_agent.yaml`（新建）| 数据整理角色（工具：沙箱 + 可能 fetch）|
| `agent/subagents/code_agent.yaml`（新建，可选）| 代码角色 |
| `agent/subagents/loader.py` | 无需改（自动扫目录）|
