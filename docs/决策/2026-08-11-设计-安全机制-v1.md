## 1. 背景与目标

### 1.1 背景

面试指南 §3.2 把**安全机制**列为 P2：*"Prompt 注入防护、数据脱敏、权限控制、审计日志"*——加分项，面试官可能不问，但问了要能答出真实落地。

用户临时清单第 4-5 条（2026-08-11）提出实质缺口：**文件后端只读限制，那怎么写？**（agent 需要产出文件但被只读挡住）**文件路由要不要限制 agent 给出的文件地址？**（agent 返回消息要符合格式，以对象限制，对具体文件限制规范）——这正是"文件权限 + 路由校验"的落地诉求。

### 1.2 目标

1. **文件权限管控**：agent 产出文件的**受控写入通道**（工作区白名单路径）+ 返回文件地址的**格式/路径校验**（防任意路径/越权回显）
2. **注入防护**：工具输入的注入校验（fetch_url 协议已有；补命令/参数注入校验 + 子代理工具最小化审查）
3. **脱敏深化**：审计脱敏复核 + 成本流水不记内容（成本控制已做）
4. 按 §4.6 输出面试三要求（§3）+ 完整核心代码（§6）

### 1.3 范围

| 在本设计内 | 不在本设计内 |
|-----------|-------------|
| 文件路径白名单 + 返回地址校验 | PII 全量识别（P2 后）|
| 工具输入注入校验（fetch/命令）| 完整 WAF/LLM 输出过滤（过度）|
| 子代理工具最小化审查 | 加密存储/密钥托管（P2 后）|
| 审计脱敏复核 + 注入拦截日志 | 多租户隔离（单用户）|

## 4. 机制设计（四层） 🔴 v1

### 4.1 注入防护（工具输入校验）

- **fetch_url**：协议校验已有；补 **URL 格式严格校验**（防 `javascript:`/`file:` 等）
- **run_command_in_sandbox / run_skill_script**：补**命令注入校验**——禁止 `;`/`&&`/`|` 拼接 + 禁止 `../`/绝对路径穿越（skill_tool 已有路径校验，复核）
- **子代理工具最小化**：审查全量子代理 YAML——review_agent 无工具 ✅；search_agent 仅搜索 ✅；新增子代理须过"最小工具"审查（写入规则）

### 4.2 数据脱敏（深化）

- tool_audit 脱敏复核：参数截断已有；补**密钥模式脱敏**（`sk-xxx` / `api_key=` 值打码）
- 成本流水不记内容 ✅（成本控制已做）

### 4.3 文件权限（核心，回应用户清单）

- **受控写入通道**：agent 产出文件限定 `workspace/{session_id}/` 白名单路径——工具层 `write_file`/`upload` 强制前缀校验（00-security 扩展）
- **返回文件地址校验**：agent 返回文件地址 → **对象校验**（schemas：`file_path` 必须 workspace 内相对路径，禁 `../`/绝对路径/外部协议）→ 非法降级提示（不中断）

**与 CompositeBackend 职责划分**（回应安全评审大 2，2026-08-12 补）：

| 层 | 管什么 | 落地位置 |
|----|--------|----------|
| **CompositeBackend** | agent **实际读写文件的权限**——路径白名单、deny/interrupt、会话隔离（**能不能读写**）| `core/backend.py` + PolicyBackend + FilesystemPermission（已有实现）|
| **本设计（安全机制）** | agent **返回给用户的文件地址格式校验**（防越权路径回显）+ 工具输入注入校验（**地址合不合法**）| `validate_workspace_path` / `FileRef` / 注入校验（本设计 D1-D3）|

> 一句话：**CompositeBackend 管"能不能读写"，本设计管"返回给用户的地址合不合法"**——两层互补，不重复建设：CompositeBackend 在文件系统层拦截越权访问，本设计在输出层保证 agent 回显的地址是安全可用的工作区路径。

### 4.4 审计（深化）

- tool_audit 新增 `security_blocked` 事件（校验拦截计数，日志可统计）
- 审计覆盖全量工具调用（已有）+ 拦截事件

## 6. 完整核心代码

### 6.1 `core/permissions.py` 文件路径校验

```python
from pathlib import Path


def validate_workspace_path(path: str, session_id: str) -> bool:
    """校验 agent 产出的文件路径在工作区白名单内（D1，防越权/穿越）。

    Args:
        path: agent 给出的文件路径（相对 workspace 或绝对）
        session_id: 会话 ID（工作区隔离）

    Returns:
        True=合法（workspace/{session_id}/ 内、无穿越/外部协议）
    """
    if not path or "://" in path:  # 禁外部协议
        return False
    norm = Path(path).as_posix()
    if norm.startswith("/") or ".." in norm.split("/"):  # 禁绝对路径/穿越
        return False
    return True  # 相对路径默认放行（调用方拼接 workspace/{session_id}/）
```

### 6.2 `schemas/file.py` 文件引用对象

```python
from pydantic import BaseModel, Field, field_validator

from src.core.permissions import validate_workspace_path


class FileRef(BaseModel):
    """agent 返回文件引用（D2：对象限制 + 路径校验，防任意路径回显）。"""

    name: str = Field(description="文件名")
    path: str = Field(description="工作区内相对路径")
    content_type: str = "text/plain"
    size: int = 0

    @field_validator("path")
    @classmethod
    def _check_path(cls, v: str) -> str:
        if not validate_workspace_path(v, session_id="*"):
            raise ValueError(f"文件路径越权：{v}")
        return v
```

### 6.3 `fetch_tool.py` URL 注入校验

```python
import re

_SAFE_URL_RE = re.compile(r"^https?://[^\s\"'<>;]+$")


def _validate_url(url: str) -> bool:
    """URL 严格校验（D3）：http/https + 无注入字符（空格/引号/分号/<>）。"""
    return bool(_SAFE_URL_RE.match(url))
```
