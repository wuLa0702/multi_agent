## 1. 背景（评估暴露的问题） <span style="color:#fff;background-color:#e11d48;border-radius:4px;padding:1px 6px;font-size:0.8em">v1</span>

评估跑数（2026-08-10/11）trace 三层根因定位：模型在沙箱**自写爬虫**（curl/urllib 抓官网）循环 50 轮撞 recursion limit。

**根因链**：任务要精确数据（价格/参数量）→ 博查搜索只给摘要（发现层）→ 模型要全文（内容层）→ **项目工具集缺"受控抓取"能力** → 模型被迫在沙箱裸代码联网 → 循环失控 + 审计盲区 + 数据外泄风险。

## 2. 讨论过程（方案演进） <span style="color:#fff;background-color:#e11d48;border-radius:4px;padding:1px 6px;font-size:0.8em">v1</span>

| 轮次 | co-creator 质疑 | 方案演进 |
|------|----------------|----------|
| 1 | "为啥跑满 50 轮？有记录么？监控够么？" | 补推理层 trace 采集（阶段一）→ 三层根因定位（阶段二） |
| 2 | "沙箱断网怎么实现？全断还是白名单？" | OpenSandbox egress 机制调研：NetworkPolicy 请求级 + default-deny 语义 |
| 3 | **"博查只能搜目录，curl 抓不到文章——链路不通！只加限制没解决搜索汇总核心问题"** | **关键转折**：补**受控抓取工具 fetch_url**（搜索发现 + 抓取获取 双工具分工，行业标准架构），沙箱断网从"惩罚"变为"收敛网络入口" |
| 4 | "受控工具在沙箱内搜索么？" | 澄清：工具在**服务端执行**（mcp/registry 注册，后端进程出网），沙箱只做计算 |

**核心认知修正**：问题不是"模型不听话"，是**工具集不完整**——只有搜索（发现）没有抓取（获取）。断网 + 补工具是配套方案：**有路可走，才堵得住歪路**。

## 3. 拍板结果（2026-08-11 co-creator 审核通过） <span style="color:#fff;background-color:#e11d48;border-radius:4px;padding:1px 6px;font-size:0.8em">v1</span>

### 3.1 受控抓取工具 `fetch_url`（新增）

| 项 | 设计 |
|----|------|
| 位置 | `agent/tools/fetch_tool.py` + 注册 `mcp/registry.py`（工具层，服务端执行）|
| 输入 | `url`（必填）+ 可选 `max_chars` |
| 实现 | 后端进程 httpx 请求（UA + 10s 超时 + 跟随重定向 + HTML 清洗 + 8000 字符截断）|
| 安全 | 仅 http/https；纯文本输出；无 JS 执行 |
| 审计 | ✅ 自动过 ToolAudit（抓了哪个 URL 有记录）；限流（每任务抓取上限）|

### 3.2 沙箱断网（egress NetworkPolicy）

| 项 | 设计 |
|----|------|
| 机制 | OpenSandbox egress sidecar（DNS 代理 + nftables 两层），NetworkPolicy **请求级**传入 |
| 评估场景 | `defaultAction: "deny"` + 空 egress = **全断**（curl/pip/urllib 全失败）|
| 生产 | 默认不传（现状全放行）或后续白名单（pypi 等）——单独决策 |
| 落地 | `sandbox/adapter.py` 创建沙箱支持 network_policy 透传 + settings 开关 `sandbox_offline`（评估 .env.dev 开）|

### 3.3 完整链路（拍板目标形态）

```
internet_search（博查）── 发现：关键词 → URL 列表 + 摘要
fetch_url（受控工具）  ── 获取：URL → 页面正文
沙箱（断网）           ── 计算：跑代码验证数据
模型 ── 基于正文写报告（精确数据可用）
```

## 6. 执行结果实证（v1.1） <span style="color:#fff;background-color:#e11d48;border-radius:4px;padding:1px 6px;font-size:0.8em">v1.1</span>

### 6.1 fetch_url 工具（决策 #1）✅ 完成

`a726d8b`：fetch_tool.py（httpx + 清洗 + 截断 + 降级）+ 注册 + 主 prompt 链路指引 + 9 单测（288 全绿）。

### 6.2 沙箱断网（决策 #2）⚠️ 环境障碍，改期

**实证**：SDK `network_policy` 参数可用（opensandbox 0.1.15），但 egress sidecar 在 **Windows Docker Desktop 不可用**——`create egress sidecar` 45s + `start egress sidecar` **260s** + 健康检查超时（两次一致），沙箱创建失败 `Network connectivity error: timed out`。

**结论**：egress 依赖 iptables/nftables（Linux 内核能力），本地 Windows 环境不支持；**云端 Linux 部署时验证**（同一套 sandbox.toml + SDK 参数，云端应可用）。本地替代：prompt 已写入"沙箱无法联网，联网走工具"（指引层约束）+ fetch_url 提供受控路径。

### 6.3 task-001 全链路验证 ✅（决定性实证）

| 指标 | 修复前（4 连败） | fetch_url + 指引后 |
|------|-----------------|--------------------|
| 完成率 | 0.0（recursion 50 撞限 ×4） | **1.0**（run 887e9068）|
| 沙箱调用 | 66 次（自写爬虫）| **1 次** |
| internet_search | 1 次 | 4 次 |
| 引用合规率 | — | 100% |

**结论**：fetch_url（受控抓取路径）+ prompt 链路指引组合已解核心问题——模型不再需要沙箱爬虫拿数据，走受控工具链路。**断网是环境加固（云端做），fetch_url 是核心解（已完成）**。
