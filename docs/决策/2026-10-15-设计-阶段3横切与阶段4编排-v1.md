| 阶段 | 原提纲（职责边界 §5） | 本设计取的范围 |
|---|---|---|
| **3 横切** | 脱敏 / 审计补结果 / trace_id | **只做「出站脱敏」**——审计补结果已由 2.3.1 提前做掉；`trace_id` **建议移出**（见 §1.1） |
| **4 编排侧** | 重试降级 / 幂等门控 / 审批接线 | 三项都做，但按 §4 的**收敛版**（原提纲太宽，见 §4 首段） |

### 1.1 🔴 `trace_id` 的归属争议（**请先拍这一条**）

```
trace_id 要真正有用，必须有一份「统一事件模型」做落点
    ↓
而那套（审计/可观测决策记录 D1–D4 + 待定 B1–B4）已定在【独立主题】里
    ↓
若阶段 3 先做 trace_id → 等审计分支再改一遍 = 返工
```

**建议**：`trace_id` 从阶段 3 移出，并入「审计与可观测」主题——那里本来就要做
「贯穿 ID + 统一事件模型 + 双写」，一次做完。**阶段 3 因此只剩脱敏一项。**

> 若 co-creator 坚持留在阶段 3，则本设计需追加 §3.5（trace_id 契约与贯穿），
> 并接受后续与审计分支的合并改动。

## 3. 阶段 3：出站脱敏 🔴 v1

### 3.1 定位

| 项 | 值 |
|---|---|
| **是什么** | 发往**远程 LLM 之前**，把文本里的敏感信息替换掉 |
| **落点** | 🔴 **两个接入点，一个纯函数**（实施时修正，见下） |
| **不做什么** | ❌ 不改入站内容 ❌ 不改历史消息（只处理**即将出站**的那一份）❌ 不脱工具内部处理（那是工具的事，如 audit 的 `code→code_len`）❌ 不脱绝对路径 |

#### 🔴 实施修正：原假设「adapter 是唯一 LLM 出口」**不成立**（2026-10-15 自检发现）

```python
# 原设计与规则 07 §4 都假定：出站脱敏挂 llm/adapter.py 即可覆盖全部出站
# 实测：LLMAdapter.chat() 只被两处使用
#   ├─ agent/tasks/assistant.py   生成会话标题
#   └─ agent/memory/store.py      记忆抽取
# 主 Agent 对话：[X] 走 get_chat_model() → langchain agent loop
#                      【不经过 LLMAdapter】
# → 只挂 adapter = 主对话完全没脱，而它是用户内容流向远程 LLM 的主通道
```

**修正后的落点**：

| 路径 | 接入点 | 覆盖 |
|---|---|---|
| **主对话**（主通道） | `llm/redact.py::RedactMiddleware.awrap_model_call` | 每一轮模型调用（`request.override(messages=...)`） |
| **辅助调用** | `LLMAdapter.chat()` 调 `redact()` | 标题生成 / 记忆抽取 |

**逻辑只写一份**（`redact()`），两处都调它——禁各写一套。

> ⚠️ **规则 07 §4 需同步修订**（现写「出站脱敏 → llm/adapter.py」，前提已被推翻）：
> 建议改为「出站脱敏 → `llm/redact.py`（纯函数；接入点＝模型调用边界中间件 + adapter）」。
> 按 `00-security` 的规则变更流程，**待 co-creator 确认后才改**——本轮不动规则文件。

### 3.2 脱敏对象与规则（拟定，需 co-creator 增删）

| 类别 | 模式（示例） | 替换为 | 备注 |
|---|---|---|---|
| 密钥 / Token | `sk-...`、`Bearer xxx`、`AKIA...` | `[已脱敏:KEY]` | **最高优先** |
| 手机号 | 1[3-9]xxxxxxxxx | `[已脱敏:PHONE]` | |
| 邮箱 | 标准邮箱格式 | `[已脱敏:EMAIL]` | |
| 身份证 | 18 位 | `[已脱敏:ID]` | |
| 内网地址 | `10.x` / `192.168.x` / `172.16-31.x` | `[已脱敏:IP]` | 需 co-creator 定是否要 |
| 文件绝对路径 | `D:\...` / `/home/...` | — | ⚠️ **倾向不脱**：路径是任务上下文，脱了模型看不懂 |

### 3.3 实现要点

1. **开关可配**：`settings.redact_enabled`（默认开）——出问题能一键关，不用改代码
2. **规则表集中**：一张 `(正则, 标签)` 表放一处（同 `validators.py` 的集中思路），**禁散落**
3. **幂等 + 顺序**：先长模式后短模式（避免长串被短模式切碎）；重复脱敏结果稳定
4. **性能**：预编译正则（`re.compile` 只做一次），逐条消息处理；**不做全文扫描 N 遍**
5. **可测**：纯函数 `redact(text) -> str` —— 输入输出可断言，不依赖 LLM

### 3.4 边界

- 脱敏**必然损失信息**（模型看到的与用户输入不同）——故必须**记日志**（脱了几处、哪类），
  但不记原文（否则日志本身成了泄漏源）
- 与审计的关系：审计记的是"谁在何时调了什么工具"（`audit`），
  脱敏管的是"发给模型的内容"（`llm/adapter`）——**两条链，不合并**

## 4. 阶段 4：编排侧 🔴 v1

> **先收敛范围**：原提纲「重试降级 / 幂等门控 / 审批接线」字面上可以无限扩张
> （重试策略、退避曲线、降级矩阵、并发门控……）。本设计只做**能消费阶段 2 元数据、
> 且当前确有真问题**的三件，其余进 §6 不做清单。

### 4.1 审批接线（**最大件，且有硬问题**）

**目标**：把 `hitl.py` 的硬编码收敛到 `TOOL_REGISTRY`，让 `requires_approval` /
`risk_level` 第一次真正被消费（顺带闭环 P2）。

**⚠️ 硬问题：现有元数据不足以表达现有配置**

| 工具 | 现配置（hitl.py） | `risk_level` 声明 | 能由 risk_level 推出吗 |
|---|---|---|---|
| `run_code_in_sandbox` | approve + **edit** + reject | high | ❌ |
| `run_command_in_sandbox` | approve + reject | high | ✅ |
| `run_skill_script` | approve + reject | high | ✅ |
| `upload_workspace_file` | approve + reject | medium | ✅ |
| `download_sandbox_file` | approve + reject | medium | ✅ |
| `ask_human` | **respond**（澄清域） | — | ❌ 语义完全不同 |
| `publish_report` | approve + **edit** + reject | — | ❌ |
| `internet_search` | `False`（不审批） | low | ✅ |

**两个 high 工具决策集不同、澄清域要 respond** → **光靠 `risk_level` 推不出来**。
两条路二选一（见 §8 决策点）：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | 注册表补一个字段 `allowed_decisions: tuple[str, ...] \| None`，hitl 侧**纯派生**；`ask_human` 等特例用 `domain == HITL_DOMAIN` 区分 | 元数据 +1 字段（但它是**真被消费**的，不算死数据） |
| B | 保留 hitl 侧的例外表，只把「有无审批」从 `requires_approval` 派生 | 仍是两处真相源（决策集部分） |

### 4.2 重试降级

**现状**：重试已在工具层（`retry_tool` 包在幂等读操作上，实测有效——P4 已闭环）。
本阶段**不重做重试**，只做**编排层消费**：

| 做 | 内容 |
|---|---|
| ✅ | 编排层读 `artifact.retryable`，决定「要不要把失败结果再交回模型换策略」——**只读信号，不改重试实现** |
| ✅ | `fallback_to` 从死数据变为**可读声明**：编排层/审计能知道"这个工具挂了该换谁"（P11 的"交权"仍归后续） |
| ❌ | 不实现跨工具自动降级（那要动 LLM 决策链，属大改） |

### 4.3 幂等门控

**现状**：`is_idempotent` 事实上已被用（`retry_tool` 只包幂等工具）——但那是**手写在
注册表条目里的**，不是"由 `is_idempotent` 驱动"。本阶段：让包装由元数据驱动，
并加**不变量测试**（`is_idempotent=True` ⟺ 包了重试，此测试**已存在**，见
`test_retry.py::test_retry_wrapping_matches_idempotent_metadata`）。

> 即：4.3 主要是**把已有事实固化为元数据驱动 + 补测试**，不新增机制。

## 6. 不做清单 🔴 v1

| 不做 | 原因 |
|---|---|
| `trace_id` 贯穿（阶段 3 原提纲） | 与审计/可观测主题重叠，单独做要返工（§1.1） |

| 重试退避策略调优（曲线/上限可配） | 当前无真实痛点，等有数据再说 |
| 并发门控 / 限流 | 原提纲外的扩张 |

## 7. 风险 🔴 v1

| # | 风险 | 处置 |
|---|---|---|
| R1 | **脱敏误伤**：正常文本被当敏感信息（如文档里写"手机号格式 1xx…"） | 规则表逐条给**反例用例**；开关可关 |
| R2 | **审批接线改行为**：派生结果与原硬编码不一致 → 审批弹窗变化 | 用**等价锁测试**（派生态 == 原表，逐工具逐决策比对），不一致就红 |
| R3 | 元数据与实现脱节复发 | 4.3 的不变量测试 + R2 的等价锁，双重防 |
| R4 | 脱敏影响模型效果 | 记日志（脱了几处/哪类，不记原文）；必要时关开关对比 |

## 9. 实施批次 🔴 v1

```
批次 1｜脱敏（阶段 3）：llm/redact.py + adapter 接线 + 规则表测试
        ← 纯新增，零行为变更风险（默认开，可关）
批次 2｜审批接线（阶段 4.1）：registry 补字段 + hitl 派生 + 等价锁测试
        ← 行为敏感，须先过 R2 等价锁
批次 3｜元数据消费（阶段 4.2/4.3）：编排层读 retryable/fallback_to + 幂等门控固化 + 不变量测试
        ← 具体落点本批次开工前再定（需先看编排层现状，避免设计悬空）
批次 4｜收口：文案/文档/笔记/索引同步 + 全量回归 + 文案 diff 表
```

每批次一个提交，可独立回滚。
