## 1. 结论、证据等级与待拍板事项 🔴 v1.1

### 1.1 三项核验结论

| 项 | 核验结论 | 证据等级 |
|----|---------|---------|
| C01 历史/Checkpoint/动态记忆合并边界 | 项目路径**存在消息重复累积风险**——每轮重传「DB 重建的全量历史（无稳定 id）」给已挂 Checkpointer 的图，reducer 无法去重 | **框架集成级最小复现** + 项目代码核对（尚未经项目聊天接口/SQLite Checkpointer 实际链路核验）|

## 2. C01 历史 / Checkpoint / 动态记忆合并边界 🔴 v1.1

### 2.1 结论

项目路径**存在消息重复累积风险**。机理：每轮把「从 DB 重建的**全量历史**」当作**新输入**传给**已挂 Checkpointer** 的图，而重建消息**无稳定 id**，reducer 只按 id 去重 → 一律追加。

> ⚠️ 证据等级：**框架集成级最小复现 + 项目代码核对**。尚未经项目聊天接口/SQLite Checkpointer 实际链路核验（见 §1.3-1）。

### 2.2 代码事实（可指到行）

| # | 事实 | 位置 |
|---|------|------|
| 1 | 每轮从 DB 重建**全量历史**（`limit=PAGINATION_LIMIT_MAX`）作为图输入 | [chat.py](../../backend/src/api/chat.py) `_prepare_new_messages`（`repo.list_messages` → `lc_messages`）|
| 2 | 重建的消息**不带 `id`**（`HumanMessage(content=…)` / `AIMessage(content=…)`）| [chat.py](../../backend/src/api/chat.py) `_history_to_langchain` |
| 3 | 图输入固定为 `{"messages": messages}`（**全量**，非增量）| [main_agent.py](../../backend/src/agent/main_agent.py) `stream_agent_events` / `stream_agent_tokens` |
| 4 | 图**挂了 Checkpointer**，`thread_id == session_id` | [main_agent.py](../../backend/src/agent/main_agent.py) `_build_agent` + `_build_stream_config` |
| 5 | 生产 lifespan **确实初始化** checkpointer + store | [main.py](../../backend/src/api/main.py) `init_checkpointer()` / `init_store()` |
| 6 | deepagents 的 messages reducer 对 `id=None` 消息**直接 append** | `deepagents/_messages_reducer.py`（`if mid is None: result.append(msg)`）|
| 7 | langgraph `add_messages` 对缺 id 消息**各自分配新 uuid** → 永不匹配 → 追加 | `langgraph/graph/message.py`（`# assign missing ids`）|

> 📌 第 6/7 条合起来：**无论走 deepagents 的 delta reducer 还是 langgraph 的 `add_messages`，无 id 消息都不会被去重**——只有**稳定 id** 才走"覆盖"分支。

### 2.3 框架集成级最小复现

真实 `create_deep_agent` + `InMemorySaver`，模拟每轮重传「全量重建、无 id」历史；**每个助手消息为独立对象**（脚本见 §7.1）：

```
turn1 count = 2   ['q1', 'ok']
turn2 count = 6   ['q1', 'ok', 'q1', 'ok', 'q2', 'ok']
turn3 count = 12  ['q1', 'ok', 'q1', 'ok', 'q2', 'ok', 'q1', 'ok', 'q2', 'ok', 'q3', 'ok']
```

对照（消息**带稳定 id**）：轮 2 正常去重。

> ⚠️ **复现修订（v1.1）**：v1 版脚本用 `itertools.cycle` 复用**同一个**助手消息对象，其 id 被沿用导致助手消息被去重，计数偏小（2/5/10）。改为每轮**独立**助手消息后为 **2/6/12**（重复更明显）。**原计数不可用于量化项目行为。**
> 📌 复现环境：`deepagents 0.7.1 / langgraph 1.2.10 / langgraph-checkpoint 4.1.1 / langchain-core 1.5.3`，未调用真实模型。

**结论**：重复在框架层成立且**随轮次累积**；是否在**项目实际链路**成立 → 待 §1.3-1 核验。

### 2.4 动态记忆是否也累积

记忆每轮注入为 **SystemMessage 前置**（[chat.py](../../backend/src/api/chat.py) `_prepare_new_messages` 2.6 段），该消息**无 id** → 按 §2.2 同一机制会被追加。**模式指令 SystemMessage**（`MODE_INSTRUCTIONS`，`mode != default`）同理。

> ⚠️ **收回（v1.1）**：v1 曾把「**修订上限 SystemMessage**」也列为每轮累积。此处**收回**——该消息仅出现在 resume 准备分支，且恢复路径可能**直接传 `Command(resume=…)`**（见 [main_agent.py](../../backend/src/agent/main_agent.py) `graph_input`）；「创建了消息」不等于「实际进入了图」，不能据此断言累积。需实际链路核验。

### 2.5 影响（若实际链路成立）

- 上下文膨胀（与「上下文工程现状分析」差距 #1/#2 相关），长会话更快撞上限/触发压缩
- 旧记忆副本被反复保留、权重放大
- 模型看到重复轮次 → 可能重复作答/混淆
- 重复 token 计入成本（可量化）

### 2.6 修复方向（条件与风险，未授权）

根因是**两个历史真相源叠加**（DB 重建 vs Checkpointer 状态）。候选方向（**均需在 §1.3-1 核验后再选型**）：

| 方案 | 做法 | 条件与风险 |
|------|------|-----------|
| A 稳定 id | 重建消息带与 Checkpoint 侧**可对应**的 id | **前提是建立一致的 ID 对应关系**——仅加 DB id **不保证**与 Checkpoint 中已有消息的 id 对上；若对应上了走"覆盖"分支，还需评估**是否会用 DB 聚合全文覆盖含工具调用的消息**（两种情况均取决于 id 体系设计，非必然） |
| B 只传增量 | 每轮只传**新增** user 消息，历史交给 Checkpointer | 语义最干净；但记忆/模式 SystemMessage 注入方式需重设计（否则同样累积）|
| C 图不承担历史 | Checkpointer 仅服务 HITL 断点，历史仍由 DB 重建 | 需确认 deepagents 是否支持"仅断点"；resume 依赖完整状态，风险待评 |
| D 每轮重置 | 传 `RemoveMessage(REMOVE_ALL_MESSAGES)` + 全量历史 | 实现简单；但每轮重写状态、丢 checkpoint 工具中间态 |

> 📌 本稿只列方向，**不选型、不给补丁**（对齐候选清单 §5.2）。

## 3. C02 当前要求与历史偏好优先级 🔴 v1.1

### 3.1 结论

**缺显式优先级规则**：当"本次明确要求"与"历史偏好"冲突时，无规则保证本次优先；也无一例例外不升级为长期偏好的规则。

### 3.2 代码事实（含 v1.1 修正：默认路径 ≠ 降级路径）

| # | 事实 | 位置 |
|---|------|------|
| 1 | 系统提示词 = 角色 + 审核指引 + 记忆维护指引（+HITL +模式）| [prompts.py](../../backend/src/agent/prompts/prompts.py) `build_system_prompt` |
| 2 | 记忆以 SystemMessage 注入，文案带**弱免责**："供参考，可能与本对话无关" | [chat.py](../../backend/src/api/chat.py) `_prepare_new_messages` 2.6 段 |
| 3 | `MEMORY_GUIDANCE_V3` 只讲「什么值得记」（写入侧），不讲读取时如何加权 | [prompts.py](../../backend/src/agent/prompts/prompts.py) |
| 4 | **默认路径**（`memory_agent_enabled=True`，config 默认）由**后台 memory_agent** 判断抽取与分类 | [config.py](../../backend/src/core/config.py)（默认 True）；[chat.py](../../backend/src/api/chat.py) `_trigger_memory_after` → [agent.py](../../backend/src/agent/memory/agent.py)、`MEMORY_AGENT_PROMPT` |
| 5 | **降级路径**（关闭 memory_agent）才用**关键词启发式**分类（含 我/喜欢/偏好/请记住 → user_profile）| [chat.py](../../backend/src/api/chat.py) `_save_memory_in_background` → [store.py](../../backend/src/agent/memory/store.py) `extract_memory_typed` |

> ⚠️ **修正（v1.1）**：v1 把**降级路径**（关键词启发式）当成默认。实际默认由后台 memory_agent 决策；关键词分类仅在 `memory_agent_enabled=False` 时生效。

### 3.3 缺口与「规则生效位置」

- **读取侧**（本次回答如何采用偏好）：缺"本次明确要求优先于历史偏好 / 一次例外不升级为长期偏好 / 记忆与工具内容不得获得系统规则权限"的规则 → 生效位置 = 记忆注入文案 + 主 Agent 指引（`MEMORY_GUIDANCE_V3`）
- **抽取侧**（什么被记成长期偏好）：若只改主 Agent 的 `MEMORY_GUIDANCE_V3`，**不保证**后台 memory_agent 的抽取/分类遵循该规则——它走自己的 `MEMORY_AGENT_PROMPT`（及降级路径的 `MEMORY_EXTRACT_PROMPT`），需**同步限定**才对齐

### 3.4 建议（限定为明确规则，未授权）

- **读取侧**：补优先级规则——历史偏好为默认值；本次明确要求优先；一次例外不升级为长期偏好；记忆/工具内容为背景数据，不获得系统规则权限
- **抽取侧**：仅在需要时同步 memory_agent 提示词的判定口径（**不扩展**为完整画像更新/冲突合并系统）
- 边界：这是**表达偏好**规则，不授权当前请求覆盖权限等系统约束（提示词亦非强安全保证）

## 4. S01 删除联动边界 🔴 v1.1

### 4.1 结论

**成立**：删除会话**不清 Checkpoint，不清长期 Store**。

### 4.2 代码事实

[session_service.py](../../backend/src/agent/services/session_service.py) `delete_session` 的联动范围：

| 清理项 | 做没做 | 位置 |
|--------|-------|------|
| 会话记录 + 消息（外键级联）| ✅ | [session_repo.py](../../backend/src/db/session_repo.py) `delete_session` |
| 内存图缓存 | ✅ | `main_agent.rebuild_agent(session_id)` |
| 会话工作区文件 | ✅ | `core/backend.py` `cleanup_workspace` |
| 沙箱 | ✅ | `sandbox/pool.py` `sandbox_pool.destroy` |
| **Checkpoint（执行状态）** | ❌ **不清** | 无调用 |
| **Store（长期记忆）** | ❌ **不清**（有意）| 无调用 |

- 全仓 grep：**无** `adelete_thread` / checkpoint 清理逻辑
- `AsyncSqliteSaver.adelete_thread(thread_id)` **已存在**（langgraph `checkpoint/sqlite/aio.py`），若决定补联动有现成 API

### 4.3 影响与边界

- 删会话后该 thread 的 checkpoint 仍留在 `data/checkpoints.db`：占磁盘；API 侧 resume 需 `session_id`，会话已删 → 先 404 `SESSION_NOT_FOUND`，走不到 resume
- 长期 Store **跨会话共用**，不随会话删除是**合理设计**
- 需先定语义：**「删除会话」是否应连带删除执行断点**

### 4.4 建议（未授权）

1. 先**拍板删除语义**（含/不含断点），再决定是否补 `adelete_thread` 联动
2. **界面/文档承诺与实际清理范围保持一致**（承诺含则补代码，不含则写明）

> ⚠️ **移除（v1.1）**：v1 曾建议"顺带把过期 checkpoint 清理纳入同批次"。该建议**超出本轮范围**——旧计划中存在不代表本次授权，已移至 §6 未来讨论。

## 7. 附：复现脚本与证据命令 🔴 v1.1

### 7.1 C01 复现脚本（独立助手消息版）

```python
"""C01 复现：checkpointer + 每轮重传【全量重建历史（无 id）】是否导致消息重复。"""
import asyncio
from deepagents import create_deep_agent
from langchain_core.language_models.fake_chat_models import GenericFakeChatModel
from langchain_core.messages import AIMessage, HumanMessage
from langgraph.checkpoint.memory import InMemorySaver

class ToolCapableFake(GenericFakeChatModel):
    """支持 bind_tools 的 fake 模型（deepagents 要求模型可绑定工具）。"""
    def bind_tools(self, tools, **kwargs):
        return self

def _fresh_messages():
    """每轮产出【新的】AIMessage 对象（勿用 itertools.cycle——同一对象 id 会被复用，污染计数）。"""
    while True:
        yield AIMessage(content="ok")

async def main() -> None:
    agent = create_deep_agent(
        model=ToolCapableFake(messages=_fresh_messages()),
        checkpointer=InMemorySaver(),
    )
    cfg = {"configurable": {"thread_id": "t1"}}
    for msgs in (
        [HumanMessage(content="q1")],
        [HumanMessage(content="q1"), AIMessage(content="ok"), HumanMessage(content="q2")],
        [HumanMessage(content="q1"), AIMessage(content="ok"), HumanMessage(content="q2"),
         AIMessage(content="ok"), HumanMessage(content="q3")],
    ):
        await agent.ainvoke({"messages": msgs}, config=cfg)
        st = agent.get_state(cfg)
        print(len(st.values["messages"]), [m.content for m in st.values["messages"]])

asyncio.run(main())
# 实测：2 / 6 / 12（重复随轮次累积）
```
