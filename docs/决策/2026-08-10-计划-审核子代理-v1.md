## 1. 背景与目标 🔴 v1

**Why（双动机）**：
1. **面试**（备战指南 §9.2 P0-2）：补"真多 Agent 协作"故事——面经追问点"审核意见为何不回到规划节点"“是否保留历史版本选最优"正是审核子代理的天然追问链；也是指南 §3.2"HITL/容错"模块的加分项
2. **质量闭环**：P0-1 评估首跑显示 judge 质量分偏低（B1 均值 1.8/5）——**无审核的研报质量不可控**；审核子代理把"质量检查"从离线评估（事后测）提升为运行时流程（产出即检）

**目标**：主 agent 产出研报后**委派 review_agent 审核**，不通过则按问题清单修订重审（≤2 轮），最终交付带审核结论的终稿。

**边界（不做）**：不做人工审批（那是 HITL 域，P0-2 是 AI 自审）；不做多轮评审辩论（2 轮封顶，防成本失控）。

## 2. 设计 🔴 v1

### 2.1 架构：deepagents 子代理机制（零编排改动）

```
主 Agent（deepagents 编译图）
 ├─ search_agent（搜索委派，已有）
 ├─ review_agent（审核委派，本次新增）← 目录自动加载，无需改 main_agent 编排
 └─ 回路：产出研报 → 委派 review_agent → 通过？→ 交付
                          ↑ 不通过（问题清单）→ 主 agent 修订 → 重审（≤2 轮）
```

- **机制复用**：`subagents/loader.py` 自动加载目录全部 YAML——新增 review_agent.yaml 即挂载，`main_agent` 编排零改动
- **回路实现**：主 agent system prompt 注入 `REVIEW_GUIDANCE` 段（引导"审核不通过 → 修订 → 重审"），循环在主 agent 的 graph recursion 内自然发生，**recursion_limit=50 兜底**（P0-1 已调）
- **与评估联动**：多 Agent 配置自动包含 review_agent——P0-1 报告（b424e230，完成率 90%）为基线，P0-2 后重跑同任务集即纵向对比

### 2.2 review_agent 声明

| 项 | 值 | 理由 |
|----|-----|------|
| 工具 | **无**（纯 LLM 判断） | 审核不需要工具，减少工具选择噪声 |
| 权限 | 全拒绝（write deny） | 与 search_agent 同模板；审核只读产出 |
| 模型 | deepseek-v4-flash（P1-1 model 字段） | 便宜模型够用；评审严苛度由 prompt 控制 |
| 审核输出 | 结构化：**通过 / 不通过 + 问题清单**（每条具体到"章节/论断/原因"） | 防"泛泛而谈"审核——rubric 约束具体性 |

### 2.3 审核标准（复用 rubrics.py 模板语义）

- **来源可靠性**（source_veracity）：论断有可核验来源 / 区分事实与推测 / 无编造
- **章节完整度**（report_completeness）：覆盖任务要求章节 / 关键数据有引用 / 结论可追溯

> 与评估体系 judge 同源（同一 rubric 模板）——运行时审核 = 离线评估的"在线版"，面试可讲"评估与审核共享同一套质量标准"。

### 2.4 风险与兜底

| 风险 | 兜底 |
|------|------|
| 审核回路不收敛（反复打回） | ≤2 轮封顶（prompt 硬约束）+ recursion_limit 50 |
| 审核误判（好报告被打回） | 修订仍不通过 → 带审核结论交付（不阻塞） |
| token 成本↑（每次审核 1 次 LLM 调用） | 单次审核 = 1 次调用，2 轮封顶 = 至多 3 次；用量告警已有 |

## 3. 面试要点（文档规范 §4.6 三要求） 🔴 v1

### 3.1 面试点标注（对照备战指南 §3.2 五大模块）

| 面试点 | 覆盖 | 技术故事 |
|--------|------|----------|
| **评估体系**（P0） | 联动（审核 = 评估在线版，同 rubric） | "运行时审核与离线评估共享同一套质量标准" |
| **HITL 机制**（P0） | 部分（AI 自审 vs 人工审批的对比决策） | "先 AI 自审（快、便宜），高风险再人工审批（HITL 域）" |
| **容错处理**（P1） | 修订回路 ≤2 轮 + 不通过仍交付 | 防死循环设计 |
| **成本控制**（P1） | 2 轮封顶 + 用量告警 | 成本意识 |

### 3.2 追问链预演（§3.3 五层自答）

| 追问 | 预演答案 |
|------|----------|
| **为什么做审核子代理？** | 首轮评估显示无审核的研报质量不可控（judge 分低）；审核把"质量检查"从离线评估提为运行时流程——产出即检 |
| **为什么拆成子代理而不是主 agent 自己审？** | 单 Agent 自我审核 = 角色冲突（自己写自己审形同虚设，知识/提示词同源）；子代理独立上下文 + 独立评审标准（多 Agent 拆分四前提之"角色天然分离"） |
| **审核意见为什么不回到规划节点重做？** | 这是设计取舍：回到规划 = 全链路重跑（成本×N）；局部修订 = 带问题清单重写产出。2 轮后仍不通过 → 带缺陷交付（诚实记录），面试主动讲这个取舍 |
| **怎么防止死循环？** | ≤2 轮硬约束 + recursion_limit 50 + 不通过仍交付（不阻塞） |
| **审核质量怎么保证？** | 结构化问题清单（具体到章节/论断）+ rubric 约束 + 与离线评估同标准（可交叉验证） |
| **怎么量化效果？** | 评估管道纵向对比：P0-1（无审核）vs P0-2（有审核）同任务集——完成率/质量分/成本变化（§5 实施） |

### 3.3 可量化结果（落地后预期产出）

- 评估纵向对比报告：P0-1 vs P0-2（完成率 / B1/B2 质量分 / token 成本 Δ）
- 审核行为数据：打回率、修订轮次分布、终稿审核通过率

## 4. 完整核心代码（YAML + prompt 代码形态） 🔴 v1

### 4.1 `backend/src/agent/subagents/review_agent.yaml`

```yaml
# 审核子代理声明（P0-2，2026-08-10）：研报质量审核 + 修订回路
# 无工具纯判断；审核标准与评估体系 rubrics.py 模板同源
name: review_agent
description: >-
  研报质量审核专员：按来源可靠性/章节完整度标准审核研报，
  输出"通过"或"不通过 + 问题清单"（每条具体到章节/论断/原因）。
system_prompt: |-
  你是一名研报质量审核专员。审核用户提交的研究报告，输出严格结构化意见：

  审核标准：
  - 来源可靠性：每条关键论断都有可核验来源（编号引用对应文末列表）；
    区分事实与推测（推测必须标注）；无编造的数据/引用/统计数字
  - 章节完整度：覆盖任务要求的全部章节；关键数据有来源引用；
    结论可追溯（从数据到结论路径清晰）

  输出格式（严格）：
  结论: 通过 | 不通过
  问题清单:
  - 章节: <章节名>
    问题: <具体问题描述>
    建议: <修改建议>
  （通过时问题清单输出"无"）

  只输出上述格式，不要其他解释。
tools: []
# 便宜模型够用（P1-1 model 字段）；审核严苛度由 prompt 控制
model: deepseek-v4-flash
# 审核只读产出，无文件需求（与 search_agent 同权限模板）
permissions:
  - operations: [write]
    paths: ["/**"]
    mode: deny
```

### 4.2 `backend/src/agent/prompts/prompts.py` 新增段（REVIEW_GUIDANCE）

```python
# 主 Agent 审核回路指引（P0-2，2026-08-10）：产出研报后委派 review_agent
# 审核；不通过按问题清单修订重审（≤2 轮）；仍不通过带审核结论交付。
REVIEW_GUIDANCE = """

## 研报质量审核（P0-2）

完成研报撰写后，必须委派 `review_agent` 审核（把完整报告作为任务内容）：

1. 委派审核 → 收到"通过" → 直接交付
2. 收到"不通过 + 问题清单" → **逐条修订报告** → 再次委派审核（第 2 轮）
3. 第 2 轮仍"不通过" → 停止修订，交付终稿并附审核结论
   （说明遗留问题，诚实呈现——不要无休止修订）
"""


def build_system_prompt(*, mode: str = "default") -> str:
    from src.agent.prompts import (
        DEFAULT_SYSTEM_PROMPT,
        MEMORY_GUIDANCE_V3,
        MODE_INSTRUCTIONS,
        REVIEW_GUIDANCE,
    )

    parts = [DEFAULT_SYSTEM_PROMPT, REVIEW_GUIDANCE, MEMORY_GUIDANCE_V3]
    instruction = MODE_INSTRUCTIONS.get(mode)
    if instruction:
        parts.append(instruction)
    return "\n".join(parts)
```

### 5.2 评审点

1. 审核回路"局部修订（≤2 轮）"而非"回到规划节点重做"——取舍认可？

3. 审核标准与评估体系同源（rubrics 模板）——认可？
4. P0-2c 小样本验证（2-3 任务）先行，全量 P0-2d 留给用户按需——认可？
