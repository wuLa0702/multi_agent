## 1. 总：背景、目标与范围

### 1.1 背景

记忆抽取现状：对话结束后 `asyncio.create_task` 后台**单次 LLM 调用**抽取
（`extract_memory_typed`，无工具、无多步）。

讨论结论：记忆抽取正踩在**子 agent 甜点**上（三个需求全中）：

| 需求 | 子 agent 价值 |
|------|--------------|
| **抽取→去重→分类→关联（多步推理）** | ✅ 天然支持多步编排 |
| **查历史记忆去重、读文件辅助（工具）** | ✅ 可绑定专属工具集 |
| **写 Store + 写 Wiki + 发通知（多系统联动）** | ✅ 多工具按序/并行调用 |

若用直接 LLM 调用，需自写多步流程控制/工具调用/错误重试/状态管理——这些
本就是子 agent 框架做的事。**做（学习 demo 价值高）**：一个 demo 学到
子 agent 隔离 / 工具编排 / 多系统联动 / 异步 / 幂等 五个实践。

### 1.2 目标

1. **memory_agent**：记忆管理员子代理——后台抽取/去重/分类/关联/存储
2. **后台任务队列**（用户明确）：监控 + 记录日志 + 限制并发（替代裸 create_task）
3. 幂等性：重复对话/重试不重复写记忆
4. 失败降级：memory_agent 挂了不影响主对话

### 1.3 范围

| 在本方案内 | 不在本方案内 |
|-----------|-------------|
| memory_agent 子代理 + 专属工具集（search/read/write_store/write_wiki/notify） | 通知的真实通道（send_notification 先日志占位，P2 接真实） |
| 后台任务队列（监控/日志/并发限制） | Wiki 写入的真实实现（write_wiki 先设计，Wiki 系统接入后启用） |
| 幂等（内容哈希去重） | 记忆质量评估/评分（P3） |
| 降级与开关 | 关联推理的深度（P3） |

## 2. 分·决策依据

### 2.1 单次 LLM vs 子 agent（本场景）

| 维度 | 单次 LLM 调用（现状） | memory_agent 子代理（目标） |
|------|---------------------|---------------------------|
| 多步流程 | ❌ 需自写（抽取→去重→分类→关联） | ✅ 框架编排 |
| 工具调用 | ❌ 无工具（只能查一次 prompt） | ✅ search_memory/read_file 等 |
| 多系统联动 | ❌ 单次返回 | ✅ write_store + write_wiki + notify |
| 状态管理/重试 | ❌ 自写 | ✅ 子代理图内管理 |
| 成本 | 主模型单次调用 | 子代理模型（可小模型，同上下文分析 §4 思路） |

**判定标准**：单次调用 → 直接 LLM；**多步 + 工具 + 多系统 → 子 agent**——本场景全中。

### 2.2 与现有异步链路的关系

```
现状（v3 已落地）：对话结束 → create_task(_save_memory_in_background) → 单次 LLM 抽取
本方案升级：   对话结束 → MemoryTaskQueue.enqueue(对话)  → 队列 worker（并发限制）
                    → worker ainvoke memory_agent（多步+工具+多系统）→ 结果/日志
```

- 异步语义**保持**（后台不阻塞主对话）——升级的是"后台做什么"（单次调用 → 子代理）
- `extract_memory_typed`（单次抽取）保留为**降级路径**（子代理不可用时回退，§3.7）

## 3. 分·设计

### 3.1 memory_agent 定位

**记忆管理员**：专门负责记忆的抽取、整理、存储——纯后台任务，不返回用户。

- 形态：**CompiledSubAgent 预编译**（独立 StateBackend + 独立工具集 + 权限最小化——
  沿用 CompositeBackend 深化 P2 隔离实践）
- 输入：对话历史（user 消息 + assistant 回复）+ 上下文（session_id）
- 输出：抽取结果（成功/失败 + 写了哪些记忆）——仅供日志/监控，不回用户

### 3.2 专属工具集（权限最小化）

```
memory_agent 工具（只挂这 5 个，天然最小化——不给文件工具/沙箱工具）：
├── search_memory(kw)        # 查历史记忆（去重用，只读）
├── read_memory_file(path)   # 读记忆文件（辅助抽取，只读 /memories/）
├── write_store(type, fact)  # 写 Store（结构化记忆，只写 memory namespace）
├── write_wiki(page, content) # 写 Wiki（文档记忆，指定命名空间，P2 接入）
└── send_notification(msg)   # 发通知（可选，P2 接真实通道，先日志占位）
```

- **只读记忆、不能改用户数据**：文件工具/沙箱工具不挂
- **只写记忆相关**：write_store 限定 memory namespace；write_wiki 限定 Wiki 命名空间
- **约束诚实表述（v1.1 修正）**：工具集最小化 = **挂载层面单一约束**（只挂 5 个
  工具，不暴露的天然不可调）——"双重约束"表述不准确（allowed_tools 声明与
  挂载是同一层）；如需第二重，后续加 PolicyBackend 上层拦截（P2 可选）

### 3.3 工作流

```
收到对话 → ① 分析有什么值得记（触发条件清单，记忆方案 §4.1）
  → ② 查历史记忆（search_memory——去重，内容哈希比对）
  → ③ 分类（用户画像/事实/决策/任务——记忆方案 §3.1 四类）
  → ④ 关联（和已有记忆的关系——P3 深化，先跳过）
  → ⑤ 写 Store（write_store——幂等检查后写入）
  → ⑥ 写 Wiki（重要决策/知识——P2）
  → ⑦ 发通知（可选——P2）
  → 返回结果（写入了哪些记忆，供队列记录）
```

### 3.4 后台任务队列（用户明确要求：监控 + 日志 + 并发限制）

**`MemoryTaskQueue`**（替代裸 `asyncio.create_task`）：

```python
MemoryTaskQueue（进程内单例）
  ├─ enqueue(dialog)          # 入队（对话历史 + session_id）
  ├─ worker（常驻消费）       # 取任务 → ainvoke memory_agent → 记录结果
  ├─ 并发限制                 # Semaphore（如 max_concurrent=2）——后台任务不堆积
  ├─ 监控                     # pending/running/failed 计数（可查）
  └─ 日志                     # 每任务 audit 行（入队/开始/完成/失败 + 耗时）
```

| 需求 | 实现 |
|------|------|
| **监控** | 队列计数（pending/running/failed）+ 最近 N 条任务状态可查 |
| **记录日志** | `layer=memory_agent` audit 行（enqueue/start/completed/failed + session_id + 耗时 + 写入结果） |
| **限制并发（v1.1 修正）** | **多 worker 协程**（`asyncio.create_task(run_worker())` × N，如 2 个）——单 worker 循环 + Semaphore 无效（串行执行本来就不会并发）；Semaphore 仅作兜底 |
| **失败重试** | 失败记日志 + 入 failed 计数（下次对话再试；不自动重试防重复写） |

> 🔧 v1.1 并发实现决策（评审问题 2）：选 **A 多 worker**（更简单直观）——
> lifespan 里 `asyncio.create_task(run_worker())` 调 2 次即 2 并发；
> 放弃"单 worker + create_task 异步处理"方案（需任务级管理，复杂）。

### 3.5 幂等性（重要）

- 同一对话可能被抽取多次（重试/网络问题）——必须保证**重复记忆不重复写**
- 实现：`write_store` 内部**内容哈希去重**——按 fact 内容 hash 在 namespace 检索，
  已存在则跳过（返回"已存在，跳过"）
- 队列层面：任务入队带对话指纹（session_id + 消息 hash），相同指纹未处理完
  不重复入队（防并发重复）
- **指纹集合防泄漏（v1.1 修正）**：`_seen` 只增不减会内存泄漏——改 **LRU
  （上限 1000 条指纹）**，超出逐出最旧（学习 demo 场景 1000 条对话指纹足够）

### 3.6 失败降级

- memory_agent 失败 → 记日志 + failed 计数——**绝不抛给用户**（后台任务）
- 降级路径：子代理不可用（构建失败/模型错误）→ 回退单次 LLM 抽取
  （`extract_memory_typed` 保留）——记忆链路不断
- 开关：`MEMORY_AGENT_ENABLED`（True=子代理；False=回退现状单次抽取）

### 3.7 模型策略（v1.1 决策，评审问题 3）

**memory_agent 用独立小模型，不随主模型切换**——理由：

| 维度 | 独立小模型（决策） | 随主模型切换 |
|------|-------------------|-------------|
| 成本 | ✅ 抽取不消耗主模型配额/钱（与压缩器小模型同思路） | 主模型贵，抽取频繁成本高 |
| 稳定 | ✅ 抽取质量不随用户换模型漂移 | 换 provider 后抽取行为变化 |
| 实现 | `memory_agent_model` 配置（空=主模型兜底），编译时绑定 | 需按 provider 重建子代理（复杂） |

- 多 provider 时：用**默认 provider 的小模型**（`memory_agent_model` 配置指定）
- **默认无配置走主模型**（用户拍板 2026-08-05）：`memory_agent_model` 为空 →
  主模型兜底（`get_chat_model()`）——未配置时不引入额外模型依赖
- CompiledSubAgent 编译时绑定模型（不随 `_configurable_model` 切换）——
  **这正是我们要的**（独立性），非缺陷

### 3.8 与 v3 记忆体系的衔接

- 类型化 namespace（user_profile/facts）复用 ✓
- 分类职责从"启发式关键词"升级为"子代理推理分类"（更准）
- 归档（tasks_archive）与 memory_agent 并行（归档仍是会话结束检查，不冲突）

### 7.1 后台任务队列（`src/agent/memory/queue.py`，新建）

```python
"""记忆后台任务队列（方案 §3.4）：监控 + 日志 + 并发限制。

替代裸 asyncio.create_task——后台抽取任务可观测、不堆积、失败可追踪。
"""

from __future__ import annotations

import asyncio
import json
import logging
from dataclasses import dataclass, field
from datetime import datetime

logger = logging.getLogger(__name__)
audit_logger = logging.getLogger("audit")

# 并发 worker 数（v1.1 修正：多 worker 协程实现并发——单 worker + Semaphore
# 无效（串行）；lifespan 里 create_task(run_worker()) 调 N 次即 N 并发）
_WORKER_COUNT = 2
# 队列上限（防无限堆积；超出拒绝并记日志）
_MAX_QUEUE = 100
# 指纹 LRU 上限（v1.1：_seen 只增不减会内存泄漏——超限逐出最旧）
_SEEN_MAX = 1000


@dataclass
class MemoryTask:
    """记忆抽取任务：对话历史 + 会话定位 + 指纹（幂等去重）。"""

    session_id: str
    user_message: str
    assistant_text: str
    fingerprint: str   # session_id + 消息 hash（防重复入队）


class MemoryTaskQueue:
    """进程内单例后台队列（lifespan 启动/关闭）。

    ⚠️ v1.1 并发实现（评审问题 2）：**多 worker 协程**——
    lifespan 里 `asyncio.create_task(run_worker())` 调 _WORKER_COUNT 次，
    每个 worker 独立消费，自然并发 _WORKER_COUNT；
    单 worker 循环 + Semaphore 是伪并发（串行执行）。

    Attributes:
        _queue: 待处理任务
        _seen: 指纹 LRU（幂等去重，上限 _SEEN_MAX 防泄漏）
        stats: 监控计数（pending/running/completed/failed）
    """

    def __init__(self) -> None:
        self._queue: asyncio.Queue[MemoryTask] = asyncio.Queue(maxsize=_MAX_QUEUE)
        self._seen: dict[str, None] = {}   # OrderedDict 语义：插入序 = 使用序
        self.stats = {"pending": 0, "running": 0, "completed": 0, "failed": 0}

    def enqueue(self, task: MemoryTask) -> bool:
        """入队（幂等：相同指纹不重复入队；队列满拒绝）。

        Returns:
            True = 入队成功；False = 重复/队列满
        """
        if task.fingerprint in self._seen:
            logger.debug("记忆任务去重：fingerprint=%s", task.fingerprint)
            return False
        try:
            self._queue.put_nowait(task)
        except asyncio.QueueFull:
            logger.warning("记忆队列满（%d），任务拒绝：session=%s", _MAX_QUEUE, task.session_id)
            return False
        self._seen[task.fingerprint] = None
        while len(self._seen) > _SEEN_MAX:        # LRU 逐出最旧（防内存泄漏）
            self._seen.pop(next(iter(self._seen)))
        self.stats["pending"] += 1
        self._audit("enqueue", task, "")
        return True

    async def run_worker(self, consumer) -> None:
        """常驻 worker：取任务 → 消费（consumer 执行 memory_agent）→ 记录。

        多 worker 并发（v1.1）：lifespan 启动 _WORKER_COUNT 个本协程——
        每个独立 while 循环消费，天然并发。

        Args:
            consumer: 异步消费函数（ainvoke memory_agent + 写入），
                由调用方注入（解耦队列与子代理）
        """
        while True:
            task = await self._queue.get()
            self.stats["pending"] -= 1
            self.stats["running"] += 1
            self._audit("start", task, "")
            try:
                result = await consumer(task)
                self.stats["completed"] += 1
                self._audit("completed", task, str(result)[:200])
            except Exception:  # noqa: BLE001 —— 后台任务失败不冒泡
                logger.exception("记忆任务失败：session=%s", task.session_id)
                self.stats["failed"] += 1
                self._audit("failed", task, "")
            finally:
                self.stats["running"] -= 1
            self._queue.task_done()

    def _audit(self, event: str, task: MemoryTask, detail: str) -> None:
        """任务审计行（layer=memory_agent，与 policy_backend 同构扁平 JSON）。"""
        record = {
            "ts": datetime.now().astimezone().isoformat(timespec="seconds"),
            "layer": "memory_agent",
            "event": event,
            "session_id": task.session_id,
            "fingerprint": task.fingerprint,
            "detail": detail,
        }
        audit_logger.info(json.dumps(record, ensure_ascii=False))


# 进程内单例（lifespan 启动 worker，关闭时 stop）
memory_task_queue = MemoryTaskQueue()
```

### 7.6 lifespan 完整接线（v1.1 补齐，评审问题 2/4）

```python
"""（main.py lifespan 增量：队列 worker 启动/关闭完整示例）"""

_workers: list[asyncio.Task] = []


async def _memory_consumer(task: MemoryTask) -> str:
    """队列消费：ainvoke memory_agent（工具内部 get_store() 运行时解析）。

    Args:
        task: 记忆抽取任务（对话历史 + session_id）

    Returns:
        抽取结果摘要（供队列 audit 记录）
    """
    agent = build_memory_agent(get_chat_model())   # 懒构建（模型按 memory_agent_model 配置）
    result = await agent.ainvoke(
        {"messages": [{"role": "user", "content": task.user_message},
                      {"role": "assistant", "content": task.assistant_text}]}
    )
    return str(result)[:200]


async def start_memory_queue() -> None:
    """启动队列（lifespan 启动调用）：create_task × _WORKER_COUNT（多 worker 并发）。

    ⚠️ 不能 await run_worker（常驻循环会阻塞启动）——create_task 后台运行。
    """
    for _ in range(_WORKER_COUNT):
        _workers.append(asyncio.create_task(memory_task_queue.run_worker(_memory_consumer)))


async def stop_memory_queue() -> None:
    """关闭队列（lifespan 关闭调用）：等当前任务跑完再取消（优雅停止）。

    策略（v1.1 明确）：先 queue.join()（等已取出任务完成）→ 再取消 worker；
    队列中未取出的任务丢弃（记忆旁路，下轮对话补）。
    """
    await memory_task_queue._queue.join()          # 等当前处理中的任务完成
    for worker in _workers:
        worker.cancel()                            # 取消常驻循环
    _workers.clear()
```
