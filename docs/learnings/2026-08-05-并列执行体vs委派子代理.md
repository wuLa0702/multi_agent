## 1. 背景

开发 memory_agent（记忆抽取子代理）时，co-creator 疑问：**为什么放在
`agent/memory/` 而不是专门的 `agent/subagents/` 路径**？

追问澄清出两个概念的本质区别——"平级/主子"表述不准，准确术语是
**并列执行体（peer executor）vs 委派子代理（delegated subagent）**。

## 2. 核心概念

### 2.1 委派（Delegation）——父子关系

- **主 agent 用 `task` 工具调用**下属干活，结果回主 agent 继续
- 生命周期随主对话流；随主图编译（subagents= 参数）
- 语义：**主 agent 指挥下属**（主从）

### 2.2 编排（Orchestration）——流水线衔接

- **系统/队列编排**独立执行体运行，不经过主 agent 的委派工具
- 生命周期独立（如队列 worker 常驻）；独立编译
- 语义：**系统安排平级执行体接力**（流水线，无主从）

### 2.3 并列执行体（peer executor）定义

> 与主对话 agent **并列的执行体**——不是"主子委派"关系，而是系统编排下的
> 流水线衔接：**职责分离、时序衔接、领域独立**。

## 3. 三维度判别

| 维度 | 委派子代理（subagent） | 并列执行体（peer executor） |
|------|----------------------|---------------------------|
| **关系** | 主 agent 调用（task 工具委派），结果回主 | 系统/队列编排（orchestration），独立驱动 |
| **时序** | 对话流内（委派 → 执行 → 回结果 → 继续） | 流水线衔接（上一环节结束 → 接手），有先后无从属 |
| **领域** | 交互域内角色（主 agent 的"分工臂"） | 独立领域（如记忆域/执行域），按域存放 |

## 4. 项目落地体现

| 项 | 委派子代理 | 并列执行体 |
|----|-----------|-----------|
| 目录 | `agent/subagents/`（search_agent——YAML 声明 + loader，进主图） | `agent/memory/`（memory_agent——代码编译 + 队列驱动） |
| 驱动 | `main_agent._build_agent → load_subagents()`（主图 subagents=） | `main.py._memory_consumer → build_memory_agent()`（队列 worker ainvoke） |
| 生命周期 | 随主对话流 | lifespan 常驻队列 |
| 返回 | 结果回主 agent | 不返回用户（仅供日志/监控） |

## 5. 判别速查表

```
拿到一个 agent，问三个问题：
1. 谁调动它？  主 agent 的 task 工具 → 委派子代理；系统/队列 → 并列执行体
2. 结果给谁？  回主 agent 继续 → 委派；给日志/存储/用户侧 → 并列
3. 放哪？      主图 subagents= 挂载 → agent/subagents/；独立驱动 → 按领域目录
```

**一句话记忆**：委派 = 主 agent 调用下属干活（父子）；编排 = 系统安排平级
执行体接力（流水线）。**memory_agent 属于后者——被编排的并列执行体。**
