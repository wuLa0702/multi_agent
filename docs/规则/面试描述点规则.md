## R0 架构总纲（系统广度入口）🔴 v2

**描述点分两类，缺一不可**：

| 类型 | 数量 | 职责 | 示例 |
|------|------|------|------|
| **总纲**（架构广度）| **1 篇** | 讲**系统整体设计**：分层架构 + 核心决策 + 演进路径，把 N 个功能描述点串成一条主线 | `2026-08-12-面试描述点-架构总纲-v1.md` |
| **功能节点**（逐个深度）| N 篇 | 讲**单个模块**：问题 → 方案 → 权衡（R1-R5）| 22 个 `面试描述点-X` |

**总纲写作要求**（2026-08-12 定稿，源自架构总纲实践）：
- **广度叙事**：分层（api→agent→能力层→底座 + 依赖单向）→ 核心决策表（每个决策回链对应功能描述点）→ 演进路径（为什么从单体拆多 Agent）
- **mermaid 两张**：静态分层架构图（全貌）+ 动态演进图（前后两阶段）
- **主流程不重画**：一次请求的数据流细节引用 `项目追问链.md` §7，总纲只做总装配
- **定位**：面试官问系统设计 → 总纲给全景；问单个功能 → 功能描述点给深度，再回链总纲定位它在哪层

## R1 总分总三明治（黄金结构）

- **总（≤30s）**：一句话结论 = 做了什么 + 解决什么 + 一个数据
- **分（60~90s）**：2-3 层展开（问题 → 方案 → 权衡），每层埋一个"可追问点"
- **总（≤20s）**：价值升华 + 关联系统（"这块和 X 联动"）

## R2 流程图规则（系统/横切类表达）

- 主流程固定分层：用户 → api → 主图 → 工具 → 审核 → 交付（与 `项目追问链.md` §7 一致）
- 新增改动标色块：🟦原有 ｜ 🟥新增 ｜ 🟨横切
- 横切点写清两件事：**挂在哪个环节 + 影响什么**
- 结尾一句全景（"主流程没动，加了三层护栏"）
- **总纲图例外**：总纲用 mermaid 静态分层图 + 动态演进图（R0），不套用主流程分层

## R3 数据弹药规则

- 每模块 ≥1 个可量化结果 + commit 来源（`git show <hash>` 可回溯）
- 三类数据：效果（完成率/质量分）｜ 工程（测试数/bug 数）｜ 成本（单价/费用）
- 主动讲代价的数据（延迟、成本放大）——证明踩过坑
