## 3. 命名规则（动态 vs 过程） 🔴 v1

| 文档性质 | 命名 | 例 |
|----------|------|-----|
| **动态维护**（顶层 / 参考 / 规则 / 索引 / 日志）| **`主题.md`**（无日期、无 -vN）| `架构目录.md`、`索引.md`、`文档规范.md` |
| **过程性**（评审稿 / 方案 / 学习 / 决策记录）| `YYYY-MM-DD-类型-主题-vN.md` | `2026-08-11-设计-成本控制-v1.md` |
| **踩坑** | `YYYY-MM-DD-主题.md`（沿用）| `2026-08-04-PyCharm索引未解析引用.md` |

> 动态文档的版本靠文档头 📝 版本记录（只追加不删除）；文件名不带版本，避免"动态文件却叫 v1"误导。

## 4. 双向链接规则 ★ 🔴 v1

> co-creator 2026-08-12 拍板："很多文件要做好双向链接。"

**三层要求**：

| 层 | 规则 | 检查 |
|----|------|------|
| **关联成对** | A 引用 B ⇒ B 反向引用 A（关联段必须成对出现）| 新增/改关联时，同步补对方文档的反向链接 |
| **索引 ↔ 文档** | 索引表里每个文档一行；**每个文档头部必须有"回索引"链接**（关联段含 `docs/索引.md`）| 新增文档即加索引行 + 回链 |
| **权威 ↔ 镜像** | `.claude/rules/` ↔ `规则/` 双位置文档互相标注"权威在 X / 镜像" | 改权威必须同步镜像（或注明冲突以权威为准）|

**落地**：每个文档头部规范头下方固定放 `> **关联**（双向）：…` 段——既有链接列全，反向链接一并列出。

## 5. 转正 / 归档流程 🔴 v1

| 场景 | 动作 |
|------|------|
| **决策/ → 方案/**（评审通过）| `git mv 决策/设计-X-v1.md 方案/方案-X-v1.md` + 版本记录追加 + 索引状态 ⏳→✅ + 引用扫描 |
| **执行完使命 / 被覆盖** | `git mv` 入 `归档/`（保历史，不删）+ 索引状态 📦 |
| **改造过程文档**（如治理方案）| 规则部分抽入 `规则/`，执行记录归档 `归档/` |
| **顶层动态文档** | 永不归档（活着），只更新内容 + 版本记录 |

## 6. 索引维护 🔴 v1

- `索引.md` 是 docs 唯一入口：新增 / 改名 / 归档文档时**同步更新一行**
- 索引本身是动态文档：**无前缀尾缀**（§3）
- 索引 ↔ 文档双向链接（§4）
- 索引每节（架构/规则/方案/决策/学习/踩坑/归档/参考/临时）列对应目录全部文件

## 7. 权威 vs 镜像（双位置） 🔴 v1

| 位置 | 角色 | 说明 |
|------|------|------|
| `.claude/rules/`（9 个）| **机器加载权威** | Claude Code 自动加载，规则生效处 |
| `规则/`（docs 侧）| 人类可读镜像 + 统一入口 | 与 .claude/rules/ 对应文档互为镜像 |

**冲突处理**：以 `.claude/rules/` 为准（同 06-structure-optimization 的双位置模式）；改规则必须两处同步或注明差异。
